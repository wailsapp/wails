# Wails Enhancement Proposal (WEP)

## Native macOS Split View, Source-List Sidebar, Inspector, and Pane-Aware Toolbar

**WEP Number**: (assigned on acceptance)
**Status**: Draft
**Author**: Lea Anthony
**Created**: 2026-08-05
**Target**: Wails v3

## Summary

Add a macOS-only `NSSplitViewController` layout to an existing
`WebviewWindow`, together with a native AppKit source-list sidebar, native
property inspector, and the standard toolbar controls that operate on them.

The window keeps exactly one `WKWebView`: its existing primary content view.
The sidebar is an `NSOutlineView` hosted by
`NSSplitViewItem.sidebarWithViewController`. It is not an HTML page and is not
implemented by making a second WebView transparent. The inspector uses
`NSSplitViewItem.inspectorWithViewController` with native AppKit property
controls; it is not a DOM overlay.

The proposal also adds:

- the standard AppKit sidebar toggle;
- the standard sidebar tracking separator; and
- the standard inspector toggle and inspector tracking separator; and
- configurable `NSToolbar.displayMode` presentation.
- configurable below-toolbar or edge-to-edge primary content layout.

All native and callback identifiers are generated internally. Applications
retain typed Go handles, following the existing menu and toolbar API style.

## Motivation

An HTML column can imitate the dimensions of a macOS sidebar, but it cannot
provide the real source-list behavior. It misses AppKit's material, focus and
selection semantics, keyboard navigation, accessibility roles, collapse and
overlay behavior, divider persistence, and titlebar integration.

Wrapping that HTML column in a native split item is still not a native
sidebar. The WebView paints and manages the visible sidebar surface, which is
especially obvious on macOS 26 where Finder uses a translucent floating
sidebar panel.

Wails should expose the native building blocks directly while preserving the
existing WebView and window APIs.

## Design principles

1. **One WebView per window in this layout.** The original window WebView is
   reparented into the primary pane. The sidebar and inspector contain AppKit
   controls.
2. **Semantic AppKit construction.** Sidebars use
   `sidebarWithViewController`; source-list content uses `NSOutlineView`.
3. **No public IDs.** Section, row, pane, and callback IDs are generated by
   Wails and are never part of application code.
4. **Typed live handles.** Applications retain `MacSidebarItem` and
   `MacSplitPane` pointers for later updates.
5. **Native defaults first.** AppKit controls sizing, material, selection,
   collapse, and accessibility unless the application explicitly overrides a
   supported property.
6. **Atomic installation and deterministic teardown.** A failed native build
   leaves the original window hierarchy intact. Dead handles become no-ops.
7. **Portable declarations.** The API compiles on every Wails platform;
   AppKit operations are inert outside desktop macOS.

## Non-goals

This proposal does not create auxiliary sidebar, content-list, or inspector
WebViews. A native content-list pane and arbitrary custom AppKit view hosting
remain separate follow-ups.

It also does not attempt to expose every `NSOutlineView` feature in the first
version. Hierarchical nesting beyond sections, drag and drop, inline rename,
custom row views, and sidebar context menus can be additive follow-ups.

## Proposed Go API

### Split layout

```go
type MacSplitView struct { /* unexported */ }

func NewMacSplitView() *MacSplitView
func (s *MacSplitView) SetAutosaveName(name string) *MacSplitView

// AddSidebar adds a native AppKit source list and returns its split-pane
// sizing/collapse handle.
func (s *MacSplitView) AddSidebar(sidebar *MacSidebar) *MacSplitPane

// AddPrimaryContent places the window's existing and only WKWebView here.
func (s *MacSplitView) AddPrimaryContent() *MacSplitWebviewPane

// AddInspector adds a native trailing AppKit property inspector.
func (s *MacSplitView) AddInspector(inspector *MacInspector) *MacSplitPane

func (w *WebviewWindow) SetSplitView(split *MacSplitView) Window
```

Exactly one primary pane and at least two total panes are required. Pane order
is declaration order. Structural changes are rejected after attachment.

### Pane state

```go
func (p *MacSplitPane) SetMinimumThickness(points float64) *MacSplitPane
func (p *MacSplitPane) SetMaximumThickness(points float64) *MacSplitPane
func (p *MacSplitPane) SetPreferredThicknessFraction(fraction float64) *MacSplitPane
func (p *MacSplitPane) SetHoldingPriority(priority float64) *MacSplitPane
func (p *MacSplitPane) SetCollapsible(value bool) *MacSplitPane
func (p *MacSplitPane) SetCanCollapseFromWindowResize(value bool) *MacSplitPane
func (p *MacSplitPane) SetCollapsed(value bool) *MacSplitPane
func (p *MacSplitPane) Toggle() *MacSplitPane
func (p *MacSplitPane) IsCollapsed() bool
func (p *MacSplitPane) OnCollapsedChange(func(*Context, bool)) *MacSplitPane
```

Zero minimum or maximum thickness restores AppKit's role-specific unspecified
dimension. Nonfinite, negative, or internally inconsistent dimensions are
ignored. Preferred fraction must be within `(0, 1]`; holding priority must be
within `1...1000`.

`OnCollapsedChange` observes toolbar, menu, divider, window-resize, and
programmatic collapse sources. Duplicate KVO values are suppressed.

### Primary content layout

```go
type MacContentLayout int

const (
    MacContentLayoutAutomatic MacContentLayout = iota
    MacContentLayoutBelowToolbar
    MacContentLayoutEdgeToEdge
)

// Window default.
type MacWindow struct {
    ContentLayout MacContentLayout
}

// Primary split-pane override.
func (p *MacSplitWebviewPane) SetContentLayout(MacContentLayout) *MacSplitWebviewPane
func (p *MacSplitWebviewPane) ContentLayout() MacContentLayout
```

`Automatic` on a primary pane inherits the window. `Automatic` at window
level follows `MacTitleBar.FullSizeContent`: full-size content is edge-to-edge
and ordinary content remains below the toolbar. An explicit pane value wins
over the window value.

Below-toolbar layout pins the WebView's top edge to
`NSWindow.contentLayoutGuide`. Edge-to-edge layout pins it to the primary
pane's full top edge and enables `NSWindowStyleMaskFullSizeContentView`. On
macOS 26 and newer, a standard `NSToolbar` adopts Liquid Glass automatically.

With a full-size content view and a nontransparent titlebar, `WKWebView`
participates in macOS 26's genuine adaptive scroll-edge fade and blur beneath
toolbar controls. Wails does not inspect private WebKit classes or insert an
HTML fade or custom visual-effect overlay. AppKit does not expose soft/hard
style selection for an ordinary `NSToolbar`; those selectors are limited to
real titlebar and split-item accessory controllers on macOS 26.1+.

The public native-interoperability surface wraps either supported controller
without taking ownership:

```go
type MacScrollEdgeEffectStyle int

const (
    MacScrollEdgeEffectStyleAutomatic MacScrollEdgeEffectStyle = iota
    MacScrollEdgeEffectStyleSoft
    MacScrollEdgeEffectStyleHard
)

func WrapMacAccessoryViewController(unsafe.Pointer) (*MacAccessoryViewController, error)
func (c *MacAccessoryViewController) SupportsPreferredScrollEdgeEffectStyle() bool
func (c *MacAccessoryViewController) SetPreferredScrollEdgeEffectStyle(MacScrollEdgeEffectStyle) error
func (c *MacAccessoryViewController) PreferredScrollEdgeEffectStyle() (MacScrollEdgeEffectStyle, error)
func (c *MacAccessoryViewController) NativeController() unsafe.Pointer
```

The wrapper accepts only `NSTitlebarAccessoryViewController` and
`NSSplitViewItemAccessoryViewController`. Explicit styles report
`ErrMacScrollEdgeEffectStyleUnavailable` before macOS 26.1; Automatic remains
a successful system-default fallback. This is deliberately separate from the
standard-toolbar API.

### Native sidebar

```go
type MacSidebar struct { /* unexported */ }
type MacSidebarSection struct { /* unexported */ }
type MacSidebarItem struct { /* unexported */ }

func NewMacSidebar() *MacSidebar
func (s *MacSidebar) AddSection(label string) *MacSidebarSection
func (s *MacSidebar) AddItem(label string) *MacSidebarItem
func (s *MacSidebarSection) AddItem(label string) *MacSidebarItem

func (i *MacSidebarItem) SetLabel(label string) *MacSidebarItem
func (i *MacSidebarItem) SetSymbol(sfSymbol string) *MacSidebarItem
func (i *MacSidebarItem) SetTooltip(tooltip string) *MacSidebarItem
func (i *MacSidebarItem) SetEnabled(enabled bool) *MacSidebarItem
func (i *MacSidebarItem) SetHidden(hidden bool) *MacSidebarItem
func (i *MacSidebarItem) OnClick(func(*Context)) *MacSidebarItem

func (s *MacSidebar) SetSelectedItem(item *MacSidebarItem) *MacSidebar
```

Sections are nonselectable native group rows and expand by default. Root items
may appear before or between sections. `SetSelectedItem(nil)` clears native
selection. Programmatic selection does not invoke `OnClick`; user selection
does.

SF Symbols are used where available. Missing or empty symbols leave the row
without an image. Native cells retain AppKit text colors, disabled appearance,
selection drawing, focus rings, and accessibility behavior.

Rows can be added and updated after installation. Wails rebuilds the native
source-list snapshot on the application thread while preserving selection.

### Native inspector

```go
type MacInspector struct { /* unexported */ }
type MacInspectorSection struct { /* unexported */ }
type MacInspectorControl struct { /* unexported */ }

func NewMacInspector() *MacInspector
func (i *MacInspector) AddSection(label string) *MacInspectorSection
func (s *MacInspectorSection) AddLabel(label, value string) *MacInspectorControl
func (s *MacInspectorSection) AddTextField(label, value string) *MacInspectorControl
func (s *MacInspectorSection) AddCheckbox(label string, checked bool) *MacInspectorControl
func (s *MacInspectorSection) AddPopup(label string, options []string, selected int) *MacInspectorControl

func (c *MacInspectorControl) SetLabel(string) *MacInspectorControl
func (c *MacInspectorControl) SetValue(string) *MacInspectorControl
func (c *MacInspectorControl) SetChecked(bool) *MacInspectorControl
func (c *MacInspectorControl) SetOptions([]string) *MacInspectorControl
func (c *MacInspectorControl) SetSelectedIndex(int) *MacInspectorControl
func (c *MacInspectorControl) SetTooltip(string) *MacInspectorControl
func (c *MacInspectorControl) SetEnabled(bool) *MacInspectorControl
func (c *MacInspectorControl) SetHidden(bool) *MacInspectorControl
func (c *MacInspectorControl) OnTextChange(func(*Context, string)) *MacInspectorControl
func (c *MacInspectorControl) OnToggle(func(*Context, bool)) *MacInspectorControl
func (c *MacInspectorControl) OnSelectionChange(func(*Context, int, string)) *MacInspectorControl
```

The first control set covers common property-inspector needs: read-only
values, editable strings, booleans, and fixed choices. Returned handles,
rather than caller-supplied IDs, provide identity. Programmatic setters update
native state without invoking user callbacks; user edits update the Go handle
before callbacks run.

The semantic inspector factory is used on macOS 11 and newer. macOS 10.13–10.15
retain the same controls and pane API in a regular trailing split item.
No inspector operation creates or navigates a WebView.

### Pane toolbar items

```go
func (t *MacToolbar) AddSidebarToggle()
func (t *MacToolbar) AddSidebarTrackingSeparator()
func (t *MacToolbar) AddInspectorToggle()
func (t *MacToolbar) AddInspectorTrackingSeparator()
```

These methods return no item handle because they use AppKit-owned standard
identifiers. The toggle sends `toggleSidebar:` through the responder chain.
Collapse state is observed through `MacSplitPane.OnCollapsedChange`.

The tracking separator requires a sidebar split in the same window and
`NSWindowStyleMaskFullSizeContentView`. Toolbars containing more than one
toggle or tracking separator are rejected.

The inspector methods use AppKit's standard identifiers on macOS 14 and newer.
On older supported releases Wails supplies a native inspector toggle button;
the inspector tracking separator is omitted because AppKit does not provide
that behavior there. Both standard and fallback toggles collapse the same
`MacSplitPane` and are observable through `OnCollapsedChange`.

### Toolbar display mode

```go
type MacToolbarDisplayMode int

const (
    MacToolbarDisplayModeDefault MacToolbarDisplayMode = iota
    MacToolbarDisplayModeIconAndLabel
    MacToolbarDisplayModeIconOnly
    MacToolbarDisplayModeLabelOnly
)

func (t *MacToolbar) SetDisplayMode(mode MacToolbarDisplayMode) *MacToolbar
```

The Wails default remains icon-and-label for compatibility. The setter works
before and after attachment and maps directly to `NSToolbar.displayMode`.

## Example

```go
sourceList := application.NewMacSidebar()
notes := sourceList.AddSection("Notes")

first := notes.AddItem("Saturday, slowly.").
    SetSymbol("doc.text").
    SetTooltip("A slow day is still a day well spent.")
first.OnClick(func(*application.Context) {
    app.Event.Emit("note:selected", 0)
})
sourceList.SetSelectedItem(first)

split := application.NewMacSplitView().
    SetAutosaveName("example.main-window")
sidePane := split.AddSidebar(sourceList)
sidePane.SetMinimumThickness(210).
    SetMaximumThickness(340).
    SetCollapsible(true)
split.AddPrimaryContent().
    SetContentLayout(application.MacContentLayoutEdgeToEdge)

inspector := application.NewMacInspector()
document := inspector.AddSection("Document")
title := document.AddTextField("Title", "Saturday, slowly.")
title.OnTextChange(func(_ *application.Context, value string) {
    app.Event.Emit("note:rename", value)
})
document.AddPopup("Category", []string{"Personal", "Work"}, 0)
document.AddCheckbox("Pinned", false)
statistics := inspector.AddSection("Statistics")
words := statistics.AddLabel("Words", "27")

inspectPane := split.AddInspector(inspector)
inspectPane.SetMinimumThickness(240).
    SetMaximumThickness(360).
    SetCollapsible(true)
window.SetSplitView(split)

toolbar := application.NewMacToolbar().
    SetDisplayMode(application.MacToolbarDisplayModeIconOnly)
toolbar.AddSidebarToggle()
toolbar.AddSidebarTrackingSeparator()
toolbar.AddFlexibleSpace()
toolbar.AddInspectorTrackingSeparator()
toolbar.AddInspectorToggle()
window.SetToolbar(toolbar)
```

## Native implementation mapping

| Go API | AppKit implementation |
|---|---|
| `MacSplitView` | `NSSplitViewController` |
| `AddSidebar` | `NSSplitViewItem sidebarWithViewController:` |
| `MacSidebar` | `NSScrollView` + source-list `NSOutlineView` |
| `MacSidebarSection` | `outlineView:isGroupItem:` nodes |
| `MacSidebarItem` | native `NSTableCellView` rows |
| `AddPrimaryContent` | reparent existing `WKWebView` |
| `AddInspector` | `NSSplitViewItem inspectorWithViewController:` on macOS 11+ |
| `MacInspector` | `NSScrollView` + native section stack |
| Inspector value/text/boolean/choice controls | `NSTextField`, `NSButton`, `NSPopUpButton` |
| `AddSidebarToggle` | `NSToolbarToggleSidebarItemIdentifier` |
| `AddSidebarTrackingSeparator` | `NSToolbarSidebarTrackingSeparatorItemIdentifier` |
| `AddInspectorToggle` | `NSToolbarToggleInspectorItemIdentifier` on macOS 14+; native fallback earlier |
| `AddInspectorTrackingSeparator` | `NSToolbarInspectorTrackingSeparatorItemIdentifier` on macOS 14+ |
| `SetDisplayMode` | `NSToolbar.displayMode` |

## Threading and callbacks

Native UI changes run on Wails' application thread. Model fields are protected
by Go locks and are snapshotted before crossing cgo. Native selection sends an
internally generated row or control ID back to Go; registries resolve it to
the retained `MacSidebarItem` or `MacInspectorControl` handle and invoke the
callback asynchronously.

No application callback runs while a model lock is held. Native callback
registries are populated immediately before installation and cleared before
native teardown.

Primary WebView navigation uses a generation counter. A completion from an
older navigation cannot mark a newer navigation loaded or flush its pending
JavaScript.

## Ownership and lifecycle

- A split view, sidebar, and inspector may each belong to one window layout.
- Native hierarchy installation occurs before toolbar attachment.
- Installation constructs every controller before replacing the window's
  content view controller.
- The original primary WebView and configured visual-effect backdrop are
  preserved and reparented.
- Window destruction unregisters callbacks, removes KVO, invalidates all pane,
  sidebar, and inspector handles, and releases the native owner once.
- Calls on dead handles are safe no-ops.

## Platform behavior

On non-Darwin, iOS, and server builds, declarations and descriptive state
remain available but no native split, source-list, or inspector view is
installed. The ordinary primary WebView remains unchanged.

## Acceptance criteria

1. The window contains exactly one WKWebView when a sidebar/inspector split is active.
2. The sidebar accessibility hierarchy is an AppKit outline/source list, not
   web content.
3. Sidebar material, selection, focus, keyboard navigation, divider, collapse,
   and titlebar integration visually match native macOS applications.
4. The sidebar may use AppKit's full-height material, but the primary WebView
   begins at `NSWindow.contentLayoutGuide` and never paints beneath the native
   toolbar. The primary pane paints a native window-background surface behind
   that toolbar; the desktop cannot leak through it.
   `MacBackdropNormal` restores an opaque native window root, while explicit
   transparent, translucent, and Liquid Glass modes retain their requested
   backdrop behavior.
5. The standard toggle, tracking separator, menu action, and programmatic
   collapse all operate on the same sidebar item.
6. Native row selection reaches the correct generated Go callback.
7. Live labels, symbols, tooltips, enabled state, hidden state, additions, and
   programmatic selection update without recreating the window.
8. The native inspector uses AppKit controls, supports live programmatic state,
   and dispatches generated-handle callbacks for text, checkbox, and pop-up
   changes without invoking callbacks for programmatic setters.
9. Standard and fallback inspector toggles operate on the same semantic pane.
10. Invalid configuration cannot partially replace the window hierarchy.
11. Focused tests pass under the race detector; full tests, vet, and portable
   builds pass.
12. The Daymark asset server receives only the editor page request; there is no
   sidebar or inspector HTML document.
