Wake は Wails の試験的なビルドシステムです。1 つの `wails.yaml` に、アプリケーション、フロントエンド、ターゲットプラットフォーム、パッケージ、署名設定を記述します。Wake はその設定を使用してビルドを計画および実行し、変更のない処理をキャッシュして、生成されたファイルを報告します。

このチュートリアルでは、小規模なデスクトップアプリケーションを作成し、ブラウザーで設定して、自分のコンピューター向けにビルドし、開発モードで実行します。まず、ローカルターゲットを 1 つだけ指定し、署名なしでビルドします。クロスコンパイルと配布の設定は、最初のビルドが成功してから追加してください。

すでにアプリケーションがある場合は、[既存のプロジェクトを移行する](#heading-7)に進んでください。個々のフィールドと高度なワークフローについては、[YAML ビルドガイド](/experimental/yaml-builds/)および[マニフェストリファレンス](/reference/wails-yaml-fields/)を参照してください。

## 試験機能の利用にあたって

@note{type="caution" title="テスト用プロジェクトまたは別のブランチを使用してください"}
Wake はオプトイン機能であり、その設定、コマンド、動作はプレビュービルド間で変更される可能性があります。現時点では、安定版ビルドシステムと同等の互換性は保証されません。プロジェクトの正常に動作することが確認済みのリビジョンを保持し、テストした CLI とフレームワークのバージョンを記録してください。パッケージは配布前に配布先のシステムでテストしてください。
@end

Wake と **Pure Go** バックエンドは、それぞれ独立した選択項目です。Wake を有効にしても、Pure Go は自動的には有効になりません。このレッスンでは標準バックエンドを使用するため、macOS および Linux の GUI ビルドには、通常どおり各環境のネイティブ開発ツールが必要です。

ウィザードは要件を確認し、設定を保存します。保存はビルドではなく、選択したすべてのターゲットの準備が整っていることを証明するものでもありません。不足しているツールや認証情報には、たとえば CI ホスト上で後から対処できます。無効なターゲットとパッケージの組み合わせは、保存前に修正する必要があります。

移行は**一方向**です。Wake は Taskfile の実行、Task テンプレートの展開、YAML から Taskfile への逆変換を行いません。未移行のプロジェクトでは、引き続き別個の従来版 Task ランタイムを使用します。有効な `wails.yaml` が暗黙的に従来版ランタイムへフォールバックすることはありません。

## 始める前に

Go、スターターフロントエンド用の npm を含む Node.js、お使いのコンピューター向けの[プラットフォーム依存関係](/getting-started/installation/#platform-specific-dependencies)が必要です。新しいプロジェクトフォルダーを作成するディレクトリから開始してください。ウィザードを使用するためのブラウザーも必要です。

このプレビューを含む CLI とフレームワークのリビジョンを使用してください。安定版の `v3.0.0` CLI をインストールしても、ここで説明する Wake のプロジェクト作成画面は追加されません。次のコマンドでは、[PR #6531](https://github.com/wailsapp/wails/pull/6531) のプレビューを固定して使用します。

```sh
go install github.com/wailsapp/wails/v3/cmd/wails3@b1daf95f3
wails3 version
```

Go の実行ファイルがあるディレクトリを `PATH` に追加してください。手順については、[インストールガイド](/getting-started/installation/)を参照してください。このチュートリアルの後半では、アプリケーションの Go 依存関係を同じリビジョンに固定します。より新しいプレビューをテストする場合は、両方のリビジョン引数を同時に更新してください。

### ターミナルで Wake を有効にする

Bash または Zsh の場合：

```bash
export WAILS_EXP_USE_WAKE=1
```

PowerShell の場合：

```powershell
$env:WAILS_EXP_USE_WAKE = '1'
```

チュートリアルの残りの手順では、このターミナルを開いたままにしてください。Wake コマンドを実行する新しいターミナルや CI ジョブでは、その都度この変数を設定してください。この変数が**存在すること**で Wake が有効になります。`false` または空文字列を設定しても無効にはなりません。以前の `WAILS_USE_WAKE` という名前は無視されます。

## アプリケーションを作成する

プロジェクト作成ウィザードを実行します。

```sh
wails3 init -ui
```

ブラウザーでプロジェクトウィザードが開きます。Wake が有効な場合、ソースとビルドに関する選択を 1 つのフローで収集します。最後の **プロジェクトを作成**ボタンを押すまで、何も作成されません。`wails3 setup` はグローバル設定、ツール、署名用認証情報を設定する別のウィザードであり、このプロジェクトの Wake プロファイルは設定しません。

| 画面 | このチュートリアルでの選択 | 次に行われること |
| --- | --- | --- |
| **プロジェクト — Wails プロジェクトを作成** | `wake-demo` と入力し、**続行**を選択します。 | 表示されているディレクトリの下に新しい `wake-demo` フォルダーが作成され、その中にプロジェクトが作成されます。 |
| **フレームワーク — フレームワークを選択** | **Vanilla** を選択し、**続行**を選択します。 | フレームワーク固有の学習手順を必要としない、小規模なフロントエンドが作成されます。 |
| **言語 — 言語設定** | **JavaScript** を選択し、**続行**を選択します。 | TypeScript 専用の **バインディング**画面はスキップされます。 |
| **詳細 — プロジェクトの詳細** | 製品名に `Wake Demo`、バンドル識別子に `com.example.wakedemo`、バージョンに `0.1.0` を指定します。**続行**をクリックします。 | ビルド設定を選択している間、メタデータはウィザードに保持されます。 |

このレッスンでは **グローバルの既定値を使用**を選択しないでください。選択すると、フレームワークと言語の選択がスキップされます。別のプロジェクトで TypeScript を選択した場合は、**バインディング**画面で、生成する Go データバインディングにインターフェースとクラスのどちらを使用するか選択できます。

## 作成前にビルド設定を選択する

同じブラウザーウィンドウで続行してください。以下のスクリーンショットは、Linux でこの手順を実行した場合のものです。ホストのターゲットと必要なツールは、Windows または macOS では異なります。

### アプリケーション — 何をビルドしますか？

**デスクトップアプリケーション**のままにして、**標準バックエンド**を選択します。**続行**をクリックします。

![プロジェクト作成ウィザードのアプリケーション画面。「デスクトップアプリケーション」と「標準バックエンド」が選択されています。](/assets/screenshots/wake/application.png)

このレッスンでは、Web フロントエンドを備えた GUI を作成します。<strong>Pure Go（試験的）</strong>は独立したオプトイン機能です。依存関係も CGo なしでビルドできる場合、サポートされているデスクトップ向けのコンパイルで C コンパイラーが不要になります。ただし、ターゲットのランタイムライブラリや、すべてのパッケージ化および署名ツールが不要になるわけではありません。

バックエンドは**プロジェクト全体に適用される設定**です。これらの設定を継承する他のプロファイルでも、選択したバックエンドが使用されます。

### ターゲット — どこで実行しますか？

現在使用しているコンピューター向けのターゲットだけを残し、**続行**をクリックします。ウィザードでは最初に、ホストのオペレーティングシステムとアーキテクチャが選択されています。

![チュートリアル用ホストの linux/amd64 だけが選択されたターゲット画面。](/assets/screenshots/wake/targets.png)

ターゲット名は、オペレーティングシステムと CPU アーキテクチャを組み合わせたものです。たとえば、`windows/amd64`、Apple Silicon Mac 向けの `darwin/arm64`、または `linux/amd64` があります。`darwin` は macOS を意味します。別のターゲットを選択すると、そのマシン向けの実行ファイルが要求されます。その実行ファイルが現在のコンピューターで実行可能になるわけではありません。

追加のアーキテクチャ、macOS ユニバーサルビルド、試験的なモバイルターゲットは後で設定してください。最初のローカルビルド後に `wails.yaml` へ追加できます。

### パッケージ — リリース出力を選択する

パッケージ形式のチェックボックスはすべて未選択のままにし、**リリース出力に署名**をオフにします。**続行**をクリックします。

![追加の Linux パッケージ形式が選択されておらず、署名がオフになっているパッケージ画面。](/assets/screenshots/wake/packages.png)

追加の形式を選択しない場合、Wake はターゲットのデフォルト出力（デスクトップ実行可能ファイル、または macOS GUI の場合は macOS アプリケーションバンドル）を生成します。ローカルでアプリケーションを確認するには、これで十分です。形式を選択すると、サポートされている場合は DMG、MSIX、NSIS、DEB、AppImage などの配布用出力が追加されます。

この最初のローカルビルドでは、署名は任意です。未署名のビルドが成功しても、アプリケーションを一般公開できる状態になったとは限りません。署名付きプロジェクトの場合は、作成前に `wails3 setup` で再利用可能な認証情報を設定するか、作成後に `wails.yaml` で署名を設定します。作成ウィザードは設定済みの認証情報を使用しますが、グローバルな署名設定は変更しません。

Wake は、秘密鍵やパスワードを `wails.yaml` にコピーせずに、プロジェクト外にある設定済みの証明書ファイルを使用できます。プロジェクトで明示した署名設定が優先されます。一般公開用リリースを準備する前に、[署名設定ガイド](/getting-started/setup/)と[パッケージ化および署名ガイド](/experimental/yaml-builds/#package-and-sign-for-distribution)に従ってください。モバイル署名は YAML で設定します。

### ツール — ビルドに使用するツール

選択内容に応じた要件を確認してください。この一覧は Wake のビルドプランに基づいており、すべてのプラットフォームにすべてのツールをインストールするよう求めるものではありません。

![ローカルの Linux ソースビルドについて解決された要件を示す「ツール」画面。](/assets/screenshots/wake/tools.png)

このレッスンでは、Go とフロントエンド用ツールに加えて、ホストの標準 GUI バックエンドに必要なネイティブ開発ツールが必要です。Docker が一律に必要なわけではありません。CGo を使用するクロスビルドでは、コンパイラとターゲットライブラリ、またはサポートされているコンテナツールチェーンが必要になる場合があります。

ローカルビルドを試す前に、**準備未完了**、**設定が必要**、または **更新が必要** と表示された行を解決してください。表示されている手順があればそれを使用し、なければ[プラットフォーム別インストールガイド](/getting-started/installation/)を参照してから、**要件を再確認**をクリックします。インストールによってターミナルの `PATH` が変更された場合は、更新後のターミナルから `wails3 init -ui` を再起動し、選択をやり直してください。

このコンピューターにツールや署名用認証情報がなくても、ウィザードは有効なプロジェクトを作成できます。これは CI の設定には便利ですが、このチュートリアルでは、このコンピューター上で実行できるビルドが必要です。無効な設定は作成前に修正する必要があります。

### プロジェクトを作成する

選択内容が、デスクトップアプリケーション、標準バックエンド、ホスト環境のターゲット、署名無効になっていることを確認します。**ツール**で**プロジェクトを作成**をクリックし、**プロジェクトの選択内容を受け付けました**と表示されるまで待ちます。ターミナルに戻り、CLI によるプロジェクトの作成が完了するまで待ちます。ブラウザーでの確認は、選択内容を受け付けるだけです。

![作成成功後に使用する予定のアプリケーションパスとコマンドが表示された「プロジェクトの選択内容を受け付けました」画面。](/assets/screenshots/wake/save.png)

ウィザードはソースを作成し、ターゲット、パッケージ、署名の選択内容を `wails.yaml` 内の `profiles.setup` に保存します。また、アプリケーションの種類、フロントエンドの有効化、プロジェクト全体のバックエンドも設定します。ブラウザーを閉じてターミナルに戻ることができます。プロジェクトの作成が完了するまで待ってから、次を実行します。

```sh
cd wake-demo
go get github.com/wailsapp/wails/v3@b1daf95f3
```

これで、`main.go`、Go モジュール、`frontend` ディレクトリ、ネイティブの `wails.yaml` が作成されているはずです。組み込みテンプレートは Wake を直接使用するため、この新しいプロジェクトを移行する必要はありません。コミュニティテンプレートには独自のレガシータスクが含まれている場合があり、その場合は後述する移行レビューが必要になることがあります。

完了画面には `wails3 build setup` と `wails3 dev` が表示されます。プロファイル名は重要です。`wails3 build setup` は、直前に保存した選択内容を使用します。単に `wails3 build` を実行しても、`setup` プロファイルは自動的に選択されません。プロファイル名は、`wails3 setup` を実行する必要があるという意味ではありません。

## 最初のアプリケーションをビルドして実行する

ウィザードに表示されたコマンドを実行します。

```sh
wails3 build setup
```

最初のビルドでは、フロントエンドの依存関係をインストールし、バインディングを生成して、アプリケーションをコンパイルします。以降のビルドでは、変更されていない処理の結果を再利用できます。**ビルド成功**と表示されるまで待ち、CLI が出力するパスを確認してください。デフォルトの出力ディレクトリは `bin` です。macOS GUI は `.app` バンドルとして構成されます。

自分のコンピューターで開発モードを開始します。

```sh
wails3 dev
```

スターターアプリケーションのウィンドウが表示されます。名前を入力し、挨拶機能を試してください。`frontend/index.html` で名前入力欄のプレースホルダーを変更してファイルを保存すると、フロントエンドが更新されます。Go の再ビルドを試すには、`greetservice.go` の挨拶文を編集します。終了したら、ターミナルで **Ctrl+C** を押します。

開発はローカルホスト上で行うワークフローです。リリースプロファイルに複数のクロスビルドターゲットを含めても、開発ウィンドウを実行できるマシンは変わりません。プロダクション用アプリケーションをローカルでビルドして起動するには、`wails3 run` を使用します。[run リファレンス](/reference/wails-yaml-run/)を参照してください。

これで、ソースプロジェクト、レビュー済みのビルドプロファイル、正常に動作するローカル開発ループが用意できました。ソースと `wails.yaml` をバージョン管理にコミットしてください。生成された `.wails/` 作業ファイルは、設定の基準となるソースではありません。

## 次にできること

| 目的 | Wake のサポート | 最初に確認すること |
| --- | --- | --- |
| 別のデスクトップ向けにビルドする | Windows、macOS、Linux の各ターゲット。macOS の両アーキテクチャーとユニバーサル出力を含みます。 | Pure Go と CGo では、コンパイラ要件が異なります。対象の OS とアーキテクチャーでテストしてください。 |
| インストーラーまたはパッケージを作成する | MSIX、NSIS、macOS app/DMG、DEB、RPM、Arch、Void、AppImage。 | NSIS には `makensis` が必要です。AppImage にはターゲットランタイムが必要です。GUI のクロスパッケージ化には、別途用意した Linux ランタイムツリーも必要です。 |
| リリースに署名する | Windows、macOS、DEB/RPM/Arch 向けの、エクスポート済みキーを使用するポータブル署名。ネイティブの ID ストアも引き続き使用できます。 | ID、形式、ホストごとに制限があります。AppImage と Void には組み込みの署名フローがありません。 |
| macOS アプリを公証する | チーム API キーによる送信とチケットのステープル処理、または macOS キーチェーンプロファイル。 | 適切な Developer ID 署名とタイムスタンプは、引き続き必要です。Go で生成したテスト署名がネイティブチェックに合格しても、Apple がリリースを受理する証明にはなりません。 |
| 複数のプログラムをビルドする | GUI、CLI、またはサーバーのプライマリプログラムと、名前付きの付随プログラム。 | 付随プログラムのパッケージと種類を YAML で宣言します。ウィザードはそれらのソースを生成しません。 |
| 別の場所でビルドしたファイルをパッケージ化する | `wails3 build setup --skip-build`. | `build.output` で、実行可能ファイル名とアーキテクチャーが一致するものを指定します。このフラグはコマンド実行時に一度だけ指定する選択肢であり、永続的なプロファイル設定ではありません。 |
| リリースの自動化を追加する | 名前付きプロファイル、範囲が制限されたライフサイクルフック、キャッシュ、パッケージ処理の並列実行。 | リテラル YAML と、宣言済みのプロジェクト所有スクリプトを使用してください。任意の Taskfile 動作を Wake の拡張機構として使用することはできません。 |

`wails.yaml` で `profiles.setup`、その他の名前付きプロファイル、詳細設定を編集します。共有設定と認証情報を変更するには、`wails3 setup` を使用します。完全な例とパッケージ要件については、[YAML ビルドガイド](/experimental/yaml-builds/)を参照してください。GUI アプリケーションには、引き続き対象環境のシステムライブラリが必要です。Pure Go を使用しても、完全な静的アプリケーションにはなりません。

iOS と Android は引き続き実験的な機能であり、それぞれのプラットフォーム SDK と CGo が必要です。この最初のデスクトップ向けレッスンの対象外です。ウィザードを使用しても、任意のホスト間でモバイルビルドを移植可能にはできません。

## 既存のプロジェクトを移行する

作業中の **Wails v3** プロジェクトについて、別のブランチまたは作業コピーで作業してください。これはビルド設定の移行であり、Wails v2 からのアップグレードではありません。有効化後に動作を比較できるよう、既存のビルド結果とテストを保持してください。

@note{type="note" title="レビュー済みの移行から始める"}
現在の組み込みレガシーテンプレートから生成した新規プロジェクトは、フロントエンドをビルドする前に移行できます。Wake は、Taskfile を実行したりカスタム式を評価したりすることなく、標準のタスクセレクターと開発ライフサイクルを認識します。

カスタムタスク、変数のオーバーライド、開発ポリシーについては、引き続き確認が必要です。解析でプロジェクトを表現できない場合は、レガシービルドのままにして診断結果を報告してください。アクティベーションを通すためだけに、必要な動作を削除しないでください。上記の新規プロジェクト向けチュートリアルでは移行は不要です。
@end

### 1. アクティブなビルドを変更せずに解析する

このページの冒頭に従って Wake を有効にし、プレビュー版 CLI を使用します。既存のプロジェクトルートで次を実行します。

```sh
wails3 migrate --dry-run
```

報告された、サポート対象の設定とブロッカーを確認してください。アナライザーはレガシー宣言を読み取りますが、そのコマンドは実行しません。ドライランではアクティブなマニフェストは作成されません。機械可読の診断結果を得るには `wails3 migrate --json` を使用します。ドラフトの書き込みも避ける場合は、`--dry-run --json` を使用してください。

### 2. 非アクティブな提案を作成して確認する

```sh
wails3 migrate
```

これにより作成されるのは **`wails.migrated.yaml`** であり、`wails.yaml` ではありません。既存の Taskfile および `build/config.yml` と照らし合わせて確認してください。プロジェクトのメタデータ、フロントエンドコマンド、ターゲットアーキテクチャ、パッケージの内容、アセット、署名設定を確認します。シークレットは環境変数または認証情報ストアに保管してください。

既知の組み込みタスクはネイティブ設定にマッピングできます。引数を取らず、プロジェクトが所有するスクリプトを呼び出す保守的なライフサイクルタスクは、フックに変換できます。それ以外の到達可能なカスタムタスクの動作はブロッカーです。Wake が暗黙に破棄したり、フォールバックとして Task 経由で実行したりすることはありません。

ドラフトがすでに存在する場合、移行によって確認済みの編集内容が上書きされることはありません。意図的に置換または再生成する前に、コピーを保存してください。アクティベーションチェックを回避するために、ブロックされたドラフトを `wails.yaml` に改名しないでください。サポートされていないレガシー動作を削減または置換し、アクティベーションの前に解析を再実行してください。まだプロジェクトを表現できない場合は、レガシービルドを維持して不足点を報告してください。

### 3. 明示的にアクティベートする

ドラフトを確認してブロッカーを解消したら、次を実行します。

```sh
wails3 migrate --activate --dry-run
wails3 migrate --activate
```

最初のコマンドは、アクティベーションを反映せずに検査します。2 番目のコマンドはレガシー宣言を再確認し、ドラフトを検証してから `wails.yaml` をアトミックに作成します。アクティベーションに成功すると、非アクティブな `wails.migrated.yaml` は削除されます。Taskfile、`build/config.yml`、スクリプト、アセットには変更を加えません。この時点以降、Wake のビルドはアクティブなマニフェストによって制御されます。古いファイルは第 2 の設定ソースにはなりません。

一部の古いプロジェクトには、トップレベルの `info:` セクションを持つ、メタデータ専用の `wails.yaml` がすでに存在します。これはネイティブの Wake マニフェストではありませんが、アクティベーション先をすでに占有しています。そのレガシーファイルを保持したうえで、アクティベーション前に意図的に移動してください。移行ツールが上書きしたり改名したりすることはありません。

### 4. 移行したアプリケーションを検証する

```sh
wails3 config check
wails3 build
wails3 dev
```

カスタムのリリース動作も含め、アプリケーションとパッケージの内容を以前のビルドと比較してください。プロジェクトのテストを実行します。移行した各プロファイルを明示的に確認してください。たとえば、ドラフトに `release` プロファイルが含まれている場合は、`wails3 config check release` と `wails3 build release` を確認します。

移行したプロファイルは `wails.yaml` で直接編集してください。`wails3 init -ui` は新規プロジェクトを作成し、`wails3 setup` はグローバル設定を管理します。どちらも既存プロジェクトのリリースプロファイルを編集するものではありません。

### 実験を中止する必要がある場合

`WAILS_EXP_USE_WAKE` の設定を解除するとオプトインは無効になりますが、アクティブな `wails.yaml` がある場合、Taskfile への自動ルーティングは引き続きブロックされます。無効な YAML がある場合もエラーで停止します。逆移行コマンドはありません。

以前のワークフローに戻すには、アクティブなマニフェストが存在しない状態も含め、移行前のプロジェクトリビジョン全体をバージョン管理から復元し、それと互換性のある CLI と依存関係を使用してください。その前に、必要な新しいソース変更を保存してください。試行用に別のブランチを使用すると、この意図的な復旧が大幅に容易になります。

## 問題を診断してフィードバックを送る

| 症状 | 最初に確認すること |
| --- | --- |
| プロジェクト作成時に Application、Targets、Packages、Tools が省略される | 起動元のターミナルで `WAILS_EXP_USE_WAKE` を設定し、`PATH` 上にある `wails3` 実行ファイルを確認してください。グローバルな `wails3 setup` では常に設定フローが維持されます。 |
| コミュニティテンプレートに移行が必要である | アクティベーションの前に、移行コマンドを使用してレガシー設定を確認してください。 |
| 保存済みのビルドでツール不足が報告される | プロジェクトを作成すると、指定した内容が記録されます。ビルドする前に、報告されたホスト要件をインストールしてください。プロジェクト作成時に、選択したすべてのツールがインストールされるわけではありません。 |
| クロスビルドした実行ファイルをこの環境で起動できない | 選択したオペレーティングシステムとアーキテクチャ上で実行してください。ローカル開発にはホストターゲットを使用します。 |
| プリビルドモードでバイナリが見つからない | マルチターゲット用のサブディレクトリも含め、[プリビルドのファイル名とパス](/experimental/yaml-builds/#use-prebuilt-desktop-executables)を確認してください。 |
| マニフェストの変更に失敗する | 該当するプロファイルに対して `wails3 config check` を実行し、フィールドの診断結果に従ってください。Wake は Taskfile にフォールバックしません。 |

ビルドを実行する前に、`wails3 build setup --plan --json` を使用して内容を確認してください。`wails3 config check` は設定を検証し、`wails3 eject` はアクティブなマニフェストを変更せずに、非アクティブな `wails.ejected.yaml` スナップショットを書き込みます。コマンド出力を共有する前に確認してください。プロジェクトのパスや認証情報の保存場所から、ローカル環境が特定される可能性があります。

[Experiments Discussions](https://github.com/wailsapp/wails/discussions/categories/experiments) でフィードバックを共有するか、[再現可能なバグを報告](https://github.com/wailsapp/wails/issues)してください。CLI とフレームワークのリビジョン、ホストの OS／アーキテクチャ、選択したターゲット、正確なコマンド、Pure Go を選択したかどうか、関連する診断結果を含めてください。失敗した段階が、コンパイル、パッケージ化、署名、アプリケーションの実行のいずれであったかを明記してください。シークレットを削除した最小限のマニフェストと、役立つ場合は `wails3 doctor` の出力も含めてください。
