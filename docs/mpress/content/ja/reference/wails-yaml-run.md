## 利用可否

このリファレンスでは、実験的な run 拡張機能について説明します。リリース版 CLI で利用できることを保証するものではありません。

`wails3 run` は、ローカルマニフェストのデフォルト設定を使用してアプリケーションをビルドし、起動します。マニフェストに基づく実行には、[`WAILS_EXP_USE_WAKE=1` によるオプトイン](/experimental/yaml-builds#enable-yaml-builds)が必要です。マニフェストが見つからない場合、このオプトインを必要とせず、現在のディレクトリで `go run .` を実行します。マニフェストが無効または読み取り不能な場合はエラーとなり、フォールバックが選択されることはありません。YAML が無効な状態でマニフェストが存在する場合、このコマンドは有効化の方法を表示します。

生成された [`wails.yaml` フィールドリファレンス](/reference/wails-yaml-fields)には、フィールドの型とデフォルト値が記載されています。リリースでネイティブモバイルおよび macOS バンドル対応を表明する前に、適切なホスト上で受け入れ検証を行う必要があります。

## コマンドの仕様

`wails3 run` は最も近い `wails.yaml` を検出し、1 つのターゲット用の設定を解決して、既存のキャッシュ対応パイプラインでビルドし、生成物を起動します。検出処理では、作業ディレクトリから上位へ向かって検索し、各階層でマニフェストを確認してから `go.mod` 境界で停止します。マニフェストのディレクトリがプロジェクトルートとなり、デスクトップアプリケーションの作業ディレクトリにもなります。

デフォルトのターゲットは、ホストのオペレーティングシステムとアーキテクチャです。モバイルターゲットは明示的に選択する必要があります。クロスコンパイルを行っても、デスクトップ実行ファイルをホスト上で実行できるとは限りません。互換性のないデスクトップターゲットは、ビルド前に失敗します。これには `CGO_ENABLED=0` でビルドされた実行ファイルも含まれます。Go のみのクロスビルドに成功しても、エミュレーターは提供されず、ローカルでの起動仕様も変わりません。クロスコンパイルには [`wails3 build` を使用し](/experimental/yaml-builds/#cross-compile-desktop-applications)、生成されたファイルはターゲットシステム上で実行またはインストールしてください。Android では `--target android/arm64 --device <adb-serial>` または `--target android/arm64 --emulator <avd-name>` を使用します。選択するアーキテクチャは、デバイスまたはエミュレーターと一致している必要があります。iOS シミュレーターには `--target ios/arm64 --device <udid>` を使用し、実機の場合は `--destination device` を追加します。iOS の計画と実行には macOS と Xcode が必要です。

YAML を使用する場合、ビルドでは埋め込みアセットと本番ビルドパスが使用され、`production` タグが自動的に指定されます。ライブリロードは引き続き `wails3 dev` が担います。`dev.tags` は `wails3 run` には影響しません。

```shell
wails3 run
wails3 run --tags extra_tag
wails3 run -- --example-mode other
wails3 run --plan
wails3 run --skip-build
```

`--plan` は、ビルド、インストール、起動を行わずに、選択したターゲット、有効なビルドタグ、実行可能またはインストール可能な成果物、引数、作業ディレクトリを解決して表示します。計画には環境オーバーライドのキー名が記載されますが、その値は省略されます。

## CLI オプション

| オプション | 意味 |
| --- | --- |
| `--tags <tags>` | 追加する Go ビルドタグをカンマ区切りで指定します。 |
| `--skip-build` | YAML の出力ディレクトリから既存のデスクトップ実行ファイルをインポートし、コンパイルせずに起動します。 |
| `--target <os>/<arch>` | ターゲットを 1 つ選択します。デフォルトはホストの OS とアーキテクチャです。 |
| `--plan` | ビルドまたは起動を行わずに、解決済みの設定を表示します。クロスプラットフォームのデスクトップ計画も指定できます。 |
| `--device <id>` | Android の adb シリアル番号、または iOS のシミュレーター／デバイス識別子です。 |
| `--emulator <name>` | 起動または再利用する Android Virtual Device です。`--device` と併用できません。 |
| `--destination <kind>` | iOS の実行先です。`simulator`（デフォルト）または `device` を指定します。 |
| `-- <args...>` | 設定済みのアプリケーション引数を置き換えます。値を伴わない `--` を指定すると、引数がクリアされます。 |
| `--appargs <string>` | 互換性のための別表記です。POSIX 形式の引用規則を使用して、1 つの文字列を解析します。複数回指定することも、`--` の後に続く引数と併用することもできません。 |

モバイルセレクターを使用するには、マニフェストと、それに一致するモバイルターゲットが必要です。

`--skip-build` を使用するには、アクティブな YAML プロジェクトと互換性のあるデスクトップ実行ファイルが必要です。フロントエンド処理、バインディング、コンパイル、UPX、ビルドフックはスキップされますが、設定済みの起動引数と環境は引き続き適用されます。インポートされた実行ファイルは検証され、ソースファイルを変更することなく Wake が生成したワークスペースにコピーされます。macOS GUI アプリケーションは、それらの入力と現在のパッケージアセットから構成されます。[ビルド済み入力のパスと要件](/experimental/yaml-builds/#use-prebuilt-desktop-executables)を参照してください。
ビルドタグではビルド済み実行ファイルを変更できないため、このモードでは `--tags` と設定済みのビルドタグは効果がありません。

## フィールド

省略可能な `run` マッピングでは、共通の起動デフォルトを指定します。`targets["<os>"]` または `targets["<os>/<arch>"]` 内の省略可能な `run` マッピングでは、プラットフォーム固有またはアーキテクチャ固有のデフォルトを指定します。マップ内の順序にかかわらず、アーキテクチャ固有の設定が OS 全体の設定より優先されます。

| フィールド | 型 | デフォルト | 意味 |
| --- | --- | --- | --- |
| `run.tags` | `list(string)` | `[]` | run ビルドでのみ使用する追加の Go タグです。 |
| `run.args` | `list(string)` | `[]` | アプリケーションに渡す引数です。 |
| `run.environment` | `map(string)` | `{}` | コンパイラー環境とは別に指定する、実行時環境のオーバーライドです。 |
| `target["<os>"].run.tags` | `list(string)` | `[]` | 選択したプラットフォーム用の追加の run タグです。 |
| `target["<os>"].run.args` | `list(string)` | 継承 | 明示的に設定した場合、共通引数を置き換えます。`[]` を指定すると引数がクリアされます。 |
| `target["<os>"].run.environment` | `map(string)` | `{}` | 共通の実行時環境値をキーごとに上書きします。 |

引数はシェル展開を行わず、引数ベクターとして渡されます。環境値は、既存の YAML のリテラル限定仕様に従うリテラル文字列です。

## プラットフォーム別の例

このフラグメントは通常のプロジェクト設定と併用します。`example_private_api` は、この例で必要となる実際のプライベート API タグを表すプレースホルダーです。

```yaml
build:
  tags: [devtools]
run:
  args: [--example-mode]
targets:
  darwin:
    tags: [example_private_api]
    run:
      environment:
        EXAMPLE_WINDOW_MODE: native
  linux:
    run:
      environment:
        GDK_BACKEND: wayland
  windows:
    run:
      args: [--example-mode, --windows-option]
```

Linux の環境設定はこの例に固有であり、Wayland セッションが必要です。Wails のデフォルトではありません。プライベート API タグは macOS でのみ選択されます。既存の `target.tags` は、run ビルドを含む本番ビルドに適用されます。`target.run.tags` は、追加のタグを run ビルドに限定します。

アーキテクチャ固有のオーバーライドを使用して、OS 全体のデフォルトをさらに調整できます。

```yaml
targets:
  linux/arm64:
    run:
      tags: [example_arm64]
      args: []
```

前述の Linux マッピングと組み合わせると、`GDK_BACKEND` を維持したままアーキテクチャ固有のタグを追加し、共通のアプリケーション引数をクリアします。

## 解決規則

| 設定 | 解決順序（優先度の低いものから高いものへ） |
| --- | --- |
| タグ | `build.tags`、選択した `target.tags`、自動指定される `production`、`run.tags`、選択した `target.run.tags`、CLI の `--tags` を結合し、各タグの最初の出現のみを保持します。 |
| 実行時環境 | 起動元のシェル環境を継承し、`run.environment`、選択した `target.run.environment` の順に重ねて適用します。空の値を指定すると、空文字列が設定されます。 |
| アプリケーション引数 | 共通の `run.args` を、明示的に設定したターゲット引数で置き換え、さらに `--` の後に明示した引数で置き換えます。値を伴わない `--` を指定すると、設定済みの引数がクリアされます。 |

選択したターゲット内では、OS 全体の設定を解決してから、アーキテクチャ固有の設定を解決します。タグは蓄積され、環境値はキーごとにマージされ、明示的に指定された引数は、より汎用的な設定のリストを置き換えます。run ビルドでは、対応するモバイルターゲット用の `android` または `ios` も指定されます。

バインディング生成と Go コンパイルには、同じ解決済みタグが渡されます。ビルドキャッシュのキーには、それらのタグが含まれます。アプリケーション引数または実行時環境だけを変更しても、コンパイルキャッシュは無効になりません。次回の起動では新しい値が使用されます。

プラットフォームマッピングは各プラットフォームの設定をカスタマイズするものであり、その存在によって他のプラットフォームが非対応になるわけではありません。`project.supported_platforms` は、ビルドおよび `run` で受け入れるプラットフォームを制限します。省略した場合、または空のリストを指定した場合は、すべてのプラットフォームが許可されます。たとえば、`project` 内の `supported_platforms: [darwin]` により、macOS 専用の例は Linux 上で早期に失敗します。

## プラットフォーム別の起動動作

| プラットフォーム | 起動動作 |
| --- | --- |
| Linux および Windows | 標準入出力を接続し、終了処理とアプリケーションの終了ステータスの伝播を行って実行可能ファイルを起動します。 |
| macOS | アプリバンドルを作成し、標準入出力を接続してその `Contents/MacOS` バイナリを実行します。URL スキームとファイルの関連付けのため、バンドルを Launch Services に登録します。署名とネイティブライフサイクルの受け入れについては、macOS での検証が必要です。 |
| Android | APK をビルドし、デバイスまたはエミュレーターを選択して、アプリケーションをインストールして起動します。ビルド、インストール、起動の失敗はそれぞれ区別して報告します。 |
| iOS | アプリバンドルをビルドし、シミュレーターまたはデバイスを選択し、署名とプロビジョニングの要件を満たしたうえで、インストールして起動します。デバイス向けビルドには、適切な認証情報と Apple ツールチェーンが必要です。 |

Android では、デプロイ前にアプリケーション引数と実行時環境のオーバーライドが拒否されます。Android もサポートする場合、デスクトップ専用の共有設定はデスクトップターゲットのマッピングに配置します。Android の実行ではアプリケーションログにアタッチし、アタッチが終了するとアプリケーションを停止します。iOS は、選択したランチャーに引数を渡します。シミュレーターには `SIMCTL_CHILD_` 変数を通じて環境オーバーライドを渡し、物理デバイスには `devicectl --environment-variables` を通じて JSON マップを渡します。モバイルの終了ステータスは、移植可能なアプリケーション終了コードではなく、ランチャーまたはログ監視の結果を表します。

## Go のみの例とフォールバック

既存または埋め込み済みのアセットを使用する Go のみの例では、フロントエンドの各ステージを無効にします。

```yaml
frontend:
  disabled: true
```

これにより、フロントエンドの依存関係のインストール、バインディングの生成、フロントエンドのビルドをスキップします。生成されたバインディングクラスが必要な例では、代わりに `frontend.bindings` の下に `interfaces: false` を設定できます。

マニフェストがない場合のフォールバックでは、`production` または `devtools` を追加せずに `go run [-tags <tags>] . [application arguments]` を実行します。終了ステータスは Go 自体の動作に従います。`--` より後の引数は、`--help` などのフラグを含めてアプリケーションに渡されます。`--plan` が表示する実行時の値は環境変数のキー名に限られ、値は出力されません。フォールバックプランには Go コマンドと作業ディレクトリが表示されます。

## 開発時のアプリケーション引数

有効な YAML プロジェクトでは、`wails3 dev` は本番用の `run` のデフォルトとは独立してアプリケーション引数を受け取ります。`dev.args` は共有のデフォルトを指定します。`targets["<os>"]` または `targets["<os>/<arch>"]` 内にネストされた `dev` マッピングがある場合、そのターゲットでは共有のデフォルトが置き換えられます。マップ内の順序にかかわらず、アーキテクチャ設定は OS 全体の設定より優先されます。明示的な `args: []` は、継承した引数を消去します。

```yaml
dev:
  args: [--config-path, config/testing.yaml]
targets:
  windows:
    dev:
      args: [--config-path, config/testing-windows.yaml]
```

`run.args` と `run.tags` は開発時の起動には影響しません。既存の `dev.tags` ビルドポリシーは変更されません。アプリケーションの相対パスは、マニフェストディレクトリを基準としてアプリケーションによって解釈されます。

```shell
wails3 dev
wails3 dev -- --config-path "profile with spaces.yaml"
wails3 dev --appargs='--config-path "profile with spaces.yaml"'
wails3 dev --
wails3 dev --plan
```

`--` より後の引数は、リストが空の場合も含めて、設定済みの引数を置き換えます。この区切り記号より後の `--help` はアプリケーションに属します。`--appargs=""` もデフォルトを消去します。互換性オプションは、引用符で囲まれた文字列を 1 つ受け取ります。このオプションを `--`、位置指定のアプリケーション引数、または 2 つ目の `--appargs` と併用するとエラーになります。不正な引用符の構文は、セッションを開始する前に拒否されます。

互換性パーサーは、すべてのホストで同じ POSIX 形式の引用規則を使用します。シェルコマンドの実行や変数の展開は行いません。ただし、呼び出し元のシェルが Wails にテキストを渡す前に、すでに展開している場合があります。`--` より後の引数は、すでに個別の値になっているため、追加のトークン分割は行われません。これは Windows のパスに推奨される形式です。たとえば PowerShell では次のようにします。

```powershell
wails3 dev -- --config-path 'C:\Users\Example User\testing.yaml'
```

セッションは、ソースの再ビルド後も解決済みの引数ベクトルを保持します。`dev.args` または選択したターゲットの引数だけを変更すると、キャッシュ済みの実行可能ファイルを使用してバックエンドが再起動されます。フロントエンドは再起動されません。CLI のオーバーライドは、マニフェストの再読み込み後も有効です。置き換えに失敗した場合は、以前の引数を指定した以前の実行可能ファイルを維持するか、復元します。アプリケーション引数はコンパイラーフラグではなく、コンパイルキャッシュのキーには含まれません。`dev --plan` は、起動せずに、有限のビルドプランとともに有効な引数を表示します。

Linux、Windows、macOS は、引数ベクトルを実行可能ファイルに直接渡します。iOS は、シミュレーターまたはデバイスのランチャーを通じて渡します。Android では、同等の引数チャネルがサポートされていないため、空でない開発用アプリケーション引数は、デバイスの検出やビルドの前に拒否されます。デスクトップ専用のデフォルトは、デスクトップターゲットのマッピングに配置するか、`targets.android.dev` の下の `args: []` で消去できます。

これらの開発オプションには、有効な `wails.yaml` と YAML によるオプトインが必要です。従来の開発パスにある Taskfile またはウォッチャーのシェルコマンドは書き換えません。
