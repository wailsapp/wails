このガイドは既存の v3 アルファ版プロジェクトを対象としています。Wails v2 から移行する場合は、[v2 から v3 へのガイド](/migration/v2-to-v3/)を使用してください。

## アップグレードの前に

プロジェクトをコミットするか、バックアップしてください。現在のアルファ版から選択したベータ版までの[変更履歴](/changelog/)を読んでください。ソースコード、API、ビルド設定の変更が必要になる場合があります。[デスクトップの互換性ポリシー](/status/)と、利用するプラットフォームの要件を確認してください。

以下のコマンドは、公開済みの `v3.0.0-beta.23` をバージョン固定の例として使用しており、常に最新リリースを追従することを推奨するものではありません。別のリリースを選ぶ場合は、CLI、Go モジュール、npm ランタイムのバージョンを確認し、各コマンドをまとめて更新してください。この例では、npm のバージョンは Go のバージョンから接頭辞 `v` を除いたものです。

## 1. CLI を更新する

```sh
go install github.com/wailsapp/wails/v3/cmd/wails3@v3.0.0-beta.23
wails3 version
```

`wails3 version` がインストールしたバージョンを表示することを確認してください。`PATH` の先にある古い実行ファイルが、新しい CLI より優先される場合があります。

## 2. Go モジュールを更新する

プロジェクトのルートで実行してください。依存関係の変更を確認し、無関係なモジュールを一括更新しないでください。

```sh
go get github.com/wailsapp/wails/v3@v3.0.0-beta.23
go mod tidy
```

## 3. フロントエンドランタイムを更新する

npm と `frontend` ディレクトリを使用するプロジェクトの場合：

```sh
cd frontend
npm install --save-exact @wailsio/runtime@3.0.0-beta.23
cd ..
```

ロックファイルを保持し、変更を確認してください。フロントエンドが別のパッケージマネージャーやディレクトリを使用している場合は、ランタイムのバージョンを固定したまま、この手順を調整してください。

## 4. 再生成、ビルド、テストを行う

プロジェクトのルートで、Go サービスからバインディングを再生成し、ビルドしてください。

```sh
wails3 generate bindings
wails3 build
```

ビルドしたアプリケーションを起動し、配布対象の各サポートプラットフォームで操作の流れをテストしてください。ソース、生成されたバインディング、モジュールファイル、フロントエンドのロックファイルの変更を確認し、まとめてコミットしてください。

## アップグレードに失敗した場合

`PATH` 上の CLI、`go list -m github.com/wailsapp/wails/v3` でモジュールのバージョン、`npm --prefix frontend ls @wailsio/runtime` でインストール済みランタイムを確認してください。バージョンの不一致を解消した後、バインディングを再生成してください。すべてのアルファ版がコード変更なしでアップグレードできるとは考えないでください。

問題が解消しない場合は、旧バージョンと新バージョン、正確なエラー、`wails3 doctor` の出力を添えて、[再現可能な問題を報告](https://github.com/wailsapp/wails/issues/new/choose)してください。脆弱性については[セキュリティポリシー](https://github.com/wailsapp/wails/blob/master/SECURITY.md)に従ってください。
