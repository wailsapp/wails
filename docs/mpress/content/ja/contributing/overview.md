## Wails v3 技術ドキュメントへようこそ

このセクションでは、コミュニティのガイドラインやプルリクエストの作成方法は扱いません。代わりに、コードベースの全体像をすばやく把握し、自信を持って開発を始められるよう、**Wails v3 の仕組み**を詳しく解説します。これは**コミュニティガイドラインに関するセクションではありません**。

ランタイムの修正、CLI の拡張、新しいテンプレートの作成、あるいは内部構造の理解が目的であっても、以降のページで必要な技術的背景を得られます。

---

## 上位レベルのアーキテクチャ

@cards{cols="2"}
◇ Go バックエンド
すべての Wails アプリの中核は、ネイティブ実行ファイルにコンパイルされる Go コードです。アプリケーションロジック、システム連携、パフォーマンスが重視される処理を担います。

---
▤ Web フロントエンド
UI は標準的な Web 技術（React、Vue、Svelte、Vanilla など）で記述し、軽量なシステム WebView（Linux/macOS では WebKit、Windows では WebView2）でレンダリングします。

---
◆ ブリッジ層
ゼロコピーのインメモリブリッジにより、自動型変換、イベント伝播、エラー転送を伴う **Go⇄JavaScript** 呼び出しが可能になります。

---
▸ CLI とツール群
`wails3` は、プロジェクトの作成、ライブリロード対応の開発サーバー、アセットのバンドル、クロスコンパイル、パッケージ作成（deb、rpm、AppImage、msi、dmg など）を統括します。

@end

---

## アーキテクチャの概要

**Wails v3 – エンドツーエンドのフロー**

**[エンドツーエンドのフロー図のプレースホルダー]**

この図は、次の**エンドツーエンドのフロー**を示しています。

1. **CLI** が、生成、開発サーバー、コンパイル、パッケージ作成を制御します。\
2. **バインディングシステム**は、**Web フロントエンド**から**Go バックエンド**を呼び出せるようにするグルーコードを生成します。\
3. 開発時には、**アセットサーバー**がフレームワークの開発サーバーにプロキシし、本番環境では埋め込まれたファイルを配信します。\
4. 実行時には、**デスクトップランタイム**がウィンドウと OS API を管理し、**ブリッジ**が Go と JavaScript の間でメッセージを転送します。

## このドキュメントで扱う内容

| トピック | 重要である理由 |
| --- | --- |
| **コードベースの構成** | `/v3` ディレクトリの構成とモジュール間の連携。 |
| **ランタイムの内部構造** | ウィンドウ管理、システム API、メッセージプロセッサ、プラットフォーム互換層。 |
