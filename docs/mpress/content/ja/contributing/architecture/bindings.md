このガイドでは、Wails のバインディングシステムの内部動作について説明し、自動コード生成の背後にある仕組みを理解したい開発者向けに詳しい情報を提供します。

## アーキテクチャの概要

Wails のバインディングシステムは、主に次の 3 つのコンポーネントで構成されています。

1. **収集**：Go コードを解析し、サービス、モデル、その他の宣言に関する情報を抽出します
2. **設定**：バインディング生成プロセスの設定とオプションを管理します
3. **レンダリング**：収集した情報に基づいて JavaScript/TypeScript コードを生成します

@filetree
- internal/generator/
  - collect/     # パッケージの解析と情報の抽出
  - config/      # 設定用の構造体とインターフェース
  - render/      # JS/TS のコード生成
@end

## 収集プロセス

収集プロセスは、Go パッケージを解析し、サービス、モデル、その他の宣言に関する情報を抽出します。この処理は `collect` パッケージが担当します。

### 主要コンポーネント

- **Collector**：パッケージ情報を管理し、収集したデータをキャッシュします
- **Package**：解析対象の Go パッケージを表し、収集したサービス、モデル、ディレクティブを保存します
- **Service**：サービス型とそのメソッドに関する情報を収集します
- **Model**：フィールド、値、型パラメーターなど、モデル型に関する詳細情報を収集します
- **Directive**：Go ソースコード内の `//wails:` ディレクティブを解析して解釈します

### 収集フロー

1. コレクターがプロジェクトで指定された Go パッケージをスキャンします
2. サービス型（フロントエンドに公開されるメソッドを持つ構造体）を特定します
3. 各サービスについて、そのメソッドに関する情報を収集します
4. モデル型（サービスメソッドのパラメーターまたは戻り値として使用される構造体）を特定します
5. 各モデルについて、そのフィールドと型パラメーターに関する情報を収集します
6. コード内で見つかったすべての `//wails:` ディレクティブを処理します

## レンダリングプロセス

レンダリングプロセスは、収集した情報に基づいて JavaScript/TypeScript コードを生成します。この処理は `render` パッケージが担当します。

### 主要コンポーネント

- **Renderer**：サービス、モデル、インデックスファイルのレンダリングを統括します
- **Module**：生成される個々の JavaScript/TypeScript モジュールを表します
- **Templates**：コード生成に使用するテキストテンプレートです

### レンダリングフロー

1. レンダラーはサービスごとに、そのサービスメソッドに対応する関数を含む JavaScript/TypeScript ファイルを生成します
2. レンダラーはモデルごとに、そのモデル構造体に対応する JavaScript/TypeScript クラスを生成します
3. レンダラーは、すべてのサービスとモデルを再エクスポートするインデックスファイルを生成します
4. レンダラーは、`//wails:inject` ディレクティブで指定されたカスタムコード挿入をすべて適用します

## 型のマッピング

バインディングシステムで特に重要な点の 1 つは、Go の型を JavaScript/TypeScript の型にマッピングする方法です。マッピングの概要を次に示します。

| Go の型 | JavaScript の型 | TypeScript の型 |
| --- | --- | --- |
| `bool` | `boolean` | `boolean` |
| `int`, `int8`, `int16`, `int32`, `int64`, `uint`, `uint8`, `uint16`, `uint32`, `uint64`, `float32`, `float64` | `number` | `number` |
| `string` | `string` | `string` |
| `[]byte` | `Uint8Array` | `Uint8Array` |
| `[]T` | `Array<T>` | `T[]` |
| `map[string]V` | `Object` | `{ [_: string]: V }` |
| `map[K]V`（文字列以外の `K`） | `Object` | `{ [_ in K]?: V }` |
| `struct` | `Object` | カスタムクラス |
| `interface{}` | `any` | `any` |
| `*T` | `T \| null` | `T \| null` |
| `func` | サポートされていません | サポートされていません |
| `chan` | サポートされていません | サポートされていません |

## ディレクティブシステム

バインディングシステムでは、生成されるコードをカスタマイズするための複数のディレクティブをサポートしています。これらのディレクティブは、Go コード内にコメントとして追加します。

### 利用可能なディレクティブ

- `//wails:inject`：生成されるバインディングにカスタム JavaScript/TypeScript コードを挿入します
- `//wails:include`：生成されるバインディングに追加のファイルを含めます
- `//wails:internal`：型またはメソッドを内部用としてマークし、フロントエンドにエクスポートされないようにします
- `//wails:ignore`：バインディング生成時にメソッドを完全に無視します
- `//wails:id`：デフォルトのハッシュベース ID を上書きし、メソッドのカスタム ID を指定します

### ディレクティブの処理

1. 収集フェーズで、コレクターが Go コード内のディレクティブを識別して解析します
2. ディレクティブは、対応する宣言（サービス、メソッド、モデルなど）とともに保存されます
3. レンダリングフェーズで、レンダラーがディレクティブを適用し、生成されるコードをカスタマイズします

## 高度な機能

### 条件付きコード生成

バインディングシステムでは、`include` および `inject` ディレクティブに 2 文字の条件プレフィックスを使用した条件付きコード生成をサポートしています：

```
<language><style>:<content>
```

各文字の意味は次のとおりです：

- `<language>` には次の値を指定できます：
  - `*` - JavaScript と TypeScript の両方
  - `j` - JavaScript のみ
  - `t` - TypeScript のみ


- `<style>` には次の値を指定できます：
  - `*` - クラスとインターフェイスの両方
  - `c` - クラスのみ
  - `i` - インターフェイスのみ


例：

```go
//wails:inject j*:console.log("JavaScript only");
//wails:inject t*:console.log("TypeScript only");
```

### カスタムメソッド ID

デフォルトでは、メソッドはハッシュベースの ID で識別されます。ただし、`//wails:id` ディレクティブを使用してカスタム ID を指定できます：

```go
//wails:id 42
func (s *Service) CustomIDMethod() {}
```

これは、コードをリファクタリングする際に互換性を維持するのに役立ちます。

## パフォーマンス上の考慮事項

バインディングジェネレーターは効率的に動作するよう設計されていますが、いくつか留意すべき点があります：

1. 初回実行時は、スキャン対象パッケージのキャッシュを構築するため、処理が遅くなります
2. 2 回目以降の実行では、キャッシュされた情報を使用するため、処理が速くなります
3. ジェネレーターはプロジェクト内のすべてのパッケージを処理するため、大規模なプロジェクトでは時間がかかる場合があります
4. `-clean` フラグを使用すると、生成前に出力ディレクトリをクリーンアップできます

## デバッグ

バインディング生成で問題が発生した場合は、`-v` フラグを使用してデバッグ出力を有効にできます：

```bash
wails3 generate bindings -v
```

これにより、収集およびレンダリング処理に関する詳細情報が出力され、問題の原因を特定するのに役立ちます。
