## ついにリリース！

本日、[Wails](https://wails.io) v2 をリリースしました。最初の v2 アルファ版から約 18 か月、最初のベータ版から約1年が経ちました。プロジェクトの発展に携わってくださったすべての方に、心から感謝します。

これほど時間がかかった理由の一つは、正式に v2 と呼ぶ前に、何らかの形で完成といえる状態に到達したいと考えていたためです。しかし実際には、リリースにタグを付ける完璧なタイミングなどありません。未解決の問題や、何とか盛り込みたい「あと一つ」の機能が常に残るものです。それでも、完全ではないメジャーリリースにタグを付けることで、プロジェクトのユーザーには一定の安定性がもたらされ、開発者にとっても一区切りになります。

今回のリリースは、かつて想像していた以上のものになりました。私たちが開発を楽しんだのと同じくらい、皆さんにも楽しんでいただければ幸いです。

## Wails *とは*？

Wails をご存じない方のために説明すると、これは Go プログラマーが使い慣れた Web 技術を利用して、Go プログラムに高機能なフロントエンドを提供できるようにするプロジェクトです。Electron に代わる、Go 製の軽量な選択肢です。詳しくは[公式サイト](https://v2.wails.io/docs/introduction)をご覧ください。

## 新機能

v2 リリースは、このプロジェクトにとって大きな飛躍であり、v1 にあった多くの課題を解消しています。[macOS](/blog/wails-v2-beta-for-mac/)、[Windows](/blog/wails-v2-beta-for-windows/)、[Linux](/blog/wails-v2-beta-for-linux/) 向けベータ版に関するブログ記事をまだ読んでいない方は、ぜひご覧ください。主要な変更点がすべて詳しく説明されています。要約すると、次のとおりです。

- 最新の Web 標準とデバッグ機能に対応した、Windows 用の Webview2 コンポーネント。
- Windows での[ダーク／ライトテーマ](https://v2.wails.io/docs/reference/options#theme)と[カスタムテーマ](https://v2.wails.io/docs/reference/options#customtheme)。
- Windows では CGO が不要になりました。
- Svelte、Vue、React、Preact、Lit、Vanilla のプロジェクトテンプレートを標準でサポート。
- アプリケーションのホットリロード開発環境を提供する [Vite](https://vitejs.dev/) 統合。
- ネイティブアプリケーションの[メニュー](https://v2.wails.io/docs/guides/application-development#application-menu)と[ダイアログ](https://v2.wails.io/docs/reference/runtime/dialog)。
- [Windows](https://v2.wails.io/docs/reference/options#windowistranslucent) と [macOS](https://v2.wails.io/docs/reference/options#windowistranslucent-1) のネイティブなウィンドウ半透明効果。Mica と Acrylic の背景効果にも対応。
- Windows へのデプロイ用[NSIS インストーラー](https://v2.wails.io/docs/guides/windows-installer)を簡単に生成。
- ウィンドウ操作、イベント処理、ダイアログ、メニュー、ロギングのユーティリティメソッドを提供する、充実した[ランタイムライブラリ](https://v2.wails.io/docs/reference/runtime/intro)。
- [garble](https://github.com/burrowers/garble) を使用したアプリケーションの[難読化](https://v2.wails.io/docs/guides/obfuscated)に対応。
- [UPX](https://upx.github.io/) を使用したアプリケーションの圧縮に対応。
- Go 構造体から TypeScript を自動生成。詳しくは[こちら](https://v2.wails.io/docs/howdoesitwork#calling-bound-go-methods)。
- どのプラットフォームでも、追加のライブラリや DLL をアプリケーションに同梱する必要はありません。
- フロントエンドアセットをバンドルする必要はありません。ほかの Web アプリケーションと同じように開発できます。

## 功績と謝辞

v2 に到達するまでには、多大な労力を要しました。最初のアルファ版から本日のリリースまでに、89 人のコントリビューターによる約 2200 件のコミットがありました。さらに、翻訳、テスト、フィードバック、ディスカッションフォーラムや Issue トラッカーでの支援に携わった方々が大勢います。皆さん一人ひとりに、言葉では言い表せないほど感謝しています。また、指針、助言、フィードバックを提供してくださったプロジェクトスポンサーの皆さんにも、特別な感謝をお伝えしたいと思います。皆さんのあらゆる貢献に、心から感謝します。

ここで、何人かの方を特にご紹介します。

まず、私たち全員が恩恵を受ける数多くの貢献に加え、多くの Issue で手厚い支援を提供してくださった [@stffabi](https://github.com/stffabi) に、**心から**感謝します。外部開発サーバーのサポートなど、いくつもの重要な機能を提供してくれました。これにより [Vite](https://vitejs.dev/) の強力な機能を活用できるようになり、私たちの開発モードは一変しました。彼の[素晴らしい貢献](https://github.com/wailsapp/wails/commits?author=stffabi&since=2020-01-04)がなければ、Wails v2 は今よりずっと魅力の少ないリリースになっていたでしょう。@stffabi、本当にありがとうございます！

Web サイトを絶えず保守し、中国語翻訳の提供、Crowdin の管理、新しい翻訳者の立ち上がり支援まで担ってくださった [@misitebao](https://github.com/misitebao) にも、心から感謝します。これは非常に重要な仕事です。注いでくださったすべての時間と労力に、深く感謝しています。本当に最高です！

最後になりましたが、v2 の開発中に助言と支援を提供してくださった Mat Ryer に、心から感謝します。v2 の初期アルファ版を使って xBar を一緒に開発した経験は、v2 の方向性を形作るうえで役立ち、初期リリースにあった設計上の欠陥を理解する機会にもなりました。本日から xBar の Wails v2 への移植を開始し、このプロジェクトの旗艦アプリケーションとすることをお知らせでき、うれしく思います。ありがとう、Mat！

## 得られた教訓

v2 に到達する過程で多くの教訓を得ました。これらは今後の開発方針を形作るものになります。

## 小規模で迅速、焦点を絞ったリリース

v2 の開発過程では、多くの機能やバグ修正が場当たり的に開発されました。その結果、リリースサイクルが長くなり、デバッグも難しくなりました。今後は、含める機能を絞ったリリースを、より頻繁に行います。各リリースでは、ドキュメントの更新と徹底的なテストも実施します。こうした小規模で迅速、かつ焦点を絞ったリリースによって、リグレッションが減り、ドキュメントの品質が向上することを期待しています。

## 参加の促進

このプロジェクトを始めた当初は、問題を抱えているすべての人をすぐに助けたいと考えていました。Issue を「自分自身の問題」と捉え、できるだけ早く解決したいと思っていたのです。しかし、これは持続可能ではなく、最終的にはプロジェクトの長期的な存続を損ないます。今後は、質問への回答や Issue のトリアージに、ほかの方が参加できる余地を広げます。そのためのツールも用意できればと考えています。提案があれば、[こちら](https://github.com/wailsapp/wails/discussions/1855)のディスカッションにぜひご参加ください。

## 「No」と言うことを学ぶ

オープンソースプロジェクトに関わる人が増えるほど、大多数の人にとって役立つかどうか分からない追加機能への要望も増えていきます。こうした機能には、開発とデバッグのための初期コストがかかり、その後も継続的な保守コストが発生します。私自身、この点では最も反省すべき立場にあります。実用最小限の機能を提供するよりも、つい「すべてを一度に解決」しようとしてしまうからです。今後は、コア機能の追加に対して、これまで以上に「No」と言う必要があります。そして、開発者自身がその機能を提供できるようにする方法へ力を注ぎます。この用途に向けて、プラグインを本格的に検討しています。これにより、誰でも必要に応じてプロジェクトを拡張でき、プロジェクトに貢献するための簡単な方法も提供できます。

## 今後の展望

次のメジャー開発サイクルで Wails に追加することを検討しているコア機能は、すでに数多くあります。[ロードマップ](https://github.com/wailsapp/wails/discussions/1484)には興味深いアイデアが満載で、着手するのが楽しみです。特に要望が多い機能の一つが、複数ウィンドウのサポートです。これを正しく実現するのは難しく、現行 API は複数ウィンドウを想定して設計されていないため、別の API の提供を検討する必要があるかもしれません。初期段階のアイデアとフィードバックを踏まえると、私たちが目指している方向性を皆さんにも気に入っていただけると思います。

個人的には、Wails アプリをモバイルで動かせる可能性にとても期待しています。Wails アプリを Android で実行できることを示すデモプロジェクトはすでにあります。この先どこまで進めるのか、ぜひ探っていきたいと思います！

最後に取り上げたいのは、機能の同等性についてです。これまで、完全なクロスプラットフォーム対応がないものはプロジェクトに追加しないことを、長年にわたり基本原則としてきました。これまでは（ほぼ）実現できていましたが、そのために新機能のリリースが大きく妨げられてきたのも事実です。今後は、少し異なるアプローチを採用します。すべてのプラットフォーム向けに直ちにリリースできない新機能は、試験的な設定または API としてリリースします。これにより、一部のプラットフォームの早期導入者がその機能を試し、最終的な機能設計に反映されるフィードバックを提供できるようになります。もちろん、その機能をサポート可能なすべてのプラットフォームで完全にサポートされるまでは、API の安定性は保証されません。それでも、少なくとも開発が滞ることはなくなります。

## 最後に

V2 リリースで成し遂げられたことを、本当に誇りに思います。これまでのベータリリースを使って、すでに多くの方が素晴らしいものを構築していることに驚かされます。[Varly](https://varly.app/)、[Surge](https://getsurge.io/)、[October](https://october.utf9k.net/) といった高品質なアプリケーションです。ぜひチェックしてみてください。

このリリースは、多くのコントリビューターの尽力によって実現しました。無料でダウンロードして使用できますが、コストを一切かけずに生まれたわけではありません。誤解のないように言えば、このプロジェクトには多大なコストがかかっています。費やされたのは、私や一人ひとりのコントリビューターの時間だけではありません。その人たちが友人や家族と過ごせなかった時間も含まれます。だからこそ、このプロジェクトの実現に捧げられた一秒一秒に、心から感謝しています。コントリビューターが増えれば、この負担をより多くの人で分かち合い、力を合わせてさらに多くのことを実現できます。ほかの人が報告したバグを確認する、修正案を提案する、ドキュメントを変更する、困っている人を手助けするなど、自分にできることを一つ選んで貢献していただければと思います。こうした小さな取り組みの一つひとつが、非常に大きな影響をもたらします。v3 に至るまでの物語に、皆さんも加わっていただけたら最高です。

お楽しみください！
