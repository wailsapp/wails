## ついに登場！

本日、Wails v3.0.0 をリリースします。

正直に言うと、ここまで長い道のりでした。最初の v3 アルファタグを 2023 年1月に公開して以来、実に多くの方々が開発、テスト、破壊、修正を重ねてきました。皆さん一人ひとりに心から感謝しています。この道のりについて率直に記した記事を読みたい方は、[v3ベータ版の発表](/blog/wails-v3-beta/)をご覧ください。

## Wails *とは*？

初めての方へ：Wailsを使うと、Goプログラマーは使い慣れたWebフロントエンドツールを利用してデスクトップアプリケーションを構築できます。組み込みブラウザーではなく、各プラットフォームのネイティブWebViewを使用します。バックエンドをGoで、UIをHTML、CSS、JavaScript（または任意のフレームワーク）で記述すると、Wailsがすべてを1つのネイティブアプリケーションにまとめます。

## なぜ v3 なのか？

Wails v2 により、モダンなWebフロントエンドを備えたGoアプリケーションを簡単に構築でき、多くのアプリケーションで十分に役立ってきました。しかし、単一ウィンドウでコンテキスト駆動のランタイムであるため、日常的なデスクトップ開発の一部が本来より難しくなっていました。

v3 は異なるモデルを基盤としています。アプリケーション、ウィンドウ、サービス、イベント、プラットフォーム機能が明示的なオブジェクトです。アプリケーションを作成し、サービスを登録し、ウィンドウを作成して、必要な動作を所有するオブジェクトとやり取りします。アプリが成長しても処理を追いやすく、複数ウィンドウなどの機能も回避策ではなく、モデルの通常の一部として扱われます。

## v3.0.0 の内容

- **複数ウィンドウ。** 実行時にウィンドウを作成、管理、終了できます。各ウィンドウには固有の設定とライフサイクルがあります。
- **システムトレイ。** メニュー、ライト／ダークアイコン、macOSのテンプレートアイコンを利用して、アプリを常駐させられます。トレイアイコンにウィンドウを関連付けることもできます。
- **ネイティブメニューとダイアログ。** 各プラットフォームで、アプリケーションメニュー、コンテキストメニュー、ネイティブダイアログを利用できます。
- **サービスと生成バインディング。** バックエンドは通常のGoコードのままです。静的ソース解析によってバインディングが生成されるため、コメントや意味のあるパラメーター名がフロントエンドにも引き継がれます。必要なコマンドは `wails3 generate bindings` 1つだけです。
- **中身を確認できるビルドシステム。** プロジェクトでは、不透明な1つのコマンドではなく、内容を確認、拡張、デバッグできる [Taskfile](https://taskfile.dev) ベースのビルドを使用します。
- **クロスプラットフォーム。** Windows（amd64およびarm64）、macOS（IntelおよびApple Silicon）、Linux（amd64およびarm64）に対応しています。LinuxではGTK4とWebKitGTK 6.0 がデフォルトです。従来のGTK3スタックも、v3.1 までは `-tags gtk3` で引き続き利用できます。
- **iOSとAndroid。** 同じ `main.go` とフロントエンドをモバイルでも実行できます。ドキュメントではモバイル対応がまだ実験的機能とされているため、安定性を保証された機能ではなく、試用してフィードバックを寄せるための機能として扱ってください。
- **Go 1.26 でビルド。** v3 モジュールはGo 1.26 でビルドされます。
- **アプリ内アップデーター。** 差し替え可能なプロバイダー、暗号学的検証、アトミックな置換、テーマ変更や差し替えが可能なデフォルトUIを備えています。[アップデーターガイド](/guides/updater/)をご覧ください。
- **パッケージングと署名。** 全プラットフォーム向けの[コード署名](/guides/build/signing/)、[インストーラー](/guides/installers/)、[MSIXパッケージング](/guides/build/msix/)のガイドを用意しています。
- **サーバービルド。** 同じアプリケーションとサービスを、ネイティブウィンドウなしでHTTPサーバーとして実行できます。

## ベータ版以降の主な変更点

ベータ版の記事を8月 2 日に公開して以来、変更履歴には多くの更新が加わりました。特に取り上げたい点をいくつか紹介します。

- **新しいドキュメントサイト。** ドキュメントは現在、私たち独自のドキュメントツールである [M-Press](https://m-press.me) 上で稼働しています。翻訳も完了し、コミュニティーから移行されました。引き続き英語版ドキュメントが唯一の正規情報源です。
- **より堅牢になったWindowsでの動作。** WebView2のプロセス障害が発生しても空白のウィンドウが残らず、Wailsが復旧するようになりました。その過程で、WebView2のCOMライフタイムに関する複数の問題も修正しました。
- **キーボード配列を尊重するグローバルショートカット。** macOSでは、AZERTY、QWERTZ、Dvorakなどの配列で、文字アクセラレーターがキーに表示された文字に従うようになりました。
- **アップデーターの堅牢化。** Linuxでファイルシステムをまたいでバイナリを置換する際の問題や、AppImage更新の問題などを修正しました。
- **セットアップとツール。** `wails3 setup` ウィザードが完成し、アプリの終了時に `wails3 dev` がバックグラウンドプロセスを停止するようになりました。
- **macOSのネイティブLiquid Glass。** macOS 26 以降でLiquid Glassエフェクトに対応し、それ以前のバージョンではフォールバックを使用します。

## v2 からの移行

v3 は新しいメジャーバージョンであり、移行は単なるバージョン更新ではなく、本格的な移植作業です。主な変更点は、アプリケーションとウィンドウのライフサイクル、コンテキストに紐づくバインディングに代わるサービス、v2 ランタイムパッケージに代わるアプリケーションおよびウィンドウの直接API、フロントエンドバインディングの再生成です。

[v2からv3への移行ガイド](/migration/v2-to-v3/)では、変更前後の例を交えてすべての手順を説明しています。計画的に移植し、作業の各段階でテストしてください。v3 アプリケーションの準備が整うまでは、v2 を維持してください。

**Wails v2 はなくなりません。** 今後も重大な更新を受け取ります。新規プロジェクトでは v3.0.0 を使用してください。2つのCLIは、モジュールのインポートパスが異なる別々のバイナリ（`wails` と `wails3`）なので、同じマシンに両方をインストールできます。

## インストール

次のコマンドで v3.0.0 CLIをインストールします。

```sh
go install github.com/wailsapp/wails/v3/cmd/wails3@v3.0.0
```

続いて、対話形式のセットアップウィザードを実行します。このウィザードは環境を確認し、Wailsに必要な依存関係の準備を支援します。

```sh
wails3 setup
```

![ダークモードで表示したWails v3 セットアップウィザード](/assets/screenshots/wails3-setup-wizard-dark.png)

次に、最初のプロジェクトを作成します。

```sh
wails3 init
```

## サポートとリリース

Wailsは予想をはるかに超えて成長し、膨大な数のIssueやプルリクエストへの対応が難しくなっていました。リリースが場当たり的になることもあり、修正やコントリビューションがユーザーに届くまで長く待たせてしまうこともありました。トリアージやリリース準備の基礎作業をさらに自動化する仕組みを導入したため、問題により迅速に対応し、改善や新機能のリリースにより多くの時間を充てられるようになります。

v3.0.0 以降は、`v3.1.0-nightly.20261026` のように日付を付けたタグによる**ナイトリープレリリース**と、`v3.1.0` や `v3.2.0` のような**週次マイナーリリース**を並行して提供します。ナイトリーでは最新の修正をより早く利用でき、週次リリースではテスト済みの更新を定期的に受け取れます。

再現可能なバグを見つけた場合は、`wails3 doctor` の出力と最小限の再現例を添えて報告してください。新しい機能や公開動作の変更を提案する場合は、機能リクエストのIssueではなく、WEP（Wails Enhancement Proposal）のドラフトPRを作成してください。

## 翻訳

Wails v2 ドキュメントの翻訳にご協力くださった皆さんに、心より感謝します。開発者が母国語でドキュメントを読めるよう、皆さんは時間を割いてくださいました。そのことが、多くの人にとって大きな意味を持ちました。本当にありがとうございました。

Crowdinの管理は特に難しいと判断し、使用を終了しました。v3以降、ドキュメントは自動的に翻訳され、翻訳版は英語版のページとともにリポジトリで管理されます。

まだ対応していない言語への翻訳を希望する場合や、既存の翻訳に誤りを見つけた場合は、Issueを作成してお知らせください。皆さんからのご意見をお待ちしており、すべての報告に感謝しています。
