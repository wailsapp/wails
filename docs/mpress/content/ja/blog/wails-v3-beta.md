本日、Wails v3 Beta をリリースします。

Wails を使用すると、Go 開発者は使い慣れた Web フロントエンドツールを用い、組み込みブラウザではなく各プラットフォームのネイティブ WebView でデスクトップアプリケーションを構築できます。v3 は大きな進歩です。より直接的な API、より明確なビルドモデル、そして Wails による対応が求められてきたデスクトップアプリケーションのための、より優れた基盤を提供します。

これはベータリリースであり、最終的な 3.0 リリースではありません。デスクトップ API は安定しており、すでに複数のチームが v3 を本番環境で使用していますが、デプロイ前に十分なテストを行ってください。このベータ期間には、コミュニティとともに互換性とワークフローに残る問題を洗い出します。Wails v2 は引き続き現行の安定版であり、今後も修正が提供されます。

## ベータ期間中のドキュメント

ベータ期間中は、API とワークフローの最終検証を進める一方で、英語版ドキュメントを信頼できる唯一の情報源として維持します。現段階では翻訳 PR を受け付けていません。翻訳者が繰り返し変更に追随せずに作業できる程度にドキュメントが安定した後、一般提供の開始前に翻訳作業を再開します。

## v3 の内容

- マルチウィンドウのファーストクラスサポートを含む、明示的なアプリケーション API とウィンドウ API
- 静的ソース解析によって、コメントや意味のあるパラメーター名を保持した、より充実した TypeScript バインディングを生成する Go サービス
- バックエンド API とともにフロントエンドのアセットやスクリプトをバンドルできるサービス。インストール可能で高機能なプラグインの基盤となります
- 内容を確認し、拡張やデバッグもできる、Taskfile ベースの明示的なビルドシステム
- ネイティブなデスクトップウィンドウを使用せずに、同じアプリケーションとサービスを実行するためのサーバービルド
- サポートされる環境で、Intel、Apple Silicon、amd64、arm64 上の macOS、Windows、Linux に対応する最新のデスクトップサポート
- iOS と Android の実験的なモバイルサポート。検証目的で利用できますが、デスクトップ版ベータの互換性保証には含まれません

## v3 を開発した理由

Wails v2 により、最新の Web フロントエンドを備えた Go アプリケーションを簡単に構築できるようになりました。プロジェクト自体にも、非常に多くのアプリケーションにも十分に貢献してきました。しかし、単一ウィンドウを前提とするコンテキスト駆動型のランタイムと、厳格に管理されたビルドプロセスのため、一般的なデスクトップ開発の一部が本来より難しくなっていました。

v3 は異なるモデルを出発点としています。アプリケーション、ウィンドウ、サービス、イベント、プラットフォーム機能は、いずれも明示的なオブジェクトです。そのため、アプリケーションが成長してもフレームワークを理解しやすく、複数ウィンドウなどの機能も回避策ではなく、アプリケーションモデルの通常の一部として扱えます。

## 新機能

### 本格的なデスクトップソフトウェアのためのアプリケーション API

v3 では、v2 `wails.Run(...)` の設定方式を、明示的なアプリケーションライフサイクルに置き換えています。アプリケーションを作成し、サービスを登録し、ウィンドウを作成したうえで、必要な動作を所有するオブジェクトを直接操作します。

これにより、暗黙的なコンテキストの受け渡しが大幅に減ります。ウィンドウ操作はウィンドウに属し、アプリケーション全体の操作はアプリケーションに属します。マルチウィンドウアプリケーションにとってより自然なモデルであり、大規模なコードベースのテストや保守にも適しています。

アルファ期間中に v3 を使用した方々からは、圧倒的に好意的なフィードバックが寄せられています。特に明示的なモデルは開発者から高く評価されています。コードの流れを追いやすくし、所有関係を明確にするとともに、複雑なデスクトップアプリケーションがフレームワークに阻まれることなく成長できる余地をもたらします。

### ファーストクラスのマルチウィンドウ対応

複数ウィンドウは v3 の中核機能です。各ウィンドウは独自のライフサイクルを持ち、実行時に作成、管理、終了できます。これにより、エディター、インスペクター、環境設定、ツールウィンドウ、または複数の独立した UI を必要とするデスクトップソフトウェアを、より明確な方法で構築できます。

### サービスと生成バインディング

従来のバインディングモデルは Go サービスに置き換わります。アプリケーションロジックを通常の Go コードとして維持しながら、フロントエンドとの境界を明示できます。バインディングはアプリケーションとそのサービスを反映する構造で生成されるため、フロントエンドに公開された API を見つけて利用しやすくなります。

v3 は、静的ソース解析を使用してこれらのバインディングを生成します。つまり、リフレクションによってビルド済みプログラムを調べるのではなく、コメントや意味のあるパラメーター名など、開発者がコードに記述した情報をジェネレーターが保持できます。その結果、フロントエンド API はより充実して有用になり、生成プロセスも理解しやすく保守しやすくなります。

サービスでは、Go コードとともにフロントエンドのアセットやスクリプトをマウントすることもできます。これにより、ある機能に必要なバックエンド API、JavaScript や UI、ホストアプリケーションとの統合ポイントを、一貫した単一の場所にまとめられます。バインディングとフロントエンド依存関係を自分で寄せ集める代わりに、プラグインをインストールしてサービスをマウントするだけで、その機能を利用できる、すぐに高機能を提供する Wails プラグインへの道が開かれます。汎用プラグインシステムはこのベータには含まれませんが、v2 のバインディングモデルでは実現できなかった形で、v3 はこの方向性を現実的なものにします。

### 確認して適応できるビルドシステム

v3 では、プロジェクトのビルド構造が明示されます。すべてのビルド判断を単一のコマンド内に隠すのではなく、プロジェクトには標準的なレイアウトと Taskfile ベースのビルド設定が用意され、アプリケーションと並行して理解、拡張、デバッグできます。

### より強固なクロスプラットフォームデスクトップ基盤

このベータは、amd64 と arm64 上の Windows、Intel と Apple Silicon 上の macOS、および amd64 と arm64 上の Linux をサポートします。WebKitGTK 6.0 を使用する GTK4 が Linux のデフォルトスタックです。GTK3 は v3.0 シリーズ全体を通じて、レガシーオプションとして引き続き利用できます。モバイルサポートは期待の持てる機能ですが、依然として実験段階にあり、デスクトップ版ベータの互換性保証には含まれません。

このリリースには、日常的な開発体験の信頼性を高めるために必要な取り組みも含まれています。プラットフォーム固有の動作の改善、より高機能なウィンドウモデル、より明確な診断、チェックサムと来歴情報を備えたリリースアーティファクトなどです。

## v2 からの移行

v3 は新しいメジャーバージョンであり、移行は単なるバージョン番号の変更ではなく、実際の移植作業です。主な概念上の変更点は、アプリケーションとウィンドウのライフサイクル、コンテキストに結び付いたバインディングに代わるサービス、v2 ランタイムパッケージに代わるアプリケーションおよびウィンドウの直接 API、そして再生成されたフロントエンドバインディングです。

これらの変更を順に説明し、機能対応表とテスト用チェックリストも掲載した [v2 から v3 への移行ガイド](/migration/v2-to-v3/)を公開しています。この手動ガイドが、このベータでサポートされる移行方法です。すべての v2 プロジェクトが確認なしで移行できるとは考えないでください。結果をテストし、ランタイム呼び出しを意図的に移植し、新しいアプリケーションの準備が整うまでは v2 を維持してください。

実験的な移行アシスタントについても評価を進めています。これは今回のベータリリースには含まれておらず、実際の代表的な v2 プロジェクトで検証された後にのみ推奨する予定です。

## これまでの歩みに関する率直な説明

最初の v3 アルファタグは、18 年 2023 月に公開されました。アルファ期間としては長く、曖昧な言葉で済ませずに説明すべきことです。

その間、プロジェクトは大きく変化しました。Windows 向けの最初の Wails v2 ベータが 2021 年 9 月に公開された時点で、リポジトリのスター数はおよそ 4000 でした。2022 年 9 月の v2 リリース時には、およそ 10300 に達していました。現在では 35000 を超えています。この成長は光栄なことですが、同時に、適切なプロジェクト運営のあり方も変わります。リリースに関する決定に依存するユーザーが増え、参加するための明確な道筋を必要とするコントリビューターも増えました。そして作業の多くは、単に次の機能を追加することではなく、プロジェクトの予測可能性を高めることに関わるようになっています。

この成長に伴って必要とされたほど迅速かつ明確に、私が常にプロセスを適応できていたわけではありません。その責任は私にあります。大げさな約束をしたり、あらゆる決定を形式的な手続きにしたりすることが答えではありません。何がサポート対象で、何が実験的なのか、どのように意思決定を行うのか、そして次に何をするのかを、より明確にすることが答えです。

その取り組みは、このベータ版から始まります。現在は、ベータ版、リリース候補版、GA の各マイルストーン、より明確な互換性に関する方針、更新されたセキュリティポリシー、公開動作の変更や新機能のための WEP（Wails Enhancement Proposal）プロセスを整備しています。Wails の成長に合わせて、今後もロードマップを改善し、プロジェクトのガバナンスを見直していきます。目指すのは、動きにくいプロジェクトではなく、安心して利用でき、貢献しやすいプロジェクトです。

また、[Wails subreddit](https://www.reddit.com/r/wails/) を再始動し、v3 の一般提供に向けて、実践的な議論、質問、フィードバックのためのもう一つの場として積極的に運営していきます。

## ベータ版をインストールして試す

リリースの公開後、次のコマンドで最新の v3 CLI をインストールします。

```sh
go install github.com/wailsapp/wails/v3/cmd/wails3@latest
```

プロジェクトを作成する前に、対話型セットアップウィザードを実行してください。ローカルの開発環境を確認し、Wails に必要な依存関係の設定を支援します。

```sh
wails3 setup
```

![ダークモードで表示した Wails v3 セットアップウィザード](/assets/screenshots/wails3-setup-wizard-dark.png)

### プロジェクトを作成する

準備が整ったら、次のコマンドでプロジェクトを作成します。

```sh
wails3 init
```

再現可能なバグを見つけた場合は、`wails3 doctor` の出力と、可能であれば最小限の再現例を添えて報告してください。新機能や公開動作の変更を提案する場合は、機能リクエストの Issue ではなく、WEP のドラフト PR を作成してください。どちらの方法も、私たちが明確に対応し、ベータ版の開発を進めるうえで役立ちます。
