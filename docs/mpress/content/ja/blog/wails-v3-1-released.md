今週の Wails には、CGO フリービルド、より簡単なプロジェクト設定、パッケージ化と署名に伴う手間の軽減など、多くの進展がありました。

Wails v3.1.0 から毎週の機能リリースを開始し、新機能を定期的にお届けします。バグ修正は、準備が整い次第、引き続き nightly パッチアップデートとして提供します。

## 今週の修正と最適化

今週は、フレームワーク、CLI、ビルドツール、CI 全体で、**100 件の修正、21 件のパフォーマンス改善、4 件のセキュリティ強化**を行いました。主な変更には、混在 DPI 環境でのウィンドウ配置の信頼性向上、Linux のトレイとダークモードに関する修正、アセット配信の軽量化、MSIX パッケージ化時のメモリ使用量削減があります。[以下で変更点の一部をご覧ください](#heading-4)。

## 実験的な CGO フリービルド

purego を使うと、Go から C コードを呼び出す通常の橋渡しである CGo を使わずに、ネイティブシステムライブラリを呼び出せます。登場当初から検討を始めていましたが、2 つのバックエンドを保守するのは困難でした。purego が成熟し、生成 AI によってその保守が管理しやすくなったため、実験的な macOS および Linux バックエンドを公開できる段階になりました。

C コンパイラを使わずに、デスクトップアプリをビルドおよびクロスコンパイルできるようになりました。

```sh
WAILS_PUREGO=1 wails3 build
```

フロントエンドのアセットをビルドした後は、Go で直接ビルドすることもできます。

```sh
CGO_ENABLED=0 go build -tags purego,production .
```

macOS バックエンドは AppKit と WebKit を使用します。Linux は GTK4/WebKitGTK 6.0 および GTK3 をサポートします。ユーザー側には引き続きネイティブランタイムライブラリが必要であり、パッケージ化と署名にはそれぞれ別の要件があります。フィードバックを収集している間、CGo が引き続きデフォルトです。

[実装とプラットフォームの詳細](https://github.com/wailsapp/wails/pull/6521)

## なぜ Wake なのか？

Wails v2 では、ビルドプロセスの多くが隠蔽されていました。v3 では Taskfile によってすべてが公開されましたが、多くのユーザーが求めているのは、ビルドシステムを保守せずにいくつかのカスタマイズを行うことです。

Wake では、アプリケーション、付属 CLI ツール、サーバー、ターゲット、パッケージ化といった一般的な選択肢を `wails.yaml` にまとめています。Task は引き続き中核となるビルドシステムであり、その柔軟性が必要な場合に利用できます。

Wake は、ライブリロード、インクリメンタルビルド、出力のキャッシュ、並列パッケージ化に対応しました。バイナリがすでにある場合は、Go やフロントエンドツールをインストールしなくても `--skip-build` でパッケージ化できます。

`WAILS_EXP_USE_WAKE=1` で有効にします。

### 自分のマシンから何をビルドできるか？

コンパイル、パッケージ化、署名にはそれぞれ異なる要件があります。各ホストで実行できる操作は次のとおりです。

@table{header search sort column-separators align=["left", "centre", "centre", "centre", "left"]}
| 操作 | Windows ホスト | macOS ホスト | Linux ホスト | 必要なもの |
| purego でデスクトップアプリをコンパイル | ✓ | ✓ | ✓ | Go、および macOS/Linux ターゲット向けの実験的な purego バックエンド |
| MSIX パッケージを作成 | ✓ | ✓ | ✓ | ビルド済みアプリケーション。Windows SDK は不要 |
| NSIS インストーラーを作成 | ✓ | ✓ | ✓ | ビルド済みアプリケーションと `makensis` |
| macOS アプリと DMG を作成 | ✓ | ✓ | ✓ | ビルド済みアプリケーション。パッケージ作成は Go が処理 |
| DEB、RPM、Arch、Void パッケージを作成 | ✓ | ✓ | ✓ | ビルド済みアプリケーション |
| AppImage を作成 | ✓ | ✓ | ✓ | ターゲットの AppImage ランタイム。クロスパッケージ化には Linux GUI ランタイムツリーも必要 |
| エクスポートした ID で Windows パッケージに署名 | ✓ | ✓ | ✓ | エクスポートした RSA PFX 証明書と秘密鍵 |
| エクスポートした ID で Apple アプリと DMG に署名 | ✓ | ✓ | ✓ | エクスポートした RSA PKCS#12 ID。以下の検証に関する注記を参照 |
| DEB、RPM、Arch パッケージに署名 | ✓ | ✓ | ✓ | エクスポートした OpenPGP 鍵 |
| Apple の公証に提出してチケットを添付 | ✓ | ✓ | ✓ | Apple チーム API キーと、適切に署名されたアプリケーション |
| Apple の `codesign` またはキーチェーンプロファイルを使用 | – | ✓ | – | macOS と適切な署名 ID |
@end

CGo ビルドには引き続き C ツールチェーンが必要です。DMG を変更するカスタムフックには、macOS と `hdiutil` が必要です。

### 署名と公証

Wake は、Apple のアドホック署名を含む、Windows、Apple、Linux パッケージへの署名をサポートします。クロスプラットフォーム署名ではエクスポートした ID を使用します。証明書ストアとキーチェーンの ID には、引き続きネイティブツールが必要です。ユーザーレベルの認証情報を使用することで、秘密鍵をプロジェクト設定に含めずに済みます。AppImage と Void の署名には、まだ対応していません。

Apple の公証は、チーム API キーを使って Go から実行できます。Linux からの提出とチケット添付をテストし、Gatekeeper がその結果を受け入れることを確認しました。そのアプリは Apple の [`codesign`](https://developer.apple.com/library/archive/documentation/Security/Conceptual/CodeSigningGuide/Procedures/Procedures.html) を使って署名しました。Wake が Go で生成する Developer ID 署名を Apple が受け入れるかどうかは、まだ検証されていません。

### Wake への移行

移行は、組み込みの 9 つのテンプレートすべてに対応しています。移行は一方向です。`wails.yaml` を有効にすると、Taskfile のルーティングが置き換えられます。サポートされていないカスタムコマンドとオーバーライドは拒否され、確認が求められます。

[Wake の機能、要件、移行の詳細](https://github.com/wailsapp/wails/pull/6531)

## 今週の主な変更点

- **混在 DPI ディスプレイでも、ウィンドウが適切な位置に表示されるようになりました。** ディスプレイごとに表示倍率が異なる macOS および Linux 環境で、画面の境界と位置が正しく処理されるようになりました。[#6346](https://github.com/wailsapp/wails/pull/6346)
- **Linux のトレイとテーマ検出の信頼性が向上しました。** アプリの起動後に作成したトレイが破棄されなくなり、ツールチップが設定されるようになりました。また、ダークモード検出では、起動時からデスクトップの外観設定を読み取ります。
- **Go のイベントコールバックは、リスナーごとの順序を維持します。** 各リスナーは emit の順序どおりに逐次実行されます。異なるリスナーは同時に実行でき、同時に行われた emit の順序は定義されていません。データ競合を回避するため、イベントフックはロック下でスナップショット化されます。 [#6275](https://github.com/wailsapp/wails/pull/6275)、[#6276](https://github.com/wailsapp/wails/pull/6276)
- **ビルドキャッシュが、より多くの実際のプロジェクトに対応しました。** 引用符で囲まれた、またはエスケープされたスペースによって Go 出力のキャッシュミスが発生しなくなりました。また、ファイルの破損を防ぐため、同時に行われるキャッシュ保存を直列化しました。[#6495](https://github.com/wailsapp/wails/pull/6495)、[#6488](https://github.com/wailsapp/wails/pull/6488)
- **アセット配信で不要な処理を削減しました。** 既知のファイル拡張子では MIME スニッフィングを省略し、デバッグログが無効な場合は破棄されるメッセージを準備しなくなりました。どちらの変更も、リクエスト処理経路の作業量を削減します。[#6414](https://github.com/wailsapp/wails/pull/6414)、[#6420](https://github.com/wailsapp/wails/pull/6420)
- **MSIX パッケージ化で、バイナリと同じサイズのバッファを使用しないようになりました。** 実行可能ファイル全体をメモリに読み込む代わりに、パッケージへストリーミングします。代表的な 16 MiB のコピーでは、以前は処理ごとに約 16.8 MB が割り当てられていました。[#6472](https://github.com/wailsapp/wails/pull/6472)
