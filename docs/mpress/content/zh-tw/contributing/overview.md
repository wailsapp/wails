## 歡迎閱讀 Wails v3技術文件

本節**並非**介紹社群準則或如何建立提取要求，而是深入說明**Wails v3的建構方式**，讓你能快速熟悉程式碼庫，並有信心地開始修改程式碼。

無論你打算修補執行階段、擴充 CLI、製作新範本，還是只想瞭解內部機制，後續頁面都會提供所需的技術背景。

---

## 高階架構

@cards{cols="2"}
◇ Go 後端
每個 Wails 應用程式的核心，都是編譯成原生可執行檔的 Go 程式碼。它負責應用程式邏輯、系統整合及效能關鍵作業。

---
▤ Web 前端
UI 使用標準 Web 技術（React、Vue、Svelte、原生 JavaScript 等）撰寫，並由輕量的系統 WebView 呈現（Linux/macOS 使用 WebKit，Windows 使用 WebView2）。

---
◆ 橋接層
零複製的記憶體內橋接層可進行**Go⇄JavaScript**呼叫，並自動處理型別轉換、事件傳播及錯誤轉送。

---
▸ CLI 與工具
`wails3`負責協調專案建立、支援即時重新載入的開發伺服器、資產封裝、交叉編譯及套件製作（deb、rpm、AppImage、msi、dmg 等）。

@end

## 架構概覽

**Wails v3– 端對端流程**

**[端對端流程圖預留位置]**

此圖呈現以下**端對端流程**：

1. **CLI**負責驅動程式碼產生、開發伺服器、編譯及套件製作。\
2. **繫結系統**會產生黏合程式碼，讓**Web 前端**能夠呼叫**Go 後端**。\
3. 在開發期間，**資產伺服器**會將要求代理至框架的開發伺服器；在正式環境中，則提供嵌入的檔案。\
4. 在執行階段，**桌面執行階段**負責管理視窗與作業系統 API，而**橋接層**則在 Go 與 JavaScript 之間傳遞訊息。

## 本文件涵蓋的內容

| 主題 | 重要性 |
| --- | --- |
| **程式碼庫配置** | `/v3`目錄配置及模組互動方式。 |
