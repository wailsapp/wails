今天，我們正式發布 Wails v3 Beta。

Wails 讓 Go 開發者能使用已經熟悉的 Web 前端工具建置桌面應用程式，並使用各平台的原生 WebView，而非嵌入式瀏覽器。v3 是一次重大進展：它為應用程式提供更直接的 API、更清晰的建置模型，以及更完善的基礎，藉此支援大家一直期待 Wails 能夠支援的桌面應用程式。

這是 Beta 版本，並非最終的 3.0 版本。桌面 API 已經穩定，也已有團隊在正式環境中使用 v3，但您仍應在部署前進行完整測試。我們會在 Beta 期間與社群共同找出最後的相容性與工作流程問題。Wails v2 仍是目前的穩定版本，並會持續獲得修正。

## Beta 期間的文件

Beta 期間，在 API 與工作流程接受最終驗證之際，我們會將英文文件維護為唯一的權威來源。現階段不接受翻譯 PR。文件穩定到足以避免譯者反覆修改後，我們會在正式發布前恢復翻譯工作。

## v3 包含哪些內容

- 明確的應用程式與視窗 API，包括原生支援多視窗
- 搭配靜態原始碼分析的 Go 服務，可產生更豐富的 TypeScript 繫結，並保留註解及有意義的參數名稱
- 可將前端資產與指令碼連同後端 API 一併封裝的服務，為可安裝且功能更豐富的外掛奠定基礎
- 採用 Taskfile、清楚可見且能夠檢查、擴充及偵錯的建置系統
- 伺服器建置，可在沒有原生桌面視窗的情況下執行相同的應用程式與服務
- 在支援的情況下，為 Intel、Apple Silicon、amd64 及 arm64 上的 macOS、Windows 與 Linux 提供現代化桌面支援
- 供探索使用的 iOS 與 Android 實驗性行動裝置支援，但不在桌面版 Beta 的相容性承諾範圍內

## 為何推出 v3

Wails v2 讓使用現代 Web 前端建置 Go 應用程式變得簡單直接。它一直很好地服務這個專案，以及為數眾多的應用程式。然而，其單視窗、由情境驅動的執行階段，以及受到嚴格管控的建置流程，卻讓一些常見的桌面開發工作變得比應有的更困難。

v3 採用不同的模型。應用程式、視窗、服務、事件及平台功能都是明確的物件。這讓應用程式成長時更容易理解框架，也讓多視窗等功能成為應用程式模型的正常組成部分，而非權宜之計。

## 新增功能

### 為真正的桌面軟體打造的應用程式 API

v3 以明確的應用程式生命週期，取代 v2 的 `wails.Run(...)` 設定方式。您可以建立應用程式、註冊服務、建立視窗，並與負責所需行為的物件互動。

這移除了大量隱含的情境傳遞。視窗操作歸屬於視窗；涵蓋整個應用程式的操作則歸屬於應用程式。這是更符合多視窗應用程式需求的自然模型，也更適合測試及維護較大型的程式碼庫。

在 Alpha 期間使用過 v3 的使用者給予了極為正面的回饋。開發者尤其認同明確的模型：它讓程式碼更容易理解、權責歸屬更清楚，也讓複雜的桌面應用程式能在不受框架掣肘的情況下持續成長。

### 原生支援多視窗

多視窗是 v3 的核心功能。視窗擁有各自的生命週期，並可在執行階段建立、管理及關閉。因此，需要編輯器、檢查器、偏好設定、工具視窗或數個獨立 UI 區塊的桌面軟體，現在有了更清晰的實作途徑。

### 服務與產生的繫結

Go 服務取代了舊有的繫結模型。它們將應用程式邏輯保留為一般 Go 程式碼，並明確界定與前端之間的邊界。產生的繫結會採用反映應用程式及其服務的結構，讓開發者更容易找到並使用公開給前端的 API。

v3 使用靜態原始碼分析產生這些繫結。這表示產生器可以保留開發者寫入程式碼的資訊，包括註解及有意義的參數名稱，而不是透過反射探索已經建置完成的程式。如此便能提供更豐富、更實用的前端 API，以及更容易理解及維護的產生流程。

服務也能將前端資產與指令碼掛載在其 Go 程式碼旁。如此便能將一項功能完整集中於同一處：其後端 API、所需的 JavaScript 或 UI，以及與主應用程式整合的接點。這為開箱即用、可提供豐富功能的 Wails 外掛開啟了大門：安裝外掛、掛載其服務，接著便可使用功能，而不必自行組合零散的繫結與前端相依項目。通用外掛系統不在這次 Beta 的範圍內，但 v3 讓這個方向變得切實可行，這是 v2 繫結模型無法做到的。

### 可檢查及調整的建置系統

v3 讓專案的建置結構清楚可見。它不再將所有建置決策隱藏於單一命令中；專案改為採用慣用的版面配置及以 Taskfile 為基礎的建置設定，讓您能與應用程式一起理解、擴充及偵錯。

### 更穩固的跨平台桌面基礎

此 Beta 支援 amd64 與 arm64 上的 Windows、Intel 與 Apple Silicon 上的 macOS，以及 amd64 與 arm64 上的 Linux。搭配 WebKitGTK 6.0 的 GTK4 是預設 Linux 技術堆疊；在整個 v3.0 系列中，GTK3 仍可作為舊版選項使用。行動裝置支援令人期待，但仍處於實驗階段，不在桌面版 Beta 的相容性承諾範圍內。

此版本也納入了提升日常使用可靠性所需的工作：改善平台行為、提供功能更完整的視窗模型與更清晰的診斷資訊，以及附帶總和檢查碼與來源證明的發布成品。

## 從 v2 移轉

v3 是新的主要版本，因此移轉是一次真正的移植，而不只是變更版本號碼。主要的概念轉變包括應用程式與視窗的生命週期、以服務取代情境繫結、以直接的應用程式與視窗 API 取代 v2 執行階段套件，以及重新產生前端繫結。

我們已發布[從 v2 移轉至 v3 的指南](/migration/v2-to-v3/)，其中會逐步說明這些變更，並包含功能對照表與測試檢查清單。這份手動指南是此 Beta 支援的移轉途徑。請勿預期每個 v2 專案都能在未經審查的情況下完成轉換：請測試轉換結果、審慎移植執行階段呼叫，並在新應用程式準備就緒前保留 v2。

我們也正在評估實驗性的移轉輔助工具。它不屬於這次 Beta 版本；只有在經過具代表性的實際 v2 專案驗證後，我們才會建議使用。

## 坦誠談談這段歷程

第一個 v3 Alpha 標籤發布於 18 年 2023 月。Alpha 階段持續如此之久，不能只用含糊其辭的方式一筆帶過。

這段期間，專案發生了極大的變化。第一個適用於 Windows 的 Wails v2 Beta 於 2021 年 9 月推出時，儲存庫約有 4000 顆星。到了 2022 年 9 月發布 v2 時，已增至約 10300 顆。如今更已超過 35000 顆。能有這樣的成長是一種殊榮，但也改變了妥善維護專案所應有的方式：更多使用者仰賴發布決策，更多貢獻者需要明確的參與途徑，而更多工作也轉向確保專案可預期地發展，而不只是加入下一項功能。

我並未總是以這項成長所要求的速度和清晰度調整我們的流程。這是我的責任。答案不是許下宏大的承諾，也不是讓每個決策都流於繁文縟節；而是更清楚地說明哪些內容受支援、哪些仍屬實驗性質、決策如何制定，以及我們接下來要做什麼。

這項工作從此次 Beta 版開始。我們現在已明確訂立 Beta 版、候選發布版和正式發布（GA）的里程碑，提出更清楚的相容性承諾，更新安全性政策，並建立 WEP（Wails Enhancement Proposal，Wails 改進提案）流程，用於處理公開行為的變更與新功能。隨著 Wails 成長，我們會持續完善發展藍圖並檢視專案治理。目標是讓專案更值得信賴、更容易參與貢獻，而不是讓它更難向前推進。

我們也將重新啟動[Wails subreddit](https://www.reddit.com/r/wails/)，並積極維護這個空間，讓大家在v3邁向正式發布期間，能在此進行實務討論、提問及提供意見回饋。

## 安裝並試用 Beta 版

版本發布後，請使用以下命令安裝最新版v3 CLI：

```sh
go install github.com/wailsapp/wails/v3/cmd/wails3@latest
```

建立專案前，請執行引導式設定精靈。它會檢查您的本機開發環境，並協助設定 Wails 所需的相依套件：

```sh
wails3 setup
```

![深色模式下的 Wails v3設定精靈](/assets/screenshots/wails3-setup-wizard-dark.png)

### 建立專案

一切準備就緒後，請使用以下命令建立專案：

```sh
wails3 init
```
