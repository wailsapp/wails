## 목적

이슈에는 재현 가능한 버그와 문서 문제를 기록합니다. WEP(Wails 개선 제안) 풀 리퀘스트에는 제안된 기능이나 공개 동작의 변경 사항을 기록합니다.

## 이슈 분류

- 버그 보고서에 릴리스된 버전, 플랫폼, 재현 단계, 예상 동작, 실제 동작 및 `wails3 doctor` 출력이 포함되어 있는지 확인합니다.
- 확인된 보고서에 `Bug` 레이블을 지정하고 관련 버전 및 플랫폼 레이블을 적용합니다. 필요한 경우 최소 재현 예제를 요청합니다.
- 구체적인 문서 결함을 지적하는 문서 문제 보고는 열린 상태로 유지합니다. 보고자가 직접 변경할 수 있다면 PR 제출을 권장합니다.
- 기능 요청을 WEP 가이드로 안내한 다음 닫습니다. 자동 리디렉션 워크플로는 새로 enhancement 레이블이 지정된 이슈를 처리합니다. 이전 이슈에도 같은 문구를 사용합니다.
- 질문과 지원 요청은 GitHub Discussions 또는 Discord로 안내합니다.

## WEP 분류

1. PR이 제목이 `[WEP] <title>`인 초안이며 WEP와 지원 자료만 포함하는지 확인합니다.
2. WEP 템플릿을 사용하고 구현 담당자를 명시했으며 호환성, 플랫폼, 테스트, 유지관리 및 보안/개인정보 보호를 다루는지 확인합니다.
3. 기술 논의는 WEP PR에서 진행합니다. Discussions는 유용한 참고 자료이지만 의사 결정 기록은 아닙니다.
4. 유지관리자의 결정을 간단한 근거와 함께 PR 댓글에 기록합니다. 결정 상태는 승인, 거부 또는 철회 중 하나입니다.
5. 승인된 WEP에는 번호를 할당하고 WEP 색인을 업데이트한 후 WEP PR을 병합합니다. 구현 PR에는 해당 WEP로 연결되는 링크를 반드시 포함하도록 합니다.

## 기존 개선 이슈

과거의 개선 이슈를 알리지 않고 삭제하지 마세요. 여전히 유효한 각 요청에는 리디렉션 댓글을 남기고 이슈를 닫습니다. 관심 있는 기여자는 WEP를 열 수 있습니다. 중복 이슈는 기존 WEP 또는 결정으로 연결되는 링크를 남기고 닫습니다.
