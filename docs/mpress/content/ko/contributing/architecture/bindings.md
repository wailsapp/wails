이 가이드에서는 Wails 바인딩 시스템의 내부 작동 방식을 설명하여 자동 코드 생성의 이면에 있는 메커니즘을 이해하려는 개발자에게 필요한 정보를 제공합니다.

## 아키텍처 개요

Wails 바인딩 시스템은 세 가지 주요 구성 요소로 이루어집니다.

1. **수집**: Go 코드를 분석하여 서비스, 모델 및 기타 선언에 관한 정보를 추출합니다.
2. **구성**: 바인딩 생성 과정의 설정과 옵션을 관리합니다.
3. **렌더링**: 수집한 정보를 바탕으로 JavaScript/TypeScript 코드를 생성합니다.

@filetree
- internal/generator/
  - collect/     # 패키지 분석 및 정보 추출
  - config/      # 구성 구조체 및 인터페이스
  - render/      # JS/TS 코드 생성
@end

## 수집 과정

수집 과정은 Go 패키지를 분석하고 서비스, 모델 및 기타 선언에 관한 정보를 추출합니다. 이 작업은 `collect` 패키지가 처리합니다.

### 주요 구성 요소

- **Collector**: 패키지 정보를 관리하고 수집한 데이터를 캐시합니다.
- **Package**: 분석 중인 Go 패키지를 나타내며 수집한 서비스, 모델 및 지시문을 저장합니다.
- **Service**: 서비스 타입과 해당 메서드에 관한 정보를 수집합니다.
- **Model**: 필드, 값 및 타입 매개변수를 비롯한 모델 타입의 상세 정보를 수집합니다.
- **Directive**: Go 소스 코드의 `//wails:` 지시문을 구문 분석하고 해석합니다.

### 수집 흐름

1. 수집기는 프로젝트에 지정된 Go 패키지를 스캔합니다.
2. 서비스 타입(프런트엔드에 노출될 메서드가 있는 구조체)을 식별합니다.
3. 각 서비스에 대해 해당 메서드의 정보를 수집합니다.
4. 모델 타입(서비스 메서드에서 매개변수나 반환값으로 사용하는 구조체)을 식별합니다.
5. 각 모델에 대해 해당 필드와 타입 매개변수의 정보를 수집합니다.
6. 코드에서 발견된 모든 `//wails:` 지시문을 처리합니다.

## 렌더링 과정

렌더링 과정은 수집한 정보를 바탕으로 JavaScript/TypeScript 코드를 생성합니다. 이 작업은 `render` 패키지가 처리합니다.

### 주요 구성 요소

- **Renderer**: 서비스, 모델 및 인덱스 파일의 렌더링을 조율합니다.
- **Module**: 생성된 단일 JavaScript/TypeScript 모듈을 나타냅니다.
- **Templates**: 코드 생성에 사용하는 텍스트 템플릿입니다.

### 렌더링 흐름

1. 렌더러는 각 서비스에 대해 서비스 메서드에 대응하는 함수가 포함된 JavaScript/TypeScript 파일을 생성합니다.
2. 렌더러는 각 모델에 대해 모델 구조체에 대응하는 JavaScript/TypeScript 클래스를 생성합니다.
3. 렌더러는 모든 서비스와 모델을 다시 내보내는 인덱스 파일을 생성합니다.
4. 렌더러는 `//wails:inject` 지시문에 지정된 모든 사용자 정의 코드 삽입을 적용합니다.

## 타입 매핑

바인딩 시스템에서 가장 중요한 측면 중 하나는 Go 타입을 JavaScript/TypeScript 타입에 매핑하는 방식입니다. 매핑은 다음과 같습니다.

| Go 타입 | JavaScript 타입 | TypeScript 타입 |
| --- | --- | --- |
| `bool` | `boolean` | `boolean` |
| `int`, `int8`, `int16`, `int32`, `int64`, `uint`, `uint8`, `uint16`, `uint32`, `uint64`, `float32`, `float64` | `number` | `number` |
| `string` | `string` | `string` |
| `[]byte` | `Uint8Array` | `Uint8Array` |
| `[]T` | `Array<T>` | `T[]` |
| `map[string]V` | `Object` | `{ [_: string]: V }` |
| `map[K]V`(문자열이 아닌 `K`) | `Object` | `{ [_ in K]?: V }` |
| `struct` | `Object` | 사용자 정의 클래스 |
| `interface{}` | `any` | `any` |
| `*T` | `T \| null` | `T \| null` |
| `func` | 지원되지 않음 | 지원되지 않음 |
| `chan` | 지원되지 않음 | 지원되지 않음 |

## 지시문 시스템

바인딩 시스템은 생성되는 코드를 사용자 정의할 수 있는 여러 지시문을 지원합니다. 이러한 지시문은 Go 코드에 주석으로 추가합니다.

### 사용 가능한 지시문

- `//wails:inject`: 사용자 정의 JavaScript/TypeScript 코드를 생성된 바인딩에 삽입합니다.
- `//wails:include`: 생성된 바인딩에 추가 파일을 포함합니다.
- `//wails:internal`: 생성된 SDK에서 내보내기를 억제하지만, 내보낸 Go 메서드가 런타임에 호출되는 것을 막지는 않습니다.
- `//wails:ignore`: 바인딩을 생성할 때 메서드를 완전히 무시합니다.
- `//wails:id`: 기본 해시 기반 ID를 재정의하여 메서드의 사용자 정의 ID를 지정합니다.

이러한 지시문은 생성되는 코드를 제어합니다. 일반 빌드에서도 런타임 등록에는 내보낸 서비스 메서드가 계속 반영됩니다. 비공개 작업에는 내보내지 않은 메서드나 바인딩되지 않은 타입을 사용하고, 노출된 메서드에서 권한 부여를 적용하세요.

### 지시문 처리

1. 수집 단계에서 수집기는 Go 코드의 지시문을 식별하고 구문 분석합니다.
2. 지시문은 해당 선언(서비스, 메서드, 모델 등)과 함께 저장됩니다.
3. 렌더링 단계에서 렌더러는 지시문을 적용하여 생성되는 코드를 사용자 지정합니다.

## 고급 기능

### 조건부 코드 생성

바인딩 시스템은 `include` 및 `inject` 지시문에 두 문자로 된 조건 접두사를 사용하여 조건부 코드 생성을 지원합니다.

```
<language><style>:<content>
```

각 문자의 의미는 다음과 같습니다.

- `<language>`에는 다음 값을 사용할 수 있습니다.
  - `*` - JavaScript와 TypeScript 모두
  - `j` - JavaScript만
  - `t` - TypeScript만


- `<style>`에는 다음 값을 사용할 수 있습니다.
  - `*` - 클래스와 인터페이스 모두
  - `c` - 클래스만
  - `i` - 인터페이스만


예:

```go
//wails:inject j*:console.log("JavaScript only");
//wails:inject t*:console.log("TypeScript only");
```

### 사용자 지정 메서드 ID

기본적으로 메서드는 해시 기반 ID로 식별됩니다. 그러나 `//wails:id` 지시문을 사용하여 사용자 지정 ID를 지정할 수 있습니다.

```go
//wails:id 42
func (s *Service) CustomIDMethod() {}
```

이는 코드를 리팩터링할 때 호환성을 유지하는 데 유용할 수 있습니다.

## 성능 고려 사항

바인딩 생성기는 효율적으로 작동하도록 설계되었지만, 몇 가지 유의할 사항이 있습니다.

1. 첫 실행에서는 스캔할 패키지의 캐시를 구축하므로 시간이 더 오래 걸립니다.
2. 이후 실행에서는 캐시된 정보를 사용하므로 더 빠릅니다.
3. 생성기는 프로젝트의 모든 패키지를 처리하므로 대규모 프로젝트에서는 시간이 오래 걸릴 수 있습니다.
4. `-clean` 플래그를 사용하면 생성 전에 출력 디렉터리를 정리할 수 있습니다.

## 디버깅

바인딩 생성 중 문제가 발생하면 `-v` 플래그를 사용하여 디버그 출력을 활성화할 수 있습니다.

```bash
wails3 generate bindings -v
```

그러면 수집 및 렌더링 과정에 관한 자세한 정보가 제공되어 문제의 원인을 파악하는 데 도움이 될 수 있습니다.
