Wails는 <strong>Go의 성능과 단순성</strong>을 <strong>최신 웹 UI의 유연성</strong>과 결합하여, 이미 익숙한 도구로 아름다운 네이티브 데스크톱 애플리케이션을 만들 수 있게 해줍니다.

## 사용자가 체감하는 성능

**Wails 애플리케이션:**

- **약 15MB의 바이너리**(Electron은 150MB)
- **약 10MB의 기본 메모리 사용량**(Electron은 100MB 이상)
- **&lt;0.5초의 시작 시간**(Electron은 2-3초)
- OS에서 제공하는 WebView를 사용한 **네이티브 렌더링**

사용자는 애플리케이션이 빠르고 가벼우며 전문적이라고 느낍니다.

## 개발자 경험

**한 번 작성하여 어디서나 실행:**

- Windows, macOS, Linux에서 사용하는 단일 Go 코드베이스
- 모든 웹 프레임워크 사용 가능(React, Vue, Svelte, 바닐라 JS)
- 개발 중 핫 리로드
- Go 코드에서 TypeScript 바인딩 자동 생성

유지 관리할 코드를 줄이고 더 빠르게 출시하세요.

## 프로덕션에 바로 사용할 수 있는 기능

**필요한 모든 기능:**

- 각각 독립적인 수명 주기를 갖는 여러 창
- 네이티브 메뉴(애플리케이션, 컨텍스트, 시스템 트레이)
- 플랫폼 네이티브 UI를 사용하는 파일 대화 상자
- 시스템 통합(알림, 클립보드, 키보드 단축키)
- 모든 플랫폼을 위한 코드 서명 및 패키징

프로토타입이 아닌 전문적인 애플리케이션을 만드세요.

## 더 빠른 개발

- **하나의 코드베이스로 세 플랫폼 지원** - 한 번 작성하여 Windows, macOS, Linux용으로 빌드하세요
- **기존 기술 활용** - 백엔드에는 Go를, UI에는 HTML/CSS/JS를 사용하세요
- **즉각적인 피드백** - 개발 중 핫 리로드를 지원하며 컴파일 시간은 초 단위입니다
- **작은 바이너리** - 15MB 애플리케이션으로 빌드, 다운로드, 반복 개발이 더 빨라집니다

## Wails를 선택해야 할 때

**Wails가 적합한 분야:**

- **비즈니스 애플리케이션**(CRM, 재고 관리, 대시보드, 관리 도구)
- **개발자 도구**(데이터베이스 클라이언트, API 테스트 도구, 배포 도구)
- **생산성 애플리케이션**(메모 작성, 작업 관리, 시간 추적)
- **크리에이티브 도구**(이미지 편집기, 동영상 처리 도구, 디자인 유틸리티)
- **내부 도구**(회사 전용 애플리케이션, 자동화 도구)

## 실제 성공 사례

- 네이티브 성능을 제공하는 **동영상 편집 도구**
- 엔지니어링 팀에서 사용하는 **개발 유틸리티**

## Wails의 작동 방식

브라우저 전체와 Node.js 런타임을 함께 번들로 제공하는 Electron과 달리, Wails는 근본적으로 다른 방식을 사용합니다. Go 코드는 네이티브 바이너리로 컴파일되고 UI는 운영 체제에 내장된 WebView에서 실행됩니다. 이러한 아키텍처는 작은 바이너리, 빠른 시작, 적은 메모리 사용량을 구현하여 Wails 애플리케이션이 네이티브처럼 느껴지게 합니다.

### 아키텍처

Wails 애플리케이션은 원활하게 통신하는 두 가지 주요 부분으로 구성됩니다. 비즈니스 로직과 시스템 작업을 처리하는 Go 백엔드, 그리고 사용자 인터페이스를 위한 웹 기반 프런트엔드입니다. OS에서 제공하는 WebView가 브라우저를 번들로 포함하지 않고 UI를 렌더링하며, 바인딩 계층은 Go와 JavaScript 간의 타입 안전한 통신을 제공합니다.

</div>

이 간단한 아키텍처에서는 JavaScript 코드가 자동 생성된 바인딩을 통해 Go 함수를 직접 호출할 수 있고, Go는 이벤트와 데이터를 프런트엔드로 다시 보낼 수 있습니다. 두 계층은 오버헤드가 1밀리초 미만인 효율적인 인메모리 브리지를 통해 통신합니다.

**Wails가 성능을 구현하는 방법:**

1. **런타임을 번들로 포함하지 않음** - Go로 컴파일된 바이너리를 사용합니다
2. **네이티브 WebView** - OS에서 제공하는 렌더링 엔진을 사용합니다
3. **Go ↔ JS 직접 브리지** - 인메모리 통신을 사용하여 네트워크 오버헤드가 없습니다
4. **컴파일된 바이너리** - JIT 컴파일 없이 즉시 시작됩니다
