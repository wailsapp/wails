@note{type="caution" title="Здесь проводятся эксперименты"}
Всё в этом разделе по определению является экспериментальным. Эти возможности включаются по желанию, по умолчанию отключены и могут измениться, получить другое название или быть полностью удалены между выпусками. Не используйте их как основу критически важных решений, если не готовы к частым изменениям.

@end

## Что означает «экспериментальная возможность»

Wails предоставляет эксперименты открыто. Эксперимент — это идея, которую мы считаем достаточно перспективной, чтобы заранее передать вам, но которую пока не готовы окончательно утвердить. Мы публикуем её *потому, что* хотим изучить опыт реального использования, прежде чем решать, станет ли она постоянной и поддерживаемой частью Wails.

Поэтому ко всему в этом разделе применимы следующие положения:

- **Она включается по желанию.** Эксперименты никогда не меняют стандартное поведение `wails3`. Вы включаете их намеренно — обычно с помощью переменной окружения или флага сборки. Пока они отключены, ваш существующий рабочий процесс никак не меняется.
- **Она может не сохраниться.** Некоторые эксперименты становятся стабильными возможностями. Другие перерабатываются до неузнаваемости или прекращаются. Мы предпочитаем открыто пробовать новое и быстро учиться, а не выпускать только то, в чём уже полностью уверены.
- **API ещё не зафиксирован.** Пока эксперимент обретает окончательную форму, названия, флаги, значения по умолчанию и поведение могут меняться между выпусками. Изменения будут отмечены в примечаниях к выпуску, но не следует ожидать гарантий стабильности, предоставляемых стабильным возможностям.

## Нам нужны ваши отзывы

Это самое важное. Судьба экспериментов зависит от отзывов людей, которые действительно ими пользуются. Если вы попробуете один из них, мы искренне хотим узнать:

- Сработал ли он в вашем проекте? Где возникли проблемы?
- Стал ли он быстрее, понятнее или удобнее — или переход того не стоил?
- Что должно измениться, чтобы вы использовали его по умолчанию?

Наиболее полезны конкретные отзывы: что вы запускали, чего ожидали и что произошло в действительности. Для каждого эксперимента есть отдельная тема в категории **Эксперименты** в GitHub Discussions:

## Сборки без CGO (purego)

@note{type="caution" title="Экспериментальная возможность"}
Бэкенд без CGO включается по желанию с помощью тега сборки `purego` (или `WAILS_PUREGO=1`) и **не** используется по умолчанию. Без него сборки для macOS и Linux используют бэкенд cgo точно так же, как прежде. Поведение может меняться между выпусками.

@end

### Что это такое

В macOS и Linux Wails обычно взаимодействует с системными библиотеками пользовательского интерфейса через cgo: с AppKit и WKWebView в macOS, с GTK и WebKitGTK в Linux. Бэкенд без CGO выполняет те же вызовы из чистого Go с помощью [purego](https://github.com/ebitengine/purego), загружая системные библиотеки во время выполнения.

Публичный API приложения не меняется. Выберите бэкенд при сборке; изменять код приложения не требуется. Перед распространением протестируйте приложение в целевой системе.

Преимущества:

- **Для компиляции Go не нужен набор инструментов C.** Для сборки Go не требуются инструменты командной строки Xcode, `gcc` или заголовочные файлы для разработки в Linux. Для сборки фронтенда по-прежнему нужны обычные инструменты JavaScript.
- **Кросс-компиляция без Docker.** Собирайте исполняемый файл для macOS или Linux в любой ОС с помощью обычного `go build`.

Windows уже собирается без cgo, поэтому эти изменения её не затрагивают.

### Перед включением

Используйте версии CLI и фреймворка, которые обе содержат этот эксперимент. Обновление только CLI не добавит бэкенд в более старую зависимость фреймворка, указанную в `go.mod` вашего приложения. Чтобы попробовать версию в разработке, выполните следующие команды из каталога приложения:

```sh
go install github.com/wailsapp/wails/v3/cmd/wails3@master
go get github.com/wailsapp/wails/v3@master
```

Обе команды отслеживают изменяющуюся ветвь `master`. Для воспроизводимых сборок используйте один и тот же проверенный коммит CLI и фреймворка. Инструкции по настройке набора инструментов Go и CLI приведены в [руководстве по установке](/getting-started/installation/).

Экспериментальные бэкенды для macOS и Linux поддерживают `amd64` и `arm64`. Кросс-компиляция создаёт исполняемый файл для указанной целевой платформы, но не запускает его на машине сборки. Протестируйте его в целевой операционной системе и на целевой архитектуре.

### Использование

Выберите один из следующих способов выбора бэкенда.

#### С помощью Wails CLI

В проекте, созданном этой версией CLI, `build`, `package` и `dev` используют экспериментальный бэкенд, когда включена переменная `WAILS_PUREGO`. В POSIX-совместимой оболочке:

```sh
WAILS_PUREGO=1 wails3 dev
WAILS_PUREGO=1 wails3 build
WAILS_PUREGO=1 wails3 package
```

В PowerShell:

```powershell
$env:WAILS_PUREGO = "1"
wails3 build
```

CLI распознаёт `1`, `true`, `on` и `yes` без учёта регистра и окружающих пробелов. Пустое значение не включает этот эксперимент.

Или передайте тег одной команде сборки или упаковки:

```sh
wails3 build -tags purego
wails3 package -tags purego
```

Когда тег задан, обновлённые стандартные Taskfiles выполняют сборку с `CGO_ENABLED=0`, используя набор инструментов Go хост-системы. Например, так можно собрать исполняемый файл Linux ARM64 в macOS или Windows:

```sh
wails3 build -tags purego GOOS=linux ARCH=arm64
```

Старые проекты сохраняют существующие Taskfiles. Сравните собственные задачи сборки с обновлёнными шаблонами или используйте обычный Go, чтобы протестировать бэкенд без изменения этих задач. Переменная окружения выбирает тег в командах Wails CLI; при использовании обычного `go build` тег нужно указывать явно.

#### С помощью обычного Go

Сначала соберите фронтенд, чтобы существовали все ресурсы, на которые ссылается `go:embed`, а затем скомпилируйте приложение:

```sh
CGO_ENABLED=0 go build -tags purego,production .
```

`CGO_ENABLED=1 go build -tags purego` тоже работает: используется тот же бэкенд, а cgo просто остаётся доступен остальной части программы.

Для кросс-сборки также задайте `GOOS` и `GOARCH`:

```sh
GOOS=darwin GOARCH=arm64 CGO_ENABLED=0 go build -tags purego,production -o myapp .
```

В Linux выберите стек GTK3 с помощью `-tags purego,gtk3,production`.

Чтобы вернуться к бэкенду по умолчанию, удалите тег `purego` и сбросьте переменную `WAILS_PUREGO` (с помощью `unset WAILS_PUREGO` в POSIX-совместимой оболочке или `Remove-Item Env:WAILS_PUREGO` в PowerShell). При возврате к бэкенду cgo для macOS или Linux также удалите явно заданную настройку `CGO_ENABLED=0`.

Если выполнить сборку с `CGO_ENABLED=0`, но забыть тег, сборка остановится с одной ошибкой, в которой будет указано, как её исправить:

```
undefined: requires_CGO_ENABLED_1_or_build_tag_purego
```

### Требования среды выполнения

Приложение загружает системные библиотеки при запуске, поэтому они должны быть установлены на целевой машине, как и при сборке с cgo:

| Платформа | Библиотеки | Минимальная поддерживаемая версия |
|---|---|---|
| macOS | AppKit, WebKit (в составе ОС) | То же, что и для бэкенда cgo |
| Linux (по умолчанию) | GTK 4, WebKitGTK 6.0 | GTK 4.8, WebKitGTK 2.40 (Debian 12) |
| Linux (`gtk3`) | GTK 3, WebKit2GTK 4.1 | GTK 3.24, WebKit2GTK 2.36 (Ubuntu 22.04) |

Функции новее этих минимальных версий ищутся при запуске приложения и используются только при их наличии в установленной библиотеке, поэтому один и тот же бинарный файл работает как в старых, так и в новых системах.

Приложение по-прежнему использует нативные библиотеки пользовательского интерфейса и может динамически компоноваться с системными библиотеками, такими как libc в Linux. `CGO_ENABLED=0` не означает полностью статический исполняемый файл. Если необходимая библиотека времени выполнения отсутствует, установите соответствующий стек GTK/WebKit в целевой системе; установка заголовочных файлов C на машине сборки не устраняет отсутствие библиотеки времени выполнения.

### Упаковка и подписание

Этот бэкенд устраняет необходимость в инструментарии C при компиляции. У каждого формата пакета остаются собственные требования. В частности, выбор `purego` не делает существующие средства развёртывания AppImage кроссплатформенными. См. раздел [«Упаковка для Linux»](/guides/build/linux/).

Приложения macOS, собранные посредством кросс-компиляции, перед распространением по-прежнему необходимо надлежащим образом подписать и нотариально заверить. Для установщиков Windows по-прежнему требуются соответствующие средства создания установщиков. См. разделы [«Упаковка для macOS»](/guides/build/macos/) и [«Упаковка для Windows»](/guides/build/windows/). Для зависимостей, использующих cgo, `CGO_ENABLED=1` также требуется компилятор C и все заголовочные файлы или библиотеки для целевой платформы; выбор бэкенда Wails на чистом Go не отменяет требования этих зависимостей.

### Проверка

Проверки сгенерированных привязок и `puregocheck` проверяют нативные символы, защитные проверки для необязательных версий и охват бэкендов. Процесс проверки эквивалентности в Linux тестирует GTK4 и GTK3 с обоими бэкендами, включая запросы ресурсов, двоичные тела запросов и нативную диспетчеризацию; он также выполняет кросс-компиляцию для целевых систем Linux ARM64. Проверки кросс-компиляции подтверждают, что код собирается, а проверки времени выполнения тестируют нативные библиотеки, установленные на тестовой машине.

В [руководстве по тестированию бэкенда](https://github.com/wailsapp/wails/blob/master/v3/TESTING.md) описаны проверки эквивалентности и сквозные тесты ввода. Сообщая о проблеме, отличайте ошибку компиляции от ошибки времени выполнения или упаковки.

### Известные различия

- **Клавиатурные ускорители меню в Linux регистрируются на уровне приложения.** Не назначайте конфликтующие ускорители разным меню. Явное удаление меню окна с помощью `SetMenu(nil)` также предотвращает срабатывание в этом окне сочетаний клавиш удалённого меню; в остальных окнах сохраняются их меню и сочетания клавиш.
- **Панели открытия и сохранения в macOS** выполняются в отдельном системном процессе, как и при использовании cgo; тесты проверяют, что они открываются и корректно закрываются при отмене.
