Wake — экспериментальная система сборки Wails. Один файл `wails.yaml` описывает приложение, фронтенд, целевые платформы, пакеты и параметры подписания. Wake использует эту конфигурацию для планирования и выполнения сборок, кеширования неизменившихся результатов работы и вывода сведений о полученных файлах.

В этом руководстве вы создадите небольшое настольное приложение, настроите его в браузере, соберёте для своего компьютера и запустите в режиме разработки. Начните с одной локальной целевой платформы и сборки без подписи. Добавьте кросс-компиляцию и подготовку дистрибутивов после того, как заработает первая сборка.

У вас уже есть приложение? Перейдите к разделу [Перенос существующего проекта](#--). Описание отдельных полей и расширенных рабочих процессов см. в [руководстве по сборкам с YAML](/experimental/yaml-builds/) и [справочнике по манифесту](/reference/wails-yaml-fields/).

## Чего ожидать от эксперимента

@note{type="caution" title="Используйте тестовый проект или отдельную ветку"}
Wake включается по желанию, а его конфигурация, команды и поведение могут меняться между предварительными сборками. На него пока не распространяются гарантии совместимости стабильной системы сборки. Сохраняйте заведомо рабочую ревизию проекта и записывайте версии CLI и фреймворка, на которых проводите тестирование. Перед распространением тестируйте пакеты в целевых системах.
@end

Wake и бэкенд **Pure Go** выбираются независимо друг от друга. Включение Wake не включает Pure Go автоматически. В этом уроке используется стандартный бэкенд, поэтому для сборки GUI под macOS и Linux требуются обычные нативные инструменты разработки.

Мастер проверяет требования и сохраняет конфигурацию. Сохранение не запускает сборку и не подтверждает готовность всех выбранных целевых платформ. Недостающие инструменты или учётные данные можно добавить позднее, например на узле CI. Недопустимые сочетания целевых платформ и пакетов необходимо исправить перед сохранением.

Миграция **необратима**. Wake не выполняет Taskfile, не разворачивает шаблоны Task и не преобразует YAML обратно в Taskfile. Проекты, которые не были перенесены, по-прежнему используют отдельную устаревшую среду выполнения Task. Активный файл `wails.yaml` никогда не переключается на неё без явного указания.

## Перед началом

Вам потребуются Go, Node.js с npm для начального фронтенда, а также [зависимости для вашей платформы](/getting-started/installation/#platform-specific-dependencies). Перейдите в каталог, в котором хотите создать папку нового проекта. Для работы с мастером также потребуется браузер.

Используйте ревизии CLI и фреймворка, включающие эту предварительную версию. Установка стабильной версии CLI `v3.0.0` не добавляет описанные здесь экраны создания проекта Wake. Следующие команды фиксируют предварительную версию из [PR #6531](https://github.com/wailsapp/wails/pull/6531):

```sh
go install github.com/wailsapp/wails/v3/cmd/wails3@b1daf95f3
wails3 version
```

Убедитесь, что каталог с исполняемым файлом Go добавлен в `PATH`; это объясняется в [руководстве по установке](/getting-started/installation/). Далее в этом руководстве вы зафиксируете зависимость приложения от Go на той же ревизии. При тестировании более новой предварительной версии обновляйте оба аргумента ревизии одновременно.

### Включение Wake в терминале

В Bash или Zsh:

```bash
export WAILS_EXP_USE_WAKE=1
```

В PowerShell:

```powershell
$env:WAILS_EXP_USE_WAKE = '1'
```

Не закрывайте этот терминал до конца руководства. Задавайте переменную снова в каждом новом терминале или задании CI, где выполняются команды Wake. Wake включается самим **наличием** переменной: значение `false` или пустая строка не отключают его. Старое имя `WAILS_USE_WAKE` игнорируется.

## Создание приложения

Запустите мастер создания проекта:

```sh
wails3 init -ui
```

В браузере откроется мастер проекта. Если Wake включён, мастер собирает параметры исходного кода и сборки в рамках одного процесса. Ничего не создаётся до нажатия последней кнопки **Создать проект**. `wails3 setup` — отдельный мастер для глобальных настроек, инструментов и учётных данных для подписания; он не настраивает профиль Wake этого проекта.

| Экран | Что выбрать в этом руководстве | Что произойдёт дальше |
| --- | --- | --- |
| **Проект — Создание проекта Wails** | Введите `wake-demo`, затем нажмите **Продолжить**. | Проект будет создан в новой папке `wake-demo` внутри указанного каталога. |
| **Фреймворк — Выбор фреймворка** | Выберите **Vanilla**, затем нажмите **Продолжить**. | Вы получите небольшой фронтенд, не требующий предварительного изучения конкретного фреймворка. |
| **Язык — Выбор языка** | Выберите **JavaScript**, затем нажмите **Продолжить**. | Экран **Привязки**, предназначенный только для TypeScript, будет пропущен. |
| **Сведения — Сведения о проекте** | Укажите название продукта `Wake Demo`, идентификатор пакета `com.example.wakedemo` и версию `0.1.0`. Нажмите **Продолжить**. | Пока вы выбираете параметры сборки, метаданные сохраняются в мастере. |

В этом уроке не используйте **Глобальные значения по умолчанию**: в этом случае выбор фреймворка и языка будет пропущен. Если в другом проекте выбрать TypeScript, на экране **Привязки** можно выбрать интерфейсы или классы для создаваемых привязок данных Go.

## Выбор параметров сборки перед созданием

Продолжайте работу в том же окне браузера. На снимках экрана ниже показано выполнение этих действий в Linux. В Windows или macOS целевая платформа хоста и необходимые инструменты будут другими.

### Приложение — Что вы создаёте?

Оставьте вариант **Настольное приложение** и выберите **Стандартный бэкенд**. Нажмите **Продолжить**.

![Экран «Приложение» в мастере создания проекта с выбранными вариантами «Настольное приложение» и «Стандартный бэкенд».](/assets/screenshots/wake/application.png)

В этом уроке создаётся приложение с GUI и веб-фронтендом. **Pure Go (экспериментальный)** включается отдельно. Он устраняет необходимость в компиляторе C при поддерживаемой сборке для настольных систем, если ваши зависимости также собираются без CGo. При этом он не отменяет необходимости в библиотеках среды выполнения целевой системы и всех инструментах упаковки и подписания.

Бэкенд — это **общая для всего проекта настройка**. Другие профили, наследующие эти настройки, также используют выбранный бэкенд.

### Целевые платформы — Где должно работать приложение?

Оставьте только целевую платформу для используемого компьютера, затем нажмите **Продолжить**. Изначально мастер выбирает операционную систему и архитектуру хоста.

![Экран «Целевые платформы», где для компьютера из руководства выбрана только linux/amd64.](/assets/screenshots/wake/targets.png)

Имя целевой платформы объединяет операционную систему и архитектуру процессора: например, `windows/amd64`, `darwin/arm64` для Mac с Apple Silicon или `linux/amd64`. `darwin` означает macOS. При выборе другой целевой платформы будет создан исполняемый файл для соответствующей машины; это не означает, что его можно запустить на текущем компьютере.

Дополнительные архитектуры, универсальные сборки для macOS и экспериментальные мобильные целевые платформы оставьте на потом. Их можно добавить в `wails.yaml` после первой локальной сборки.

### Пакеты — Выбор выходных файлов релиза

Не устанавливайте флажки форматов пакетов и отключите параметр **Подписывать выходные файлы релиза**. Нажмите **Продолжить**.

![Экран «Пакеты»: дополнительные форматы пакетов Linux не выбраны, подписывание отключено.](/assets/screenshots/wake/packages.png)

Если дополнительные форматы не выбраны, Wake создаёт стандартный результат для целевой платформы: исполняемый файл настольного приложения либо пакет приложения macOS для графического приложения macOS. Этого достаточно, чтобы проверить приложение локально. При выборе форматов добавляются поддерживаемые выходные файлы для распространения, например DMG, MSIX, NSIS, DEB или AppImage.

Для этой первой локальной сборки подписывание необязательно. Успешная сборка без подписи не означает, что приложение готово к публичному распространению. Для проекта с подписью настройте многократно используемые учётные данные с помощью `wails3 setup` до создания проекта либо настройте подписывание позже в `wails.yaml`. Мастер создания использует настроенные учётные данные, но не изменяет глобальные параметры подписывания.

Wake может использовать настроенные файлы сертификатов за пределами проекта, не копируя закрытые ключи или пароли в `wails.yaml`. Явные параметры подписывания проекта имеют приоритет. Перед подготовкой публичного выпуска ознакомьтесь с [инструкциями по настройке подписывания](/getting-started/setup/) и [руководством по упаковке и подписыванию](/experimental/yaml-builds/#package-and-sign-for-distribution). Подписывание мобильных приложений настраивается в YAML.

### Инструменты — инструменты для сборки

Ознакомьтесь с требованиями для выбранных параметров. Список формируется из плана сборки Wake; это не требование устанавливать каждый инструмент на каждой платформе.

![Экран «Инструменты» с требованиями, определёнными для локальной сборки из исходного кода под Linux.](/assets/screenshots/wake/tools.png)

Для этого руководства потребуются Go и инструменты для фронтенда, а также нативные средства разработки, необходимые стандартному графическому бэкенду основной системы. Docker не является обязательным требованием во всех случаях. Для кросс-компиляции с CGo могут потребоваться компилятор и библиотеки целевой платформы либо поддерживаемый контейнерный набор инструментов.

Перед локальной сборкой устраните проблемы в строках с отметками **Не готово**, **Требуется настройка** или **Требуется обновление**. Следуйте отображаемым инструкциям, если они доступны, либо обратитесь к [руководству по установке для платформы](/getting-started/installation/), а затем нажмите **Повторно проверить требования**. Если установка изменила `PATH` терминала, перезапустите `wails3 init -ui` из обновлённого терминала и повторите выбор параметров.

Мастер может создать корректный проект, даже если на этом компьютере отсутствуют необходимые инструменты или учётные данные для подписывания. Это удобно для настройки CI, но в этом руководстве нужна сборка, которую можно запустить здесь. Некорректную конфигурацию необходимо исправить до создания проекта.

### Создание проекта

Проверьте выбранные параметры: настольное приложение, стандартный бэкенд, целевая платформа текущего компьютера и отключённая подпись. На странице **Инструменты** нажмите **Создать проект** и дождитесь появления сообщения **Параметры проекта приняты**. Вернитесь в терминал и дождитесь, пока CLI завершит создание проекта: подтверждение в браузере лишь принимает выбранные параметры.

![Экран «Параметры проекта приняты» с запланированным путём к приложению и командами, которые следует использовать после успешного создания.](/assets/screenshots/wake/save.png)

Мастер создаёт исходный код и сохраняет параметры целевой платформы, пакета и подписывания в `profiles.setup` внутри `wails.yaml`. Он также задаёт тип приложения, включение фронтенда и общий для проекта бэкенд. Можно закрыть браузер и вернуться в терминал. Дождитесь завершения создания проекта, затем выполните:

```sh
cd wake-demo
go get github.com/wailsapp/wails/v3@b1daf95f3
```

Теперь у вас должны быть `main.go`, модуль Go, каталог `frontend` и нативный `wails.yaml`. Встроенный шаблон использует Wake напрямую; переносить этот новый проект не требуется. Шаблон сообщества может содержать собственные устаревшие задачи, поэтому для него может потребоваться описанная ниже проверка миграции.

На экране завершения отображаются `wails3 build setup` и `wails3 dev`. Имя профиля имеет значение: `wails3 build setup` использует только что сохранённые параметры. Обычная команда `wails3 build` не выбирает профиль `setup` автоматически. Имя профиля не означает, что необходимо запускать `wails3 setup`.

## Сборка и запуск первого приложения

Выполните команду, указанную мастером:

```sh
wails3 build setup
```

При первой сборке устанавливаются зависимости фронтенда, создаются привязки и компилируется приложение. Последующие сборки могут повторно использовать результаты неизменившихся этапов. Дождитесь сообщения **сборка успешно завершена** и ознакомьтесь с путями к выходным файлам, которые вывела CLI. Стандартный каталог выходных файлов — `bin`; графическое приложение macOS собирается в пакет `.app`.

Запустите режим разработки на своём компьютере:

```sh
wails3 dev
```

Должно появиться окно стартового приложения. Введите своё имя и проверьте приветствие. Измените заполнитель поля ввода имени в `frontend/index.html` и сохраните файл — фронтенд должен обновиться. Измените приветствие в `greetservice.go`, чтобы проверить пересборку Go. По завершении нажмите в терминале **Ctrl+C**.

Разработка выполняется локально на основной системе. Профиль выпуска может содержать несколько целевых платформ для кросс-компиляции, но это не влияет на то, на каком компьютере можно запустить окно приложения в режиме разработки. Чтобы локально собрать и запустить приложение для производственной среды, используйте `wails3 run`; подробности приведены в [справочнике по запуску](/reference/wails-yaml-run/).

Теперь у вас есть проект с исходным кодом, проверенный профиль сборки и работающий локальный цикл разработки. Добавьте исходный код и `wails.yaml` в систему управления версиями. Созданные рабочие файлы `.wails/` не являются источником конфигурации.

## Дальнейшие действия

| Цель | Поддержка Wake | Что проверить в первую очередь |
| --- | --- | --- |
| Сборка для другой настольной платформы | Целевые платформы Windows, macOS и Linux, включая обе архитектуры macOS и универсальный выходной файл. | Для Pure Go и CGo требуются разные компиляторы. Протестируйте на целевой ОС и архитектуре. |
| Создание установщиков или пакетов | MSIX, NSIS, приложение macOS/DMG, DEB, RPM, Arch, Void и AppImage. | Для NSIS требуется `makensis`. Для AppImage требуется среда выполнения целевой платформы; для кросс-упаковки графического приложения также необходимо предоставить дерево среды выполнения Linux. |
| Подписывание выпуска | Переносимое подписывание экспортированными ключами для Windows, macOS и DEB/RPM/Arch; также остаются доступны нативные хранилища удостоверений. | У каждого удостоверения, формата и основной системы есть ограничения. Для AppImage и Void нет встроенного процесса подписывания. |
| Нотаризация приложения macOS | Отправка с командным API-ключом и прикрепление билета либо профиль связки ключей macOS. | По-прежнему требуются подходящая подпись Developer ID и метка времени. То, что тестовые подписи, созданные Go, проходят нативные проверки, не доказывает, что Apple примет ваш выпуск. |
| Сборка нескольких программ | Основная программа с графическим интерфейсом, CLI или сервером, а также именованные вспомогательные программы. | Объявите пакеты и типы вспомогательных программ в YAML. Мастер не создаёт для них исходный код. |
| Упаковка файлов, собранных в другом месте | `wails3 build setup --skip-build`. | Укажите в `build.output` соответствующие имена исполняемых файлов и архитектуры. Этот флаг задаётся однократно для команды и не является постоянным параметром профиля. |
| Добавление автоматизации выпуска | Именованные профили, ограниченные перехватчики жизненного цикла, кеширование и параллельная обработка пакетов. | Используйте литеральный YAML и объявленные скрипты, принадлежащие проекту. Произвольное поведение Taskfile не является механизмом расширения Wake. |

Изменяйте `profiles.setup`, другие именованные профили и расширенные параметры в `wails.yaml`. Для изменения общих настроек и учётных данных используйте `wails3 setup`. Полные примеры и требования к пакетам приведены в [руководстве по сборке с YAML](/experimental/yaml-builds/). Графическим приложениям по-прежнему требуются системные библиотеки целевой платформы; Pure Go не делает их полностью статическими приложениями.

iOS и Android по-прежнему являются экспериментальными, требуют SDK своих платформ и CGo и не рассматриваются в этом первом руководстве по настольным приложениям. Мастер не обеспечивает переносимость мобильных сборок между произвольными основными системами.

## Миграция существующего проекта

Работайте в отдельной ветке или копии рабочей версии проекта **Wails v3**. Это миграция конфигурации сборки, а не обновление с Wails v2. Сохраните существующий результат сборки и тесты, чтобы после активации можно было сравнить поведение.

@note{type="note" title="Начните с проверенной миграции"}
Новые проекты, созданные на основе текущих встроенных устаревших шаблонов, можно перенести до сборки их фронтенда. Wake распознаёт стандартные селекторы задач и жизненный цикл разработки таких проектов, не выполняя Taskfile и не вычисляя пользовательские выражения.

Пользовательские задачи, переопределения переменных и политики разработки по-прежнему требуют проверки. Если средство анализа не может представить ваш проект, оставьте его на прежней системе сборки и сообщите результаты диагностики. Не удаляйте нужное вам поведение только ради успешной активации. Описанное выше руководство по созданию нового проекта не требует миграции.
@end

### 1. Проанализируйте проект, не изменяя активную конфигурацию сборки

Включите Wake и используйте предварительную версию CLI, указанную в начале этой страницы. Выполните следующую команду из корневого каталога существующего проекта:

```sh
wails3 migrate --dry-run
```

Ознакомьтесь с указанными поддерживаемыми параметрами и препятствиями. Средство анализа читает устаревшие декларации, но не выполняет их команды. Пробный запуск не создаёт активный манифест. Для диагностики в машиночитаемом формате используйте `wails3 migrate --json`; если также не хотите записывать черновик, используйте `--dry-run --json`.

### 2. Создайте и проверьте неактивное предложение

```sh
wails3 migrate
```

Эта команда создаёт **`wails.migrated.yaml`**, а не `wails.yaml`. Проверьте созданный файл вместе с существующими Taskfile и `build/config.yml`. Проверьте метаданные проекта, команды фронтенда, целевые архитектуры, содержимое пакетов, ресурсы и параметры подписи. Храните секреты в переменных окружения или в хранилище учётных данных.

Известные встроенные задачи можно сопоставить со встроенными параметрами. Консервативные задачи жизненного цикла без аргументов, вызывающие принадлежащий проекту скрипт, могут стать хуками. Иное достижимое поведение пользовательских задач считается препятствием: Wake не отбрасывает его без предупреждения и не запускает через Task в качестве запасного варианта.

Если черновик уже существует, при миграции внесённые и проверенные вами изменения не перезаписываются. Перед намеренной заменой или повторным созданием черновика сохраните его копию. Не переименовывайте заблокированный черновик в `wails.yaml`, чтобы обойти проверки активации. Сократите или замените неподдерживаемое устаревшее поведение и повторно выполните анализ перед активацией. Если проект пока невозможно представить, продолжайте использовать прежнюю систему сборки и сообщите о недостающей возможности.

### 3. Выполните активацию явно

Проверив черновик и устранив препятствия, выполните:

```sh
wails3 migrate --activate --dry-run
wails3 migrate --activate
```

Первая команда проверяет возможность активации, не применяя её. Вторая повторно проверяет устаревшие декларации и валидирует черновик, а затем атомарно создаёт `wails.yaml`; после успешной активации неактивный `wails.migrated.yaml` удаляется. Taskfile, `build/config.yml`, скрипты и ресурсы остаются без изменений. С этого момента сборками Wake управляет активный манифест. Старые файлы не служат вторым источником конфигурации.

В некоторых старых проектах уже есть содержащий только метаданные `wails.yaml` с разделом верхнего уровня `info:`. Хотя это не нативный манифест Wake, файл всё равно занимает путь назначения для активации. Сохраните этот устаревший файл и намеренно переместите его перед активацией: средство миграции не будет перезаписывать или переименовывать его за вас.

### 4. Проверьте перенесённое приложение

```sh
wails3 config check
wails3 build
wails3 dev
```

Сравните приложение и содержимое пакетов с предыдущей сборкой, включая пользовательское поведение при выпуске. Запустите тесты проекта. Явно проверьте каждый перенесённый профиль, например `wails3 config check release` и `wails3 build release`, если черновик содержит профиль `release`.

Редактируйте перенесённые профили непосредственно в `wails.yaml`. `wails3 init -ui` создаёт новые проекты, а `wails3 setup` управляет глобальными настройками. Ни одна из этих команд не предназначена для редактирования профиля выпуска существующего проекта.

### Если потребуется прекратить эксперимент

Удаление `WAILS_EXP_USE_WAKE` из окружения отключает добровольно включаемую функцию, но активный `wails.yaml` по-прежнему блокирует автоматическую маршрутизацию через Taskfile. При недопустимом YAML работа также завершается с ошибкой. Команды обратной миграции нет.

Чтобы вернуться к прежнему процессу, восстановите в системе управления версиями полную ревизию проекта до миграции, включая отсутствие активного манифеста, и используйте совместимые с ней CLI и зависимости. Перед этим сохраните все необходимые новые изменения исходного кода. Отдельная ветка для эксперимента значительно упрощает такое намеренное восстановление.

## Диагностика проблем и отправка отзывов

| Симптом | Что проверить в первую очередь |
| --- | --- |
| При создании проекта пропускаются разделы Application, Targets, Packages и Tools | Задайте `WAILS_EXP_USE_WAKE` в терминале, из которого выполняется запуск, и проверьте, какой исполняемый файл `wails3` находится в `PATH`. Глобальная команда `wails3 setup` всегда сохраняет свой процесс настройки параметров. |
| Шаблону сообщества требуется миграция | Перед активацией проверьте его устаревшую конфигурацию с помощью команд миграции. |
| Для сохранённой сборки сообщается об отсутствующих инструментах | При создании проекта фиксируется намерение. Перед сборкой установите указанные требования к хост-системе: при создании устанавливаются не все выбранные инструменты. |
| Исполняемый файл, созданный кросс-компиляцией, здесь не запускается | Запустите его в выбранной операционной системе и на выбранной архитектуре; для локальной разработки используйте целевую платформу хост-системы. |
| В режиме предварительной сборки не удаётся найти двоичный файл | Проверьте [имена и пути предварительно собранных файлов](/experimental/yaml-builds/#use-prebuilt-desktop-executables), включая подкаталоги для нескольких целевых платформ. |
| Не удаётся применить изменение манифеста | Выполните `wails3 config check` для соответствующего профиля и следуйте диагностическому сообщению для поля. Wake не использует Taskfile в качестве запасного варианта. |

Чтобы проверить сборку перед запуском, используйте `wails3 build setup --plan --json`. `wails3 config check` валидирует конфигурацию, а `wails3 eject` записывает неактивный снимок `wails.ejected.yaml`, не изменяя активный манифест. Перед публикацией вывода команды проверьте его: пути проекта и расположение учётных данных могут раскрыть сведения о вашей локальной среде.

Поделитесь отзывом в [обсуждениях экспериментов](https://github.com/wailsapp/wails/discussions/categories/experiments) или [создайте воспроизводимый отчёт об ошибке](https://github.com/wailsapp/wails/issues). Укажите ревизии CLI и фреймворка, ОС и архитектуру хост-системы, выбранную целевую платформу, точную команду, выбор Pure Go и соответствующее диагностическое сообщение. Сообщите, на каком этапе произошёл сбой: компиляции, упаковки, подписания или запуска приложения. Если это полезно, приложите минимальный манифест без секретов и вывод `wails3 doctor`.
