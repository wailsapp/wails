`NewNotchWindow` создаёт фигурную неактивирующую панель macOS, прикреплённую к корпусу камеры. Wails управляет её нативным размещением, чёрными боковыми областями примыкания, прозрачным внешним холстом, уровнем окна, поведением в Spaces и необязательной анимацией показа и скрытия. Веб-содержимое занимает только запрошенную внутреннюю прямоугольную область. При наведении указателя на окно его webview немедленно становится ключевым, не активируя приложение.

@note{type="caution" title="Для прозрачности webview используется закрытый API"}
Чтобы прозрачное веб-содержимое не закрывало нативную форму выреза, для `NewNotchWindow` требуется `-tags private_mac_apis`. Без этого тега панель, размещение и анимации по-прежнему работают, но webview остаётся непрозрачным. См. раздел [«Закрытые API macOS»](/guides/build/private-macos-apis/#webview-transparency-and-background).

@end

```go
alert := app.Window.NewNotchWindow(application.NotchWindowOptions{
    Width:    660,
    Height:   92,
    Animated: true,
    WindowOptions: application.WebviewWindowOptions{
        Name: "alert",
        URL:  "/alert",
    },
})

alert.Show()
alert.Hide()
visible := alert.Visibility()
alert.Close()
```

## Параметры

| Поле | Тип | Значение по умолчанию | Описание |
| --- | --- | --- | --- |
| `Width` | `int` | `660` | Доступная ширина webview внутри нативных фигурных краёв. |
| `Height` | `int` | `92` | Доступная высота webview внутри нативных фигурных краёв. |
| `Animated` | `bool` | `false` | Сдвигает окно вниз при `Show` и вверх при `Hide`. |
| `AnimationSpeed` | `time.Duration` | `420ms` | Длительность показа. Скрытие занимает две трети этого времени — по умолчанию `280ms`. |
| `Screen` | `*Screen` | основной дисплей | Выбирает определённый дисплей. Если он не указан, Wails использует основной дисплей. |
| `WindowOptions` | `WebviewWindowOptions` | значения по умолчанию | Задаёт имя, URL или HTML, CSS, JavaScript, сочетания клавиш и другие параметры поведения webview. |

`NewNotchWindow` управляет внешними размерами, положением, рамкой, прозрачностью, политикой изменения размера, классом нативной панели, уровнем окна и поведением в коллекции. Значения этих полей в `WindowOptions` намеренно заменяются. Остальные поля сохраняются. Нативное перетаскивание за фон и области перетаскивания CSS отключены, чтобы окно оставалось прикреплённым к корпусу камеры.

Возвращаемый `NotchWindow` намеренно предоставляет только `Show`, `Hide`, `Visibility` и `Close`; изменить нативную геометрию через высокоуровневый дескриптор нельзя.

@note{type="note"}
Для окон у выреза экрана требуется macOS. На компьютере Mac без корпуса камеры Wails размещает окно по центру в верхней части экрана, под строкой меню. На неподдерживаемых платформах `NewNotchWindow` возвращает неактивный дескриптор: его методы жизненного цикла безопасны и ничего не делают, а `Visibility` всегда имеет значение false.

@end

## Жизненный цикл

- `Show` показывает существующее нативное окно. Если анимация включена, оно выдвигается вниз из-за верхней границы дисплея.
- `Hide` сохраняет окно для повторного использования. Если анимация включена, перед удалением из порядка отображения окно задвигается обратно за верхнюю границу дисплея. Webview, состояние JavaScript, привязки и обработчики событий остаются загруженными, но скрытое окно не реагирует на наведение; чтобы снова показать его, приложение должно вызвать `Show`.
- `Visibility` сообщает текущее состояние нативной видимости.
- `Close` безвозвратно уничтожает нативное окно. Прежде чем снова показать это уведомление, создайте новое окно.
- При наведении указателя окно у выреза выводится на передний план, а его webview получает фокус для немедленного ввода с клавиатуры, при этом сохраняется неактивирующее поведение панели.

Каждый вызов `NewNotchWindow` создаёт независимое окно с собственным содержимым, состоянием видимости и анимации. Окна используют один нативный уровень, поэтому экземпляр, который был показан последним или в который последним вошёл указатель, отображается впереди и может перекрывать предыдущие экземпляры. Если окна назначены разным экранам, каждое из них располагается по центру относительно корпуса камеры соответствующего экрана. macOS не координирует окна у выреза, принадлежащие разным приложениям: если разные приложения показывают окна в одном месте и на одном уровне, впереди отображается окно, последним помещённое в порядок отображения.

Для уведомлений приложения обычно повторно используют скрытое окно или ведут собственную очередь в одном webview. Wails не навязывает очередь, замену, автоматическое закрытие или политику единственного окна.

@note{type="note"}
Постоянные свёрнутые поверхности, которые вновь открываются при наведении, намеренно отделены от скрытия уведомлений и отслеживаются в [#6009](https://github.com/wailsapp/wails/issues/6009).

@end

См. пример [notch-notification](https://github.com/wailsapp/wails/tree/v3.0.0/v3/examples/notch-notification) с компактным системным монитором, состояние JavaScript которого в реальном времени сохраняется при многократных циклах показа и скрытия уведомления.
