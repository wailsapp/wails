## Обзор

Система сборки Wails — это гибкий и мощный инструмент, предназначенный для упрощения сборки приложений Wails. Она использует [Task](https://taskfile.dev) — средство выполнения задач, с помощью которого можно легко определять и запускать задачи. Хотя система сборки v3 используется по умолчанию, Wails поддерживает подход «используйте собственные инструменты», позволяя разработчикам при необходимости настраивать процесс сборки.

Подробнее об использовании Task см. в [официальной документации](https://taskfile.dev/usage/).

## Task — основа системы сборки

[Task](https://taskfile.dev) — современная альтернатива Make, написанная на Go. Для определения задач и их зависимостей используется файл YAML. В системе сборки Wails [Task](https://taskfile.dev) играет центральную роль в координации процесса сборки.

Основной файл `Taskfile.yml` находится в корне проекта, а задачи для отдельных платформ определены в файлах `build/<platform>/Taskfile.yml`. Общий файл `Taskfile.yml` в каталоге `build` содержит общие задачи, используемые на разных платформах.

@filetree

- Project Root
  - Taskfile.yml
  - build
    - windows/Taskfile.yml
    - darwin/Taskfile.yml
    - linux/Taskfile.yml
    - Taskfile.yml
@end

## Taskfile.yml

Файл `Taskfile.yml` в корне проекта служит основной точкой входа в систему сборки. В нём определены задачи и их зависимости. Ниже приведён файл `Taskfile.yml` по умолчанию:

```yaml
version: '3'

includes:
  common: ./build/Taskfile.yml
  windows: ./build/windows/Taskfile.yml
  darwin: ./build/darwin/Taskfile.yml
  linux: ./build/linux/Taskfile.yml

vars:
  APP_NAME: "myproject"
  BIN_DIR: "bin"
  VITE_PORT: '{{.WAILS_VITE_PORT | default 9245}}'

tasks:
  build:
    summary: Builds the application
    cmds:
      - task: "{{OS}}:build"

  package:
    summary: Packages a production build of the application
    cmds:
      - task: "{{OS}}:package"

  run:
    summary: Runs the application
    cmds:
      - task: "{{OS}}:run"

  dev:
    summary: Runs the application in development mode
    cmds:
      - wails3 dev -config ./build/config.yml -port {{.VITE_PORT}}


```

## Файлы Taskfile для отдельных платформ

У каждой платформы есть собственный файл Taskfile, расположенный в соответствующем подкаталоге каталога `build`. Эти файлы определяют основные задачи для соответствующей платформы. Каждый файл Taskfile подключает общие задачи из файла `build/Taskfile.yml`.

### Windows

Расположение: `build/windows/Taskfile.yml`

Файл Taskfile для Windows содержит задачи сборки, упаковки и запуска приложения в Windows. Основные возможности:

- Сборка с необязательными флагами для рабочей версии
- Создание файла значка `.ico`
- Создание файла Windows `.syso`
- Создание установщика NSIS для упаковки

### Linux

Расположение: `build/linux/Taskfile.yml`

Файл Taskfile для Linux содержит задачи сборки, упаковки и запуска приложения в Linux. Основные возможности:

- Сборка с необязательными флагами для рабочей версии
- Создание пакетов AppImage, deb, rpm и Arch Linux
- Создание файла `.desktop` для приложений Linux

### macOS

Расположение: `build/darwin/Taskfile.yml`

Файл Taskfile для macOS содержит задачи сборки, упаковки и запуска приложения в macOS. Основные возможности:

- Сборка двоичных файлов для архитектур amd64, arm64 и универсальной архитектуры (обе архитектуры)
- Создание файла значка `.icns`
- Создание пакета `.app` для распространения
- Специальное подписание пакетов `.app`
- Задание флагов сборки и переменных среды для macOS

## Выполнение задач и псевдонимы команд

Команда `wails3 task` представляет собой встроенную версию [Taskfile](https://taskfile.dev), которая выполняет задачи, определённые в вашем файле `Taskfile.yml`.

Команды `wails3 build` и `wails3 package` являются псевдонимами для `wails3 task build` и `wails3 task package` соответственно. При запуске этих команд Wails преобразует их внутри системы в вызов соответствующей задачи:

- `wails3 build` → `wails3 task build`
- `wails3 package` → `wails3 task package`

### Передача параметров задачам

Переменные командной строки можно передавать задачам в формате `KEY=VALUE`. Эти переменные передаются через команды-псевдонимы:

```bash
# These are equivalent:
wails3 build GOOS=linux
wails3 task build GOOS=linux
```

Стандартные задачи используют `GOOS`, `ARCH` и `DEV`. Такие переменные, как `VERSION`, `OUTPUT`, `PLATFORM` или `CONFIG`, влияют на задачу, только если они считываются в вашем собственном файле Taskfile. Ниже приведён пример пользовательского файла Taskfile, а не стандартной задачи сборки Wails:

```yaml
tasks:
  build:
    cmds:
      - echo "Building for {{.PLATFORM | default "darwin"}}"
      - go build -tags {{.CONFIG | default "debug"}} -o myapp
```

Если ваша пользовательская задача упаковки считывает `VERSION` и `OUTPUT`, их можно передать таким же способом:

```bash
wails3 package VERSION=2.0.0 OUTPUT=myapp.pkg
```

## Общий процесс сборки

На всех платформах процесс сборки обычно включает следующие этапы:

1. Упорядочение зависимостей модулей Go
2. Сборка клиентской части
3. Создание значков
4. Компиляция кода Go с флагами для соответствующей платформы
5. Упаковка приложения (зависит от платформы)

## Настройка процесса сборки

Хотя система сборки v3 предоставляет надёжную конфигурацию по умолчанию, её можно легко адаптировать к потребностям вашего проекта. Изменяя `Taskfile.yml` и файлы Taskfile для отдельных платформ, можно:

- Добавлять новые задачи
- Изменять существующие задачи
- Изменять порядок выполнения задач
- Интегрировать другие инструменты и сценарии

Благодаря этой гибкости процесс сборки можно адаптировать к конкретным требованиям, сохранив преимущества структуры, предоставляемой системой сборки Wails.

@note{type="tip" title="Изучение Taskfile"}
Настоятельно рекомендуем прочитать документацию по [Taskfile](https://taskfile.dev), чтобы научиться эффективно использовать Taskfile. Чтобы узнать, какая версия Taskfile встроена в Wails CLI, выполните команду `wails3 task --version`.

@end

## Режим разработки

Система сборки Wails включает мощный режим разработки, который упрощает работу разработчика благодаря автоматической перезагрузке и горячей замене модулей. Этот режим активируется командой `wails3 dev`.

### Принцип работы

При запуске `wails3 dev` выполняются следующие действия:

1. Команда проверяет наличие свободного порта и, если порт не указан, по умолчанию использует 9245.
2. Она задаёт переменные среды для сервера разработки клиентской части (Vite).
3. Она запускает наблюдение за файлами с помощью библиотеки [refresh](https://github.com/atterpac/refresh).

Библиотека [refresh](https://github.com/atterpac/refresh) отслеживает изменения файлов и запускает повторную сборку. Она использует конфигурацию, заданную в ключе `dev_mode` файла `./build/config.yml`. Её можно настроить так, чтобы она игнорировала определённые каталоги и файлы, определяла, за какими файлами следить и какие действия выполнять при обнаружении изменений. Конфигурация по умолчанию подходит для большинства случаев, но при необходимости её можно адаптировать под свои требования.

### Конфигурация

Ниже приведён пример её структуры:

```yaml
dev_mode:
  root_path: .
  log_level: warn
  debounce: 1000
  ignore:
    dir:
      - .git
      - node_modules
      - frontend
      - bin
    file:
      - .DS_Store
      - .gitignore
      - .gitkeep
    watched_extension:
      - "*.go"
    git_ignore: true
  executes:
    - cmd: wails3 task common:install:frontend:deps
      type: once
    - cmd: wails3 task common:dev:frontend
      type: background
    - cmd: go mod tidy
      type: blocking
    - cmd: wails3 task build
      type: blocking
    - cmd: wails3 task run
      type: primary
```

Этот файл конфигурации позволяет:

- Задать корневой путь для наблюдения за файлами
- Настроить уровень ведения журнала
- Задать интервал устранения дребезга для событий изменения файлов
- Игнорировать определённые каталоги, файлы или расширения файлов
- Определить команды, выполняемые при изменении файлов

### Настройка режима разработки

Режим разработки можно настроить, изменив эти значения в файле `config.yml`.

В частности, можно:

1. Изменить отслеживаемые каталоги или файлы
2. Настроить время задержки (debounce), чтобы управлять скоростью реакции системы на изменения
3. Добавить или изменить команды выполнения в соответствии с потребностями проекта

### Использование браузера при разработке

Хотя Wails v2 полностью поддерживал использование браузера при разработке, это вызывало много путаницы. Приложения, работавшие в браузере, могли не работать в настольном приложении, поскольку в WebView доступны не все браузерные API.

При разработке пользовательского интерфейса по-прежнему можно использовать браузер в v3: для этого в режиме разработки откройте URL-адрес Vite `http://localhost:9245`. Так вы получите доступ к мощным инструментам разработчика браузера при работе над стилями и компоновкой. Учтите, что в этом режиме привязки Go *работать не будут*. Когда будете готовы протестировать такие функции, как привязки и события, просто переключитесь на представление настольного приложения, чтобы убедиться, что всё безупречно работает в рабочей среде.
