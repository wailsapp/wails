Используйте `Media.SetSource` для воспроизведения коротких локальных клипов в приложении Wails v3. В Linux WebKitGTK поручает воспроизведение GStreamer, который не может напрямую загружать URL `wails://`. Вспомогательная функция получает клип через поток Wails и назначает проигрывателю blob-URL.

На настольных системах передача использует существующий транспорт ресурсов Wails, не открывая прослушивающий сокет. API работает с элементами аудио и видео. Обычные медиа по HTTP/HTTPS могут напрямую использовать `src` проигрывателя.

## Регистрация медиафайлов

Предоставьте файловую систему с клипами, которые разрешено воспроизводить фронтенду, затем зарегистрируйте обработчик медиа в именованном потоке:

```go
import (
    "embed"
    "io/fs"
    "log"

    "github.com/wailsapp/wails/v3/pkg/application"
    "github.com/wailsapp/wails/v3/pkg/services/media"
)

//go:embed clips
var clips embed.FS

func registerMedia(app *application.App) {
    mediaFiles, err := fs.Sub(clips, "clips")
    if err != nil {
        log.Fatal(err)
    }
    handler, err := media.NewHandler(mediaFiles, 32 << 20) // 32 MiB per file
    if err != nil {
        log.Fatal(err)
    }
    app.HandleStream("media", handler)
}
```

Вызовите `registerMedia(app)` после создания приложения и до вызова `app.Run()`.

Для файлов на диске используйте `os.OpenRoot(directory)` и передайте `root.FS()` в `media.NewHandler`. Держите корень открытым до возврата из `app.Run()`, затем закройте его. Выберите каталог, содержащий только файлы, доступные фронтенду для чтения; `os.Root` ограничивает доступ, даже если символическая ссылка ведёт за пределы каталога.

## Загрузка клипа

Создайте проигрыватель:

```html
<video id="player" controls></video>
```

Для фронтенда, использующего среду выполнения npm:

```javascript
import { Media } from '@wailsio/runtime';

const player = document.getElementById('player');

try {
    await Media.SetSource(player, 'media', 'welcome.mp4');
} catch (error) {
    if (error.name !== 'AbortError') {
        console.error('Could not load the clip:', error);
    }
}
```

Для приложения со встроенной средой выполнения замените импорт на:

```javascript
import { Media } from '/wails/runtime.js';
```

Второй аргумент — имя зарегистрированного потока. Третий — путь к файлу относительно корня его файловой системы, разделённый косыми чертами, например `welcome.mp4` или `tutorials/intro.mp4`. Это не URL и не путь операционной системы.

Промис разрешается после назначения источника. Затем проигрыватель декодирует его. Обрабатывайте событие `error` проигрывателя для обнаружения неподдерживаемых кодеков и вызывайте `player.play()` из обработчика действия пользователя, если нужно самостоятельно начать воспроизведение.

## Замена или освобождение клипа

Для смены клипа снова вызовите `Media.SetSource`. Это отменит предыдущую незавершённую загрузку для этого проигрывателя, поэтому медленный ответ не перезапишет последний выбор. Старый клип остаётся доступным до успешной загрузки нового. После этого его blob-URL отзывается.

Вызывайте `Media.ClearSource(player)` при закрытии проигрывателя или размонтировании его компонента:

```javascript
Media.ClearSource(player);
```

Это отменяет незавершённую загрузку, сбрасывает проигрыватель и освобождает blob-URL. Вызывайте функцию до удаления элемента из документа. Компонент фреймворка должен вызывать её в обработчике размонтирования или уничтожения. Одно лишь удаление элемента не освобождает blob-URL. Последовательно используйте эти вспомогательные функции для источника проигрывателя.

Для разметки `<video><source ...></video>` передайте выбранное имя файла в `Media.SetSource(video, "media", name)`. Функция задаёт `src` родительского проигрывателя, который имеет приоритет над дочерними `<source>`. Очистка этого атрибута позволяет браузеру снова учитывать дочерние элементы; используйте пустой проигрыватель, если управляете всеми источниками через этот API.

Аудиообъекты, не подключённые к документу, также работают:

```javascript
const sound = new Audio();
await Media.SetSource(sound, 'media', 'notification.mp3');
sound.addEventListener('ended', () => Media.ClearSource(sound), { once: true });
// Call sound.play() from an appropriate user interaction.
// Also clear it if playback is cancelled or the owning component is disposed.
```

## Ограничение скачивания и отмена загрузки

Ограничение по умолчанию — **32 MiB на источник**. Можно выбрать меньшее или большее положительное целочисленное ограничение в байтах в пределах ограничения, заданного в Go:

```javascript
const controller = new AbortController();
const loading = Media.SetSource(player, 'media', 'welcome.mp4', {
    maxBytes: 8 * 1024 * 1024,
    signal: controller.signal,
});

// Call controller.abort() to cancel this load.
await loading;
```

Слишком большой файл отклоняется с `RangeError`. Обработчик Go проверяет размер до чтения содержимого и передаёт не больше меньшего из собственного ограничения и ограничения фронтенда. Фронтенд также проверяет полученный размер и отклоняет неполные передачи. Отмена приводит к отклонению с `AbortError` либо с причиной, переданной в `AbortController.abort(reason)`.

Файлы передаются кадрами по 64 KiB. Настольный потоковый транспорт Wails ограничивает ответы опроса размером 1 MiB, поэтому буферизация полных ответов в WebView2 не сохраняет весь медиафайл в одном ответе. Очереди потоков имеют собственный ограниченный механизм обратного давления. Эти ограничения транспорта не меняют поведение функции проигрывателя, работающей с целым blob.

**Весь файл скачивается до начала воспроизведения.** Ограничение в байтах действует на файл, а не на общую память приложения. Несколько проигрывателей, старый клип во время замены, создание blob и декодированные медиа могут потреблять дополнительную память. Функция начинает передачу при вызове независимо от настройки `preload` проигрывателя. Вызывайте её, когда пользователь выбирает загрузку клипа.

Для больших локальных файлов эта функция не является решением для потокового воспроизведения. Увеличение ограничения также повышает расход памяти. Для медиа, уже размещённых по HTTP/HTTPS, следует использовать штатную загрузку браузера, чтобы он мог воспроизводить поток и перематывать с помощью запросов диапазонов.

## Устранение проблем воспроизведения в Linux

- Если прямое локальное воспроизведение сообщает **No URI handler implemented for "wails"**, загружайте клип через `Media.SetSource`. Это относится как к стандартному стеку GTK4, так и к устаревшему стеку `-tags gtk3`.
- Если загрузка успешна, но декодирование не работает, проверьте кодеки GStreamer на целевой системе. MP4 обычно требует поддержки видео H.264 и аудио AAC; MP3 нужен декодер MP3. Проверяйте поставляемые форматы в поддерживаемых дистрибутивах.
- При сбое передачи проверьте имя зарегистрированного потока, относительное имя файла и права файловой системы. Изменение файла во время передачи может привести к неполной передаче; повторите попытку после завершения записи.
- Если приложение задаёт Content Security Policy, разрешите источник ресурсов Wails в `connect-src` и `blob:` в `media-src`. Для исключительно локальной политики можно использовать `connect-src 'self'; media-src 'self' blob:`. Сохраните остальные директивы.
- Если файл превышает ограничение, выберите более короткий или меньший клип либо задайте явное ограничение в соответствии с бюджетом памяти приложения.

Запустите [пример audio-video](https://github.com/wailsapp/wails/tree/master/v3/examples/audio-video) командой `go run .`, чтобы проверить встроенные образцы MP3 и MP4 на своём компьютере.
