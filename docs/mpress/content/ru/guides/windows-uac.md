<br/>

Контроль учетных записей Windows (UAC) определяет права, с которыми выполняется приложение Wails. По умолчанию приложения Wails v3 содержат явную конфигурацию UAC в манифесте Windows, что обеспечивает единообразное поведение на разных компьютерах.

## Уровни выполнения UAC

Приложения Windows могут запрашивать разные уровни выполнения через файл манифеста. Wails v3 автоматически добавляет конфигурацию UAC с уровнем выполнения по умолчанию, который можно изменить в соответствии с потребностями приложения.

### Доступные уровни выполнения

| Уровень | Описание | Назначение |
| --- | --- | --- |
| `asInvoker` | Выполняется с теми же правами, что и родительский процесс | Уровень по умолчанию для большинства приложений |
| `highestAvailable` | Выполняется с максимальными правами, доступными пользователю | Приложения, которым может потребоваться повышение прав |
| `requireAdministrator` | Всегда требует прав администратора | Системные утилиты, программы установки |

### Конфигурация по умолчанию

Приложения Wails v3 содержат в манифесте Windows следующую конфигурацию UAC по умолчанию:

```xml
<trustInfo xmlns="urn:schemas-microsoft-com:asm.v3">
    <security>
        <requestedPrivileges>
            <requestedExecutionLevel level="asInvoker" uiAccess="false"/>
        </requestedPrivileges>
    </security>
</trustInfo>
```

Эта конфигурация обеспечивает следующее поведение приложения:

- Выполняется с теми же правами, что и запустивший его процесс
- По умолчанию не требует повышения прав
- Единообразно работает на разных компьютерах
- Не вызывает запросы UAC для обычных пользователей

## Изменение конфигурации UAC

Поскольку Wails v3 рекомендует настраивать ресурсы сборки, конфигурацию UAC можно изменить непосредственно в шаблоне манифеста Windows.

### Расположение шаблона манифеста

Шаблон манифеста Windows находится по следующему пути:

```
build/windows/wails.exe.manifest
```

### Изменение уровня выполнения

Чтобы изменить уровень выполнения, отредактируйте атрибут `level` элемента `requestedExecutionLevel`:

```xml {title="build/windows/wails.exe.manifest"}
<trustInfo xmlns="urn:schemas-microsoft-com:asm.v3">
    <security>
        <requestedPrivileges>
            <requestedExecutionLevel level="requireAdministrator" uiAccess="false"/>
        </requestedPrivileges>
    </security>
</trustInfo>
```

### Примеры

#### Стандартное приложение (по умолчанию)

Для большинства приложений следует использовать уровень `asInvoker` по умолчанию:

```xml
<requestedExecutionLevel level="asInvoker" uiAccess="false"/>
```

#### Системная утилита

Для приложений, которым при наличии возможности требуется повышение прав:

```xml
<requestedExecutionLevel level="highestAvailable" uiAccess="false"/>
```

#### Средство администрирования

Для приложений, которым всегда требуются права администратора:

```xml
<requestedExecutionLevel level="requireAdministrator" uiAccess="false"/>
```

## Доступ к пользовательскому интерфейсу

Атрибут `uiAccess` определяет, может ли приложение взаимодействовать с элементами пользовательского интерфейса процессов с более высокими правами. В большинстве случаев следует оставить значение `false`.

Установите значение `true`, только если приложению необходимо:

- Отправлять ввод другим приложениям
- Управлять пользовательским интерфейсом других приложений
- Получать доступ к элементам пользовательского интерфейса процессов с более высокими правами

@note{type="caution" title="Требования для доступа к пользовательскому интерфейсу"}
При значении `uiAccess="true"` приложение должно быть:

- Подписано цифровой подписью с использованием сертификата от доверенного центра сертификации
- Установлено в защищенном расположении (Program Files или Windows\System32)

@end

## Сборка с пользовательскими настройками UAC

После изменения шаблона манифеста соберите приложение обычным способом:

```bash
wails3 build
```

В процессе сборки пользовательская конфигурация UAC будет автоматически встроена в исполняемый файл.

## Проверка конфигурации UAC

С помощью инструмента `go-winres` можно проверить, правильно ли встроены настройки UAC:

```bash
go-winres extract --in your-app.exe --out extracted-resources/
```

Затем проверьте извлеченный файл манифеста и убедитесь, что в нем присутствует конфигурация UAC.

@note{type="tip" title="Сохранение манифеста"}
В отличие от некоторых других фреймворков, в Wails v3 конфигурация UAC встраивается непосредственно в исполняемый файл во время компиляции, поэтому она сохраняется при копировании приложения на другие компьютеры.

@end

## Устранение неполадок

### Запросы UAC не появляются

Если задано значение `requireAdministrator`, но запросы UAC не появляются:

- Убедитесь, что манифест правильно встроен в исполняемый файл
- Убедитесь, что приложение не запускается из процесса, права которого уже повышены
- Убедитесь, что синтаксис манифеста соответствует требованиям XML

### Приложение не запускается

Если приложение не запускается после изменения параметров UAC:

- Проверьте синтаксис манифеста на наличие ошибок XML
- Убедитесь, что указано допустимое значение уровня выполнения
- Чтобы локализовать проблему, попробуйте вернуть значение `asInvoker`

### Различия в поведении на разных компьютерах

Если поведение UAC различается на разных компьютерах:

- Убедитесь, что манифест встроен в исполняемый файл, а не хранится отдельно
- Убедитесь, что исполняемый файл не был изменён после сборки
- Убедитесь, что UAC Windows включён на целевом компьютере
