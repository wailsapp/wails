## Доступность

В этом справочном разделе описано экспериментальное расширение run. Его наличие в выпущенной версии CLI не гарантируется.

`wails3 run` собирает и запускает приложение с локальными параметрами манифеста по умолчанию. Для выполнения на основе манифеста необходимо явно включить [`WAILS_EXP_USE_WAKE=1`](/experimental/yaml-builds#enable-yaml-builds). Если манифест не найден, команда запускает `go run .` в текущем каталоге без необходимости включать эту возможность. Недопустимый или недоступный для чтения манифест считается ошибкой; резервный вариант в таком случае никогда не выбирается. Если манифест существует, но поддержка YAML отключена, команда сообщает, как её включить.

Сгенерированный [`wails.yaml` справочник по полям](/reference/wails-yaml-fields) содержит типы полей и значения по умолчанию. Перед объявлением поддержки нативных мобильных платформ и пакетов macOS в выпуске её необходимо проверить на соответствующей системе.

## Контракт команды

`wails3 run` находит ближайший `wails.yaml`, определяет конфигурацию для одной целевой платформы, выполняет сборку через существующий конвейер с кэшированием и запускает результат. Поиск идёт от рабочего каталога вверх: на каждом уровне сначала проверяется наличие манифеста, а затем — границы `go.mod`, на которой поиск прекращается. Каталог манифеста служит корнем проекта и рабочим каталогом настольного приложения.

По умолчанию целевой платформой служат операционная система и архитектура хоста. Мобильные цели необходимо выбирать явно. Возможность кросс-компиляции не означает, что настольный исполняемый файл можно запустить на хосте; при выборе несовместимой настольной цели команда завершится с ошибкой до начала сборки. Это относится и к исполняемым файлам, собранным с помощью `CGO_ENABLED=0`: успешная кросс-сборка только на Go не предоставляет эмулятор и не изменяет контракт локального запуска. Для кросс-компиляции используйте [`wails3 build`](/experimental/yaml-builds/#cross-compile-desktop-applications), а полученные файлы запускайте или устанавливайте в целевой системе. Для Android используйте `--target android/arm64 --device <adb-serial>` или `--target android/arm64 --emulator <avd-name>`. Выбранная архитектура должна соответствовать устройству или эмулятору. Для симулятора iOS используйте `--target ios/arm64 --device <udid>`, а для физического устройства дополнительно укажите `--destination device`. Для планирования и выполнения на iOS необходимы macOS и Xcode.

При использовании YAML сборка включает встроенные ресурсы и выполняется по пути производственной сборки, который автоматически добавляет тег `production`. За оперативную перезагрузку по-прежнему отвечает `wails3 dev`; `dev.tags` не влияет на `wails3 run`.

```shell
wails3 run
wails3 run --tags extra_tag
wails3 run -- --example-mode other
wails3 run --plan
wails3 run --skip-build
```

`--plan` определяет и отображает выбранную цель, итоговые теги сборки, исполняемый или устанавливаемый артефакт, аргументы и рабочий каталог, не выполняя сборку, установку или запуск. План содержит имена ключей переопределения окружения, но не их значения.

## Параметры CLI

| Параметр | Назначение |
| --- | --- |
| `--tags <tags>` | Дополнительные теги сборки Go, разделённые запятыми. |
| `--skip-build` | Импортировать существующие исполняемые файлы настольных приложений из каталога вывода YAML, а затем запустить их без компиляции. |
| `--target <os>/<arch>` | Выбирает одну цель; по умолчанию используются ОС и архитектура хоста. |
| `--plan` | Отображает итоговые параметры без сборки и запуска. Допускаются планы для настольных приложений на других платформах. |
| `--device <id>` | Серийный номер Android adb либо идентификатор симулятора или устройства iOS. |
| `--emulator <name>` | Виртуальное устройство Android, которое нужно запустить или использовать повторно; нельзя сочетать с `--device`. |
| `--destination <kind>` | Цель iOS: `simulator` (по умолчанию) или `device`. |
| `-- <args...>` | Заменяет настроенные аргументы приложения. Один `--` очищает их. |
| `--appargs <string>` | Совместимый вариант записи: разбирает одну строку с правилами заключения в кавычки в стиле POSIX. Нельзя указывать повторно или сочетать с аргументами после `--`. |

Для селекторов мобильных устройств необходимы манифест и соответствующая мобильная цель.

Для `--skip-build` требуются активный YAML-проект и совместимый исполняемый файл настольного приложения. При этом пропускаются обработка фронтенда, создание привязок, компиляция, UPX и хуки сборки, но настроенные аргументы запуска и переменные окружения по-прежнему применяются. Импортированные исполняемые файлы проверяются и копируются в созданное Wake рабочее пространство без изменения исходных файлов. На основе этих входных данных и текущих ресурсов пакета формируются GUI-приложения для macOS. См. [пути к предварительно собранным входным файлам и требования к ним](/experimental/yaml-builds/#use-prebuilt-desktop-executables).
Теги сборки не могут изменить предварительно собранный исполняемый файл, поэтому `--tags` и настроенные теги сборки в этом режиме не действуют.

## Поля

Необязательное сопоставление `run` задаёт общие параметры запуска по умолчанию. Необязательное сопоставление `run` внутри `targets["<os>"]` или `targets["<os>/<arch>"]` задаёт параметры по умолчанию для конкретной платформы или архитектуры. Параметры для конкретной архитектуры имеют приоритет над общими параметрами ОС независимо от порядка элементов сопоставления.

| Поле | Тип | По умолчанию | Назначение |
| --- | --- | --- | --- |
| `run.tags` | `list(string)` | `[]` | Дополнительные теги Go, используемые только при сборках для запуска. |
| `run.args` | `list(string)` | `[]` | Аргументы, передаваемые приложению. |
| `run.environment` | `map(string)` | `{}` | Переопределения окружения времени выполнения, отдельные от окружения компилятора. |
| `target["<os>"].run.tags` | `list(string)` | `[]` | Дополнительные теги запуска для выбранной платформы. |
| `target["<os>"].run.args` | `list(string)` | унаследовано | При явном задании заменяет общие аргументы; `[]` очищает их. |
| `target["<os>"].run.environment` | `map(string)` | `{}` | Переопределяет общие значения окружения времени выполнения по ключу. |

Аргументы передаются как вектор аргументов без подстановок командной оболочки. Согласно существующему контракту YAML, допускающему только литералы, значения окружения являются строковыми литералами.

## Пример для платформы

Этот фрагмент дополняет обычную конфигурацию проекта. `example_private_api` — заполнитель для фактического тега закрытого API, необходимого в этом примере.

```yaml
build:
  tags: [devtools]
run:
  args: [--example-mode]
targets:
  darwin:
    tags: [example_private_api]
    run:
      environment:
        EXAMPLE_WINDOW_MODE: native
  linux:
    run:
      environment:
        GDK_BACKEND: wayland
  windows:
    run:
      args: [--example-mode, --windows-option]
```

Параметр окружения Linux относится только к этому примеру и требует сеанса Wayland; он не является параметром Wails по умолчанию. Тег закрытого API выбирается только в macOS. Существующий `target.tags` применяется к производственным сборкам, включая сборки для запуска. `target.run.tags` ограничивает дополнительный тег сборками для запуска.

Переопределение для конкретной архитектуры может уточнять общие параметры ОС по умолчанию:

```yaml
targets:
  linux/arm64:
    run:
      tags: [example_arm64]
      args: []
```

Вместе с предшествующим сопоставлением Linux это сохраняет `GDK_BACKEND`, добавляет тег для конкретной архитектуры и очищает общие аргументы приложения.

## Правила разрешения

| Параметр | Порядок разрешения от низшего приоритета к высшему |
| --- | --- |
| Теги | Объединить `build.tags`, выбранный `target.tags`, автоматически добавляемый `production`, `run.tags`, выбранный `target.run.tags` и параметр CLI `--tags`; сохранить первое вхождение каждого тега. |
| Окружение времени выполнения | Унаследовать окружение запускающей командной оболочки, наложить `run.environment`, а затем выбранный `target.run.environment`. Пустое значение задаёт пустую строку. |
| Аргументы приложения | Общий `run.args` заменяется явно заданными аргументами цели, а затем явными аргументами после `--`. Один `--` очищает настроенные аргументы. |

В выбранной цели общие параметры ОС разрешаются перед параметрами для конкретной архитектуры: теги накапливаются, значения окружения объединяются по ключу, а явно заданные аргументы заменяют менее конкретный список. Сборки для запуска также добавляют `android` или `ios` для соответствующей мобильной цели.

При генерации привязок и компиляции Go используются одинаковые итоговые теги. Эти теги входят в ключи кэша сборки. Изменение только аргументов приложения или окружения времени выполнения не аннулирует результаты компиляции; при следующем запуске используются новые значения.

Сопоставления платформ настраивают конкретную платформу; их наличие не делает другие платформы неподдерживаемыми. `project.supported_platforms` ограничивает платформы, принимаемые сборками и `run`; отсутствие списка или пустой список разрешает все платформы. Например, `supported_platforms: [darwin]` внутри `project` приводит к ранней ошибке в Linux для примера, предназначенного только для macOS.

## Поведение запуска на платформах

| Платформа | Поведение запуска |
| --- | --- |
| Linux и Windows | Запустите исполняемый файл с подключёнными стандартными потоками ввода-вывода, обработкой завершения и передачей кода завершения приложения. |
| macOS | Соберите пакет приложения и запустите находящийся в нём двоичный файл `Contents/MacOS` с подключёнными стандартными потоками ввода-вывода. Зарегистрируйте пакет в Launch Services для поддержки схем URL и ассоциаций файлов. Для принятия подписи и нативного жизненного цикла требуется проверка в macOS. |
| Android | Соберите APK, выберите устройство или эмулятор, установите и запустите приложение. Сообщайте об ошибках сборки, установки и запуска раздельно. |
| iOS | Соберите пакет приложения, выберите симулятор или устройство, выполните требования к подписи и профилю подготовки, затем установите и запустите приложение. Для сборки под устройство требуются соответствующие учётные данные и инструментарий Apple. |

Android отклоняет аргументы приложения и переопределения среды выполнения до развёртывания. Если также поддерживается Android, общие настройки, предназначенные только для настольных систем, следует указывать в сопоставлениях целей для настольных систем. При запуске на Android подключается вывод журналов приложения, а после отключения приложение останавливается. iOS передаёт аргументы выбранному средству запуска. Симуляторы получают переопределения среды через переменные `SIMCTL_CHILD_`, а физические устройства — в виде JSON-карты через `devicectl --environment-variables`. Код завершения на мобильных платформах описывает результат работы средства запуска или мониторинга журналов, а не переносимый код завершения приложения.

## Примеры только на Go и резервный режим

Для примера только на Go с уже существующими или встроенными ресурсами этапы работы с фронтендом отключаются:

```yaml
frontend:
  disabled: true
```

При этом пропускаются установка зависимостей фронтенда, генерация привязок и сборка фронтенда. В примерах, которым нужны сгенерированные классы привязок, вместо этого можно задать `interfaces: false` в разделе `frontend.bindings`.

Резервный режим без манифеста выполняет `go run [-tags <tags>] . [application arguments]`, не добавляя `production` или `devtools`. Код завершения обрабатывается по правилам самого Go. Аргументы после `--` передаются приложению, включая такие флаги, как `--help`. В значениях среды выполнения, которые показывает `--plan`, отображаются только имена ключей среды; сами значения не выводятся. План резервного режима показывает команду Go и рабочий каталог.

## Аргументы приложения при разработке

При активном проекте YAML команда `wails3 dev` принимает аргументы приложения независимо от значений по умолчанию `run` для рабочей сборки. `dev.args` задаёт общие значения по умолчанию; вложенное сопоставление `dev` в `targets["<os>"]` или `targets["<os>/<arch>"]` заменяет их для соответствующей цели. Настройки архитектуры имеют приоритет над общими настройками ОС независимо от порядка элементов в карте. Явно заданное `args: []` очищает унаследованные аргументы.

```yaml
dev:
  args: [--config-path, config/testing.yaml]
targets:
  windows:
    dev:
      args: [--config-path, config/testing-windows.yaml]
```

`run.args` и `run.tags` не влияют на запуски в режиме разработки. Существующая политика сборки `dev.tags` остаётся без изменений. Относительные пути приложения интерпретируются самим приложением относительно каталога манифеста.

```shell
wails3 dev
wails3 dev -- --config-path "profile with spaces.yaml"
wails3 dev --appargs='--config-path "profile with spaces.yaml"'
wails3 dev --
wails3 dev --plan
```

Аргументы после `--` заменяют настроенные аргументы, в том числе когда список пуст. `--help` после этого разделителя относится к приложению. `--appargs=""` также очищает значения по умолчанию. Параметр совместимости принимает одну строку в кавычках; его использование вместе с `--`, позиционными аргументами приложения или вторым `--appargs` является ошибкой. Некорректное использование кавычек отклоняется до запуска сеанса.

Парсер совместимости использует одинаковые правила заключения в кавычки в стиле POSIX на всех платформах. Он не выполняет команды оболочки и не раскрывает переменные; вызывающая оболочка могла уже раскрыть текст перед его передачей Wails. Аргументы после `--` уже являются отдельными значениями и не подвергаются дополнительной токенизации. Это предпочтительная форма для путей Windows, например в PowerShell:

```powershell
wails3 dev -- --config-path 'C:\Users\Example User\testing.yaml'
```

Сеанс сохраняет разрешённый вектор аргументов при пересборках исходного кода. Если изменить только `dev.args` или аргументы выбранной цели, бэкенд перезапустится с использованием кэшированного исполняемого файла, а фронтенд не будет перезапущен. Переопределения из CLI сохраняются после перезагрузки манифеста. При неудачной замене сохраняется или восстанавливается предыдущий исполняемый файл с прежними аргументами. Аргументы приложения не являются флагами компилятора и не входят в ключи кэша компиляции. `dev --plan` показывает итоговые аргументы вместе с конечным планом сборки, не выполняя запуск.

Linux, Windows и macOS передают вектор непосредственно исполняемому файлу. iOS передаёт его через средство запуска симулятора или устройства. Android отклоняет непустые аргументы приложения для режима разработки до поиска устройства или сборки, поскольку поддерживаемого эквивалентного канала передачи аргументов нет. Значения по умолчанию только для настольных систем можно поместить в сопоставления целей для настольных систем или очистить с помощью `args: []` в разделе `targets.android.dev`.

Для этих параметров разработки необходимы активный `wails.yaml` и явное включение в YAML. Они не переписывают команды оболочки Taskfile или средства наблюдения в устаревшем режиме разработки.
