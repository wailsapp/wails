В Wails v3 используется **M-Press**, который преобразует Markdown в этот сайт документации. Вы можете исправить опечатку, улучшить объяснение, добавить пример или руководство либо исправить перевод. Для исправлений, затрагивающих только документацию, не требуется заранее создавать задачу или получать ошибку в тесте кода.

Чтобы подготовить изменения, вам понадобится Git, а чтобы отправить pull request — учётная запись GitHub. Загружаемый исполняемый файл M-Press содержит генератор документации и средство отрисовки диаграмм; для предварительного просмотра документации не нужны Go, Node.js, Wails CLI или зависимости для сборки настольных приложений. Для дополнительных скриптов проверки репозитория требуется Python 3.

## Начните со страницы документации

На боковой панели откройте **Участие в проекте → Документация**, чтобы перейти к этому руководству. Чтобы поработать над определённой страницей, нажмите **значок редактирования** в её заголовке, а затем выберите **Редактировать эту страницу локально**. Скопируйте команду для своей операционной системы и выполните её в терминале.

Команда использует M-Press, если он установлен; в противном случае установщик загружает официальный выпуск и проверяет контрольную сумму. Он подготавливает локальную рабочую копию для внесения изменений и открывает выбранную страницу в M-Press. Перед запуском проверок репозитория сверьте `mpress version` с закреплённой ниже версией: автоматический установщик может загрузить более новый выпуск.

Вы можете редактировать исходный файл в своём редакторе, пока локальный предварительный просмотр автоматически пересобирается. Мастер также предлагает отдельные действия: **Просмотреть изменения**, **Зафиксировать изменения**, **Отправить ветку с изменениями** и **Открыть черновик pull request**. Перед отправкой выполните проверки и следуйте приведённым ниже рекомендациям по pull request. Генерация переводов необязательна и может требовать настроенного поставщика услуг; для редактирования и предварительного просмотра Markdown он не нужен.

Для воспроизводимой ручной настройки выполните следующие действия.

## Скачайте и установите M-Press

Скрипт сборки репозитория загружает **последний стабильный выпуск M-Press**. Используйте тот же выпуск локально: выберите ниже способ установки, выполните команду `mpress version` и сравните указанную версию с версией на странице выпуска.

### Скачайте исполняемый файл

Откройте страницу [последнего стабильного выпуска M-Press](https://github.com/leaanthony/mpress/releases/latest) или загрузите ниже соответствующий архив. ARM64 включает Apple Silicon, а AMD64 — это распространённая архитектура ПК на базе Intel/AMD.

| Компьютер | AMD64 / Intel | ARM64 / Apple Silicon |
| --- | --- | --- |
| macOS | [mpress-darwin-amd64.tar.gz](https://github.com/leaanthony/mpress/releases/latest/download/mpress-darwin-amd64.tar.gz) | [mpress-darwin-arm64.tar.gz](https://github.com/leaanthony/mpress/releases/latest/download/mpress-darwin-arm64.tar.gz) |
| Linux | [mpress-linux-amd64.tar.gz](https://github.com/leaanthony/mpress/releases/latest/download/mpress-linux-amd64.tar.gz) | [mpress-linux-arm64.tar.gz](https://github.com/leaanthony/mpress/releases/latest/download/mpress-linux-arm64.tar.gz) |
| Windows | [mpress-windows-amd64.zip](https://github.com/leaanthony/mpress/releases/latest/download/mpress-windows-amd64.zip) | [mpress-windows-arm64.zip](https://github.com/leaanthony/mpress/releases/latest/download/mpress-windows-arm64.zip) |

Загрузите файл [checksums.txt](https://github.com/leaanthony/mpress/releases/latest/download/checksums.txt) из того же выпуска. В каталоге загрузки вычислите SHA-256-хеш архива и сравните его со строкой для этого имени файла в `checksums.txt`:

@tabs
[macOS]
```sh
shasum -a 256 mpress-darwin-arm64.tar.gz
```

[Linux]
```sh
sha256sum mpress-linux-amd64.tar.gz
```

[Windows PowerShell]
```powershell
Get-FileHash .\mpress-windows-amd64.zip -Algorithm SHA256
```
@end

Если вы выбрали другую архитектуру, укажите фактическое имя скачанного файла. Убедившись, что хеши совпадают, распакуйте и установите исполняемый файл:

@tabs
[macOS]
Выполните следующую команду из каталога загрузок, используя архив для Apple Silicon:

```sh
mkdir -p mpress-download
tar -xzf mpress-darwin-arm64.tar.gz -C mpress-download
mkdir -p "$HOME/.local/bin"
install -m 755 mpress-download/mpress "$HOME/.local/bin/mpress"
export PATH="$HOME/.local/bin:$PATH"
mpress version
```

На компьютерах Mac с процессором Intel подставьте `mpress-darwin-amd64.tar.gz`. Добавьте строку `export PATH` в `~/.zshrc`, чтобы команда была доступна в новых терминалах.

[Linux]
Выполните следующую команду из каталога загрузок:

```sh
mkdir -p mpress-download
tar -xzf mpress-linux-amd64.tar.gz -C mpress-download
mkdir -p "$HOME/.local/bin"
install -m 755 mpress-download/mpress "$HOME/.local/bin/mpress"
export PATH="$HOME/.local/bin:$PATH"
mpress version
```

Для ARM64 подставьте `mpress-linux-arm64.tar.gz`. Добавьте строку `export PATH` в файл запуска своей командной оболочки, например `~/.bashrc`, чтобы команда была доступна в новых терминалах.

[Windows PowerShell]
Выполните следующую команду из каталога загрузок:

```powershell
Expand-Archive .\mpress-windows-amd64.zip -DestinationPath .\mpress-download
New-Item -ItemType Directory -Force "$HOME\bin"
Copy-Item .\mpress-download\mpress.exe "$HOME\bin\mpress.exe"
$env:Path = "$HOME\bin;$env:Path"
mpress version
```

Для ARM64 подставьте `mpress-windows-arm64.zip`. Чтобы команда оставалась доступной в последующих сеансах, добавьте пользовательский каталог `bin` в пользовательскую переменную **Path** в разделе Windows **Переменные среды**, а затем заново откройте терминал.
@end

### Установите с помощью Go

Если вы уже используете Go, вместо этого можно собрать последний стабильный выпуск. Проверьте требования к инструментарию в его файле `go.mod`; функция автоматического выбора инструментария Go может загрузить необходимую версию. Для выпуска, использованного при подготовке этой версии документации, требуется Go 1.26.10 или новее.

```sh
go install github.com/leaanthony/mpress/cmd/mpress@latest
mpress version
```

Go устанавливает команду в `GOBIN` либо, если `GOBIN` не задана, в каталог `bin` внутри `go env GOPATH`. Если `mpress` не найдена, добавьте этот каталог в `PATH` и заново откройте терминал.

## Получите исходные файлы документации

[Создайте форк wailsapp/wails](https://github.com/wailsapp/wails/fork), затем выполните следующие команды, заменив `YOUR_USERNAME` своим именем пользователя GitHub:

```sh
git clone https://github.com/YOUR_USERNAME/wails.git
cd wails
git remote add upstream https://github.com/wailsapp/wails.git
git fetch upstream master
git switch -c docs/my-change upstream/master
```

В результате ветка для работы над документацией будет создана на основе вышестоящей ветки **master**. Вместо `docs/my-change` укажите собственное содержательное имя ветки.

## Запустите предварительный просмотр в реальном времени

В корневом каталоге репозитория Wails, где находится `mpress.yaml`, выполните:

```sh
mpress dev
```

Откройте [http://127.0.0.1:3000](http://127.0.0.1:3000) в браузере. Чтобы открыть это руководство, перейдите по адресу [http://127.0.0.1:3000/contributing/documentation/](http://127.0.0.1:3000/contributing/documentation/). Не останавливайте команду во время редактирования: после сохранения изменений в исходных файлах предварительный просмотр пересобирается. Прежде чем запускать приведённые ниже команды проверки, остановите процесс сочетанием клавиш **Ctrl+C**.

В репозитории уже есть конфигурация M-Press. Инициализировать новый сайт не нужно. Чтобы использовать другой порт, выполните `mpress dev --port 3001` и откройте соответствующий локальный адрес.

## Отредактируйте или добавьте страницу

Исходные страницы на английском языке находятся в `docs/mpress/content/`. Переводы находятся в каталогах соответствующих языков, например `fr/` и `id/`. В инструкциях по внесению изменений, доступных по значку редактирования, указан исходный файл текущей страницы.

Для существующей страницы отредактируйте её Markdown-разметку, сохранив метаданные YAML в верхней части файла. Используйте заголовки, абзацы, списки, ссылки и ограждённые блоки кода. Сохраняйте парные компоненты M-Press, такие как `@note` / `@end` и `@tabs` / `@end`. Поддерживаемый синтаксис описан в [документации по созданию материалов в M-Press](https://m-press.me/authoring/).

Для нового руководства создайте файл, например `docs/mpress/content/guides/my-guide.md`:

```markdown
---
title: "My guide"
description: "The task this guide helps someone complete."
slug: "guides/my-guide"
sourcePath: "guides/my-guide.md"
---

Explain the task, give working steps, and show the expected result.
```

Добавьте страницу в соответствующий раздел файла `docs/mpress/content/_nav.yaml`, если только в этом разделе уже не используется `autogenerate`. Убедитесь, что читатель может перейти к ней через навигацию и ссылки на связанных страницах. Для новых страниц на английском языке также требуются полные копии для всех локалей, иначе проверки покрытия не пройдут; согласуйте их подготовку с сопровождающими или участниками, работающими над переводами.

Сгенерированные файлы находятся в `docs/mpress/site/`. Зафиксируйте исходные страницы и все предусмотренные изменения навигации или статических ресурсов; сгенерированные файлы сайта и локальные кеши не должны попадать в pull request.

## Проверьте свои изменения

В корневом каталоге репозитория выполните:

```sh
python3 docs/mpress/scripts/check_translations.py
mpress build --strict --no-purge-css
mpress check
python3 docs/mpress/scripts/check_site.py docs/mpress/site
```

В Windows используйте `python`, если Python 3 установлен именно так. Если [Task](https://taskfile.dev/) уже установлен, `task docs:build` запускает те же проверки с `mpress` из PATH.

Проверка переводов завершается с ошибкой, если файлы переводов отсутствуют, пусты или не соответствуют ни одному исходному файлу. По умолчанию об устаревших или повреждённых переведённых фрагментах сообщается в виде предупреждений; при использовании `--strict` такие проблемы также приводят к ошибке проверки. Изменение существующего английского текста можно отправить, не дожидаясь синхронизации переводов. При исправлении одного перевода можно изменить только соответствующий язык. Не изменяйте команды, имена API, ссылки, примеры кода и связи на диаграммах; не используйте английский текст-заполнитель в качестве переведённого содержимого.

Прочитайте изменённую страницу в браузере и запустите все изменённые вами примеры кода. Если проверка завершается с ошибкой на странице, которую вы не изменяли, добавьте вывод команды и соответствующий контекст в PR вместо того, чтобы ослаблять проверку.

## Отправка запроса на включение изменений

Проверьте различия, зафиксируйте изменения исходных файлов и отправьте ветку с вашими изменениями в свой форк. Откройте PR в `wailsapp/wails` для ветки **master**. Опишите изменения, добавьте ссылку на затронутую страницу и перечислите выполненные проверки. Для изменений макета приложите снимки экрана до и после, а для изменённых примеров кода укажите платформу и версию.

Рабочий сайт является статическим; для локального предварительного просмотра и проверки не требуются учётные данные для развёртывания или поставщик услуг перевода. После проверки публикацию выполняют сопровождающие проекта.

Сведения о внесении изменений в код и предложении новых функций см. в разделе [«Участие в разработке Wails»](/contributing/). Сведения о внутреннем устройстве фреймворка см. в разделе [«Технический обзор»](/contributing/overview/).
