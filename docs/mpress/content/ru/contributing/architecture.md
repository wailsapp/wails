Wails v3 — это **фреймворк для разработки клиентской и серверной частей настольных приложений**, состоящий из среды выполнения Go, моста JavaScript, управляемой задачами цепочки инструментов и набора шаблонов, которые позволяют выпускать нативные приложения на основе современных веб-технологий.

На этой странице *общая картина* представлена на четырёх схемах:

1. **Общая архитектура** — как связаны все подсистемы\
2. **Поток вызовов среды выполнения** — что происходит, когда JS вызывает Go и наоборот\
3. **Разработка и рабочая среда** — два режима сервера ресурсов\
4. **Платформенные реализации** — где находится код для конкретных ОС\

Ключевые моменты:

## 4 · Разделение среды выполнения по платформам

**Файлы среды выполнения для каждой ОС**

**[Место для схемы разделения по платформам]**

Каждая функция реализована по следующей схеме:

1. **Общий интерфейс** в `pkg/application`\
2. **Точка входа обработчика сообщений** в `pkg/application/messageprocessor_*.go`\
3. **Реализация для каждой ОС** в `pkg/application/*_{darwin,linux,windows}.go` (например, `webview_window_darwin.go`, `clipboard_linux.go`, `dialogs_windows.go`, `systemtray_*.go`, `mainthread_*.go`), защищённая тегами сборки. В Linux также имеется мост cgo в `linux_cgo.go` / `linux_cgo_gtk4.{go,c,h}`.

`internal/runtime/` содержит только небольшой связующий код `runtime{_darwin,_linux,_windows,_android,_dev,_prod}.go` с тегами сборки, а также встроенную среду выполнения JS в `internal/runtime/desktop/`.

`internal/capabilities/` предназначен для объявления наборов возможностей каждой платформы, но сентинела `ErrCapability` нет: доступность функций регулируется обычными тегами сборки и возвращаемыми значениями платформенных заглушек (например, `nil` или ошибками конкретных функций).
