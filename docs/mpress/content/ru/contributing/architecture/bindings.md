В этом руководстве описано внутреннее устройство системы привязок Wails. Оно поможет разработчикам понять механизмы автоматической генерации кода.

## Обзор архитектуры

Система привязок Wails состоит из трёх основных компонентов:

1. **Сбор данных**: анализирует код Go и извлекает сведения о сервисах, моделях и других объявлениях
2. **Конфигурация**: управляет настройками и параметрами процесса генерации привязок
3. **Рендеринг**: генерирует код JavaScript/TypeScript на основе собранных сведений

@filetree
- internal/generator/
  - collect/     # Анализ пакетов и извлечение сведений
  - config/      # Структуры и интерфейсы конфигурации
  - render/      # Генерация кода JS/TS
@end

## Процесс сбора данных

Процесс сбора данных отвечает за анализ пакетов Go и извлечение сведений о сервисах, моделях и других объявлениях. Эту задачу выполняет пакет `collect`.

### Основные компоненты

- **Collector**: управляет сведениями о пакетах и кэширует собранные данные
- **Package**: представляет анализируемый пакет Go и хранит собранные сервисы, модели и директивы
- **Service**: собирает сведения о типах сервисов и их методах
- **Model**: собирает подробные сведения о типах моделей, включая поля, значения и параметры типов
- **Directive**: разбирает и интерпретирует директивы `//wails:` в исходном коде Go

### Последовательность сбора данных

1. Сборщик сканирует пакеты Go, указанные в проекте
2. Он определяет типы сервисов (структуры с методами, которые будут доступны клиентской части)
3. Для каждого сервиса он собирает сведения о его методах
4. Он определяет типы моделей (структуры, используемые как параметры или возвращаемые значения методов сервисов)
5. Для каждой модели он собирает сведения о её полях и параметрах типов
6. Он обрабатывает все найденные в коде директивы `//wails:`

## Процесс рендеринга

Процесс рендеринга отвечает за генерацию кода JavaScript/TypeScript на основе собранных сведений. Эту задачу выполняет пакет `render`.

### Основные компоненты

- **Renderer**: координирует рендеринг файлов сервисов, моделей и индексных файлов
- **Module**: представляет отдельный сгенерированный модуль JavaScript/TypeScript
- **Templates**: текстовые шаблоны, используемые для генерации кода

### Последовательность рендеринга

1. Для каждого сервиса средство рендеринга генерирует файл JavaScript/TypeScript с функциями, соответствующими методам сервиса
2. Для каждой модели средство рендеринга генерирует класс JavaScript/TypeScript, соответствующий структуре модели
3. Средство рендеринга генерирует индексные файлы, которые повторно экспортируют все сервисы и модели
4. Средство рендеринга применяет все пользовательские вставки кода, заданные директивами `//wails:inject`

## Сопоставление типов

Один из важнейших аспектов системы привязок — сопоставление типов Go с типами JavaScript/TypeScript. Ниже приведена сводная таблица сопоставлений:

| Тип Go | Тип JavaScript | Тип TypeScript |
| --- | --- | --- |
| `bool` | `boolean` | `boolean` |
| `int`, `int8`, `int16`, `int32`, `int64`, `uint`, `uint8`, `uint16`, `uint32`, `uint64`, `float32`, `float64` | `number` | `number` |
| `string` | `string` | `string` |
| `[]byte` | `Uint8Array` | `Uint8Array` |
| `[]T` | `Array<T>` | `T[]` |
| `map[string]V` | `Object` | `{ [_: string]: V }` |
| `map[K]V` (нестроковый `K`) | `Object` | `{ [_ in K]?: V }` |
| `struct` | `Object` | Пользовательский класс |
| `interface{}` | `any` | `any` |
| `*T` | `T \| null` | `T \| null` |
| `func` | Не поддерживается | Не поддерживается |
| `chan` | Не поддерживается | Не поддерживается |

## Система директив

Система привязок поддерживает несколько директив для настройки генерируемого кода. Эти директивы добавляются в код Go в виде комментариев.

### Доступные директивы

- `//wails:inject`: внедряет пользовательский код JavaScript/TypeScript в сгенерированные привязки
- `//wails:include`: включает дополнительные файлы в сгенерированные привязки
- `//wails:internal`: помечает тип или метод как внутренний, предотвращая его экспорт во фронтенд
- `//wails:ignore`: полностью исключает метод из процесса генерации привязок
- `//wails:id`: задаёт пользовательский идентификатор метода вместо стандартного идентификатора на основе хеша

### Обработка директив

1. На этапе сбора коллектор обнаруживает и разбирает директивы в коде Go
2. Директивы сохраняются вместе с соответствующими объявлениями (сервисами, методами, моделями и т. д.)
3. На этапе рендеринга средство рендеринга применяет директивы для настройки генерируемого кода

## Расширенные возможности

### Условная генерация кода

Система привязок поддерживает условную генерацию кода с помощью двухсимвольного префикса условия для директив `include` и `inject`:

```
<language><style>:<content>
```

Где:

- `<language>` может принимать следующие значения:
  - `*` — JavaScript и TypeScript
  - `j` — только JavaScript
  - `t` — только TypeScript


- `<style>` может принимать следующие значения:
  - `*` — классы и интерфейсы
  - `c` — только классы
  - `i` — только интерфейсы


Например:

```go
//wails:inject j*:console.log("JavaScript only");
//wails:inject t*:console.log("TypeScript only");
```

### Пользовательские идентификаторы методов

По умолчанию методы идентифицируются с помощью идентификатора на основе хеша. Однако директива `//wails:id` позволяет задать пользовательский идентификатор:

```go
//wails:id 42
func (s *Service) CustomIDMethod() {}
```

Это может быть полезно для сохранения совместимости при рефакторинге кода.

## Аспекты производительности

Генератор привязок спроектирован с расчётом на эффективную работу, однако следует учитывать несколько моментов:

1. Первый запуск будет медленнее, поскольку при нём создаётся кеш пакетов для сканирования
2. Последующие запуски будут быстрее благодаря использованию кешированных данных
3. Генератор обрабатывает все пакеты проекта, что в крупных проектах может занимать много времени
4. Чтобы очистить каталог вывода перед генерацией, используйте флаг `-clean`

## Отладка

Если при генерации привязок возникают проблемы, включите отладочный вывод с помощью флага `-v`:

```bash
wails3 generate bindings -v
```

В результате будет выведена подробная информация о процессах сбора и рендеринга, которая может помочь определить источник проблемы.
