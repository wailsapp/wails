**Среда выполнения** — это слой, который превращает обычные функции Go в кроссплатформенное настольное приложение. В этом документе описаны компоненты, с которыми вы столкнётесь при изучении исходного кода.

---

## 1. Жизненный цикл приложения

| Этап | Путь выполнения кода | Что происходит |
| --- | --- | --- |
| **Начальная загрузка** | `pkg/application/application.go:init()` | Регистрирует данные времени сборки и создаёт глобальный одиночный экземпляр `application`. |
| **New()** | `application.New(...)` | Проверяет `Options`, запускает **AssetServer** и инициализирует журналирование. |
| **Run()** | `application.(*App).Run()` | 1. Вызывает платформенную функцию `mainthread.X()` для перехода в поток пользовательского интерфейса ОС.<br />2. Запускает **среду выполнения** (`internal/runtime`).<br />3. Блокирует выполнение до закрытия последнего окна или вызова `Quit()`. |
| **Завершение работы** | `application.(*App).Quit()` | Рассылает событие `application:shutdown`, записывает накопленные данные журнала и завершает работу окон и служб. |

Жизненный цикл предусматривает строго **однократный вход**: можно создать множество окон, но сам объект приложения инициализируется только один раз.

## 2. Управление окнами

### Открытый API

```go
win := app.Window.NewWithOptions(application.WebviewWindowOptions{
    Title:  "Dashboard",
    Width:  1280,
    Height: 720,
})
win.Show()
```

> `app.Window.New()` вызывается **без аргументов**; используйте `NewWithOptions(...)`, если
>
> нужно передать структуру `application.WebviewWindowOptions` по значению.

`app.Window.New[WithOptions]()` делегирует работу `pkg/application/webview_window_*.go`, где находятся платформенные реализации:

```
pkg/application/
├── webview_window_darwin.go    // WKWebView
├── webview_window_linux.go     // GTK + WebKitGTK (plus linux_cgo*.go)
└── webview_window_windows.go   // WebView2
```

Каждый файл выполняет следующие действия:

1. Создаёт нативное веб-представление (WKWebView, WebKitGTK, WebView2).
2. Регистрирует обратный вызов **обработчика сообщений** (`pkg/application/messageprocessor*.go`).
3. Сопоставляет события Wails (`WindowDidResize`, `WindowFocus`, `WindowFilesDropped`, …) с константами в `pkg/events`.

`internal/runtime/` предназначен для небольшого связующего кода с тегами сборки (`runtime{,_darwin,_linux,_windows,_android,_dev,_prod}.go`) и встроенной среды выполнения JS в `internal/runtime/desktop/`.

Активные окна отслеживаются с помощью `pkg/application/window_manager.go` / `webview_window.go`. `pkg/application/screenmanager.go` содержит метаданные **дисплея** (разрешение, масштаб, рабочая область) и не управляет окнами.

## 3. Конвейер обработки сообщений

Мост между JavaScript и Go реализован семейством **обработчиков сообщений** в `pkg/application/messageprocessor_*.go`.

Последовательность:

1. **JavaScript** вызывает `Call.ByID(<fnv-id>, ...args)` из `/wails/runtime.js` (реализовано в `internal/runtime/desktop/@wailsio/runtime/src/calls.ts`) либо `Call.ByName("pkg.Struct.Method", ...args)` для сборок в режиме имён.
2. Вспомогательный код среды выполнения упаковывает вызов и передаёт его в Go через нативный мост соответствующей платформы.
3. **Go** получает сообщение в `pkg/application/messageprocessor_call.go`.
4. Обработчик находит привязанный метод в `pkg/application/bindings.go` (написанном вручную и основанном на `reflect`) и вызывает его.
5. Результат или ошибка сериализуется и возвращается в JS, где `Promise` переходит в выполненное или отклонённое состояние.

> Точная структура JSON-конверта определяется вспомогательным кодом среды выполнения на стороне JS и
>
> `messageprocessor_call.go` на стороне Go. В прежних версиях этой страницы
>
> приводилась структура `{"t":"c","id":"123","m":"Greet","p":[…]}`, однако она не
>
> соответствует текущей реализации. При поиске ошибки в формате обмена данными изучайте оба файла
>
> вместе.

Специализированные обработчики:

| Файл | Назначение |
| --- | --- |
| `messageprocessor_window.go` | Действия с окном (скрытие, разворачивание, …) |
| `messageprocessor_dialog.go` | Нативные диалоговые окна (`OpenFile`, `MessageBox`, …) |
| `messageprocessor_clipboard.go` | Чтение и запись буфера обмена |
| `messageprocessor_events.go` | Подписка на события и их отправка |
| `messageprocessor_browser.go` | Навигация в браузере, инструменты разработчика |

Обработчики не сохраняют **состояние**: все необходимые данные они получают из `ApplicationContext`, передаваемого с каждым сообщением.

## 4. Система событий

События представляют собой строки с пространствами имён, которые передаются через три уровня:

1. **События приложения**: глобальный жизненный цикл (`application:ready`, `application:shutdown`).
2. **События окон**: относятся к отдельным окнам (`window:focus`, `window:resize`).
3. **Пользовательские события**: определяются пользователем (`chat:new-message`).

Детали реализации:

- Константы событий находятся в `pkg/events/` (`defaults.go`, `known_events.go`, `events.txt`). Они генерируются с помощью `v3/tasks/events/generate.go` и предоставляются как `events.Common.*`, `events.Mac.*`, `events.Windows.*`, `events.Linux.*`. Перегенерировать их можно с помощью `wails3 generate constants`.
- На стороне Go (события приложения):
  ```go
  app.Event.OnApplicationEvent(events.Common.ApplicationStarted, func(e *application.ApplicationEvent) {})
  ```

- На стороне Go (события окон):
  ```go
  window.OnWindowEvent(events.Common.WindowFocus, func(e *application.WindowEvent) {})
  ```

- На стороне Go (пользовательские события):
  ```go
  app.Event.On("chat:new-message", func(e *application.CustomEvent) {})
  ```

- На стороне JS:
  ```js
  import { Events } from "/wails/runtime.js";
  Events.On("chat:new-message", (e) => { /* … */ });
  ```


События приложения, окон и пользовательские события проходят через `pkg/application/event_manager.go`. Подписки на события окна действуют только в пределах этого окна, поэтому при его закрытии обработчики автоматически отменяют регистрацию.

## 5. Реализации для отдельных платформ

Условная компиляция позволяет сохранить единый публичный API, скрывая особенности ОС.

| Аспект | Darwin | Linux | Windows |
| --- | --- | --- | --- |
| Главный поток | `mainthread_darwin.go` (Cgo для взаимодействия с Foundation) | `mainthread_linux.go` (GTK) | `mainthread_windows.go` (Win32 `AttachThreadInput`) |
| Диалоговые окна | `dialogs_darwin.*` (NSAlert) | `dialogs_linux.go` (GtkFileChooser) | `dialogs_windows.go` (IFileOpenDialog) |
| Буфер обмена | `clipboard_darwin.go` | `clipboard_linux.go` | `clipboard_windows.go` |
| Значки в области уведомлений | `systemtray_darwin.*` | `systemtray_linux.go` (DBus) | `systemtray_windows.go` (Shell_NotifyIcon) |

Основные принципы:

- **macOS и Windows** используют Cgo лишь в отдельных случаях (в основном через `pkg/mac/` и обёртки Win32 `w32` в `pkg/w32`).
- **Linux интенсивно использует Cgo** в силу необходимости: `pkg/application/linux_cgo.go` (~69 КБ) и `linux_cgo_gtk4.{c,go,h}` (~50 КБ и более) напрямую управляют GTK/WebKitGTK.
- Используйте **теги сборки** (`//go:build darwin`, `//go:build linux`, …), чтобы файлы для отдельных ОС оставались удобочитаемыми.
- `internal/capabilities/` предназначен для флагов возможностей отдельных платформ, однако фреймворк **не** экспортирует маркер `ErrCapability` — доступность функций определяется возвращаемыми значениями платформозависимых заглушек.

## 6. Справочник по файлам

| Файл | Когда его следует изменять |
| --- | --- |
| `internal/runtime/runtime_*.go` | Изменить небольшой слой заглушек с тегами сборки (разработка и продакшен, платформозависимый связующий код). |
| `pkg/application/webview_window_*.go` | Реализовать новый параметр для оконного менеджера или новое поведение окна. |
| `pkg/application/messageprocessor*.go` | Добавить новую команду моста, которую можно вызывать из JS. |
| `pkg/events/*.go` | Расширить определения встроенных событий (затем снова выполнить `wails3 generate constants`). |
| `internal/assetserver/*` | Скорректировать обработку ресурсов в режиме разработки или продакшена. |
| `internal/runtime/desktop/@wailsio/runtime/src/*` | Изменить встроенную среду выполнения JS (диспетчеризация вызовов и событий, диалоговые окна, перетаскивание и т. д.). |

## 7. Советы по отладке

- Настройте `Options.LogLevel` (например, `slog.LevelDebug`) и проверьте вывод `Options.Logger` — переменной окружения `WAILS_LOG_LEVEL` не существует.
- Доступны флаги `wails3 dev`: `--config`, `--port`, `-s` (включает HTTPS), а также глобальный `--no-colour`. Флага `-verbose` не существует.
- В macOS запускайте приложение под управлением `lldb --`, чтобы как можно раньше обнаруживать исключения Objective-C.
- Для диагностики проблем Chromium в Windows включите журналы отладки WebView2: `set WEBVIEW2_ADDITIONAL_BROWSER_ARGUMENTS=--remote-debugging-port=9222`

## 8. Расширение среды выполнения

1. Необязательно: объявите новый флаг возможности в `internal/capabilities/`.
2. Реализуйте функцию в каждом варианте `pkg/application/*_{darwin,linux,windows}.go` с помощью тегов сборки. Для платформ, которые её не поддерживают, предусмотрите заглушку.
3. Добавьте публичный API в `pkg/application` (интерфейс и конкретные методы `WebviewWindow`, структуру параметров и т. д.).
4. Зарегистрируйте новый метод обработчика сообщений (`pkg/application/messageprocessor*.go`) и, если его нужно вызывать из JS, добавьте соответствующую вспомогательную функцию в среду выполнения JS.
5. Если вы добавляете событие, объявите его константу в `pkg/events/` и выполните `wails3 generate constants`, чтобы обновить сгенерированные файлы.

Следуйте этому контрольному списку, чтобы сохранить целостность кроссплатформенного контракта.

## 9. Перетаскивание

На всех платформах перетаскивание файлов реализовано с **приоритетом JavaScript**. Нативный слой перехватывает события перетаскивания ОС, но непосредственная обработка сброса и взаимодействие с DOM выполняются в JavaScript.

### Порядок выполнения

1. Пользователь перетаскивает файлы из ОС в окно Wails
2. Нативный слой обнаруживает перетаскивание и уведомляет JavaScript для отображения эффектов при наведении
3. Пользователь сбрасывает файлы
4. Нативный слой передаёт пути к файлам и координаты в JavaScript
5. JavaScript находит целевой элемент для сброса (`data-file-drop-target`)
6. JavaScript передаёт пути к файлам и сведения об элементе серверной части на Go
7. Go генерирует событие `WindowFilesDropped` с полным контекстом

### Реализации для разных платформ

| Платформа | Нативный слой | Основная сложность |
| --- | --- | --- |
| **Windows** | Встроенная поддержка перетаскивания в WebView2 | Координаты в CSS-пикселях, преобразование не требуется |
| **macOS** | Делегаты перетаскивания NSWindow | Преобразование координат относительно окна в координаты относительно webview |
| **Linux** | Сигналы перетаскивания GTK3 | Необходимо отличать перетаскивание файлов от внутреннего перетаскивания HTML5 |

### Linux: различение типов перетаскивания

И GTK, и WebKit пытаются обрабатывать события перетаскивания. Главное — проверять тип цели перетаскивания:

```c
static gboolean is_file_drag(GdkDragContext *context) {
    GList *targets = gdk_drag_context_list_targets(context);
    for (GList *l = targets; l != NULL; l = l->next) {
        GdkAtom atom = GDK_POINTER_TO_ATOM(l->data);
        gchar *name = gdk_atom_name(atom);
        if (name && g_strcmp0(name, "text/uri-list") == 0) {
            g_free(name);
            return TRUE;  // External file drag
        }
        g_free(name);
    }
    return FALSE;  // Internal HTML5 drag
}
```

Обработчики сигналов возвращают `FALSE` для внутренних перетаскиваний, позволяя WebKit обработать их, и `TRUE` для перетаскиваний файлов, обрабатывая их самостоятельно.

### Блокировка сброса файлов

Когда `EnableFileDrop` имеет значение `false`, всё равно необходимо запретить браузеру переходить к сброшенным файлам. На каждой платформе это реализовано по-разному:

- **Windows**: JavaScript вызывает `preventDefault()` при событиях перетаскивания
- **macOS**: JavaScript вызывает `preventDefault()` при событиях перетаскивания\
- **Linux**: обработчики сигналов GTK перехватывают и отклоняют перетаскивание файлов на нативном уровне

### Основные файлы

| Файл | Назначение |
| --- | --- |
| `pkg/application/linux_cgo.go` | Обработчики сигналов перетаскивания GTK (код C в преамбуле cgo) |
| `pkg/application/webview_window_darwin.go` | Делегаты перетаскивания macOS |
| `pkg/application/webview_window_windows.go` | Обработка сообщений WebView2 |
| `internal/runtime/desktop/@wailsio/runtime/src/window.ts` | Обработка сброса в JavaScript |

### Отладка

- **Linux**: добавьте `printf` в код C (не забудьте про `fflush(stdout)`)
- **Windows**: используйте `globalApplication.debug()`
- **JavaScript**: проверьте консоль браузера и включите режим отладки

Распространённые проблемы:

1. **Внутреннее перетаскивание HTML5 не работает**: его перехватывает нативный обработчик (возвращайте `FALSE` для перетаскиваний не файлов)
2. **Эффекты при наведении не отображаются**: обработчики JavaScript не вызываются
3. **Неверные координаты**: проверьте преобразования систем координат

---

Теперь вы ознакомились с внутренним устройством среды выполнения. Используйте эти знания вместе со схемой **структуры кодовой базы** и документацией по **серверу ресурсов**, чтобы уверенно ориентироваться в проекте и вносить значимый вклад. Успешной разработки!
