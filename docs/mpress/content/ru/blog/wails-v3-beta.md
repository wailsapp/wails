Сегодня мы выпускаем Wails v3 Beta.

Wails позволяет разработчикам на Go создавать настольные приложения с помощью уже знакомых им инструментов веб-разработки для фронтенда, используя нативный WebView каждой платформы вместо встроенного браузера. v3 — это значительный шаг вперёд: приложения получают более прямой API, более понятную модель сборки и лучшую основу для настольных приложений, поддержку которых пользователи давно ожидают от Wails.

Это бета-версия, а не окончательный выпуск 3.0. API для настольных приложений стабилен, и некоторые команды уже используют v3 в рабочей среде, но перед развёртыванием следует провести тщательное тестирование. В течение бета-периода мы вместе с сообществом выявляем последние проблемы совместимости и рабочих процессов. Wails v2 остаётся текущей стабильной версией и продолжит получать исправления.

## Документация в течение бета-периода

В течение бета-периода мы поддерживаем английскую документацию как основной достоверный источник, пока API и рабочие процессы проходят окончательную проверку. На этом этапе мы не принимаем PR с переводами. Работа над переводами возобновится до выхода общедоступной версии, когда документация станет достаточно стабильной, чтобы переводчикам не приходилось постоянно переделывать её вслед за изменениями.

## Что входит в v3

- Явные API приложения и окон, включая полноценную поддержку нескольких окон
- Сервисы Go со статическим анализом исходного кода, который создаёт более информативные привязки TypeScript, сохраняя комментарии и осмысленные имена параметров
- Сервисы, способные объединять ресурсы и скрипты фронтенда со своим API бэкенда, — основа для устанавливаемых и более функциональных плагинов
- Открытая система сборки на основе Taskfile, которую можно изучать, расширять и отлаживать
- Серверные сборки для запуска того же приложения и сервисов без нативного окна настольного приложения
- Поддержка современных настольных систем macOS, Windows и Linux на Intel, Apple Silicon, amd64 и arm64 там, где эти архитектуры поддерживаются
- Экспериментальная поддержка мобильных платформ iOS и Android, доступная для ознакомления, но не охватываемая гарантиями совместимости бета-версии для настольных систем

## Зачем нужен v3

Wails v2 упростил создание приложений на Go с современным веб-фронтендом. Он хорошо служил проекту и множеству приложений. Однако его однооконная среда выполнения, основанная на контексте, и жёстко управляемый процесс сборки излишне усложняли некоторые распространённые задачи разработки настольных приложений.

В основе v3 лежит другая модель. Приложения, окна, сервисы, события и возможности платформы представлены явными объектами. Благодаря этому по мере роста приложения становится проще понимать работу фреймворка, а такие возможности, как несколько окон, становятся обычной частью модели приложения, а не обходным решением.

## Что нового

### API приложения, созданный для полноценных настольных программ

В v3 стиль конфигурации v2 `wails.Run(...)` заменён явным жизненным циклом приложения. Вы создаёте приложение, регистрируете сервисы, создаёте окна и взаимодействуете с объектами, которым принадлежит необходимое вам поведение.

Это устраняет значительную часть неявной передачи контекста. Операции с окнами принадлежат окнам, а операции уровня всего приложения — приложению. Такая модель естественнее для многооконных приложений и лучше подходит для тестирования и сопровождения крупных кодовых баз.

Отзывы пользователей v3 в период альфа-тестирования были исключительно положительными. Особенно хорошо разработчики приняли явную модель: код стало проще читать, принадлежность операций стала понятнее, а сложные настольные приложения получили возможность расти, не вступая в противоречие с фреймворком.

### Полноценная поддержка нескольких окон

Работа с несколькими окнами — одна из основных возможностей v3. Каждое окно имеет собственный жизненный цикл; окна можно создавать, контролировать и закрывать во время выполнения. Это упрощает создание настольных программ, которым требуются редакторы, инспекторы, окна настроек, панели инструментов или несколько независимых частей пользовательского интерфейса.

### Сервисы и создаваемые привязки

Сервисы Go заменяют прежнюю модель привязок. Они позволяют оставить логику приложения в виде обычного кода Go и явно обозначить границу с фронтендом. Привязки создаются в структуре, отражающей приложение и его сервисы, поэтому API, предоставленный фронтенду, проще находить и использовать.

В v3 эти привязки создаются посредством статического анализа исходного кода. Благодаря этому генератор сохраняет внесённую разработчиками в код информацию, включая комментарии и осмысленные имена параметров, вместо того чтобы исследовать уже собранную программу с помощью рефлексии. В результате API фронтенда становится более информативным и полезным, а процесс генерации — более понятным и удобным в сопровождении.

Сервисы также могут подключать ресурсы и скрипты фронтенда вместе со своим кодом Go. Благодаря этому все составляющие одной возможности находятся в едином согласованном месте: её API бэкенда, необходимый JavaScript или пользовательский интерфейс и точка интеграции с основным приложением. Это открывает путь к плагинам Wails, которые предоставляют богатую функциональность сразу после установки: установите плагин, подключите его сервис и используйте нужную возможность — вместо того чтобы самостоятельно объединять разрозненные привязки и зависимости фронтенда. Универсальная система плагинов не входит в эту бета-версию, но v3 делает это направление практически осуществимым, чего не позволяла модель привязок v2.

### Система сборки, которую можно изучать и адаптировать

В v3 структура сборки проекта стала открытой. Вместо того чтобы скрывать все решения о сборке внутри одной команды, проекты используют стандартную структуру и конфигурацию сборки на основе Taskfile, которую можно изучать, расширять и отлаживать вместе с приложением.

### Более надёжная кроссплатформенная основа для настольных приложений

Бета-версия поддерживает Windows на amd64 и arm64, macOS на Intel и Apple Silicon, а также Linux на amd64 и arm64. Стеком по умолчанию для Linux служит GTK4 с WebKitGTK 6.0; GTK3 остаётся доступным как устаревший вариант на протяжении всей серии v3.0. Поддержка мобильных платформ выглядит многообещающе, но остаётся экспериментальной и не охватывается гарантиями совместимости бета-версии для настольных систем.

В этот выпуск также вошли изменения, необходимые для повышения надёжности повседневной работы: улучшено поведение на разных платформах, расширены возможности модели окон, сделана понятнее диагностика, а к артефактам выпусков добавлены контрольные суммы и сведения о происхождении.

## Переход с v2

v3 — новая основная версия, поэтому миграция представляет собой полноценное портирование, а не простую замену номера версии. Основные концептуальные изменения касаются жизненного цикла приложения и окон, использования сервисов вместо привязок, зависящих от контекста, прямых API приложения и окон вместо пакета среды выполнения v2, а также повторно созданных привязок фронтенда.

Мы опубликовали [руководство по миграции с v2 на v3](/migration/v2-to-v3/), в котором пошагово разобраны эти изменения, приведено сопоставление возможностей и дан контрольный список для тестирования. Для этой бета-версии поддерживаемым способом миграции является следование этому руководству вручную. Не ожидайте, что каждый проект v2 удастся перенести без проверки: протестируйте результат, осознанно перенесите вызовы среды выполнения и сохраняйте v2, пока новое приложение не будет готово.

Мы также оцениваем экспериментальный помощник по миграции. Он не входит в эту бета-версию, и мы будем рекомендовать его только после проверки на репрезентативных реальных проектах v2.

## Откровенно о пройденном пути

Первый альфа-тег v3 был опубликован 18 января 2023 года. Альфа-тестирование длилось долго, и простого расплывчатого признания этого факта недостаточно.

За это время проект значительно изменился. Когда в сентябре 2021 года вышла первая бета-версия Wails v2 для Windows, у репозитория было около 4000 звёзд. К выпуску v2 в сентябре 2022 года их было около 10300. Сегодня их больше 35000. Такой рост — большая честь, но он также меняет представление об ответственном развитии проекта: от решений о выпусках зависит больше пользователей, большему числу участников нужны понятные способы внести свой вклад, а всё большая доля работы направлена на повышение предсказуемости проекта, а не просто на добавление очередной функции.

Я не всегда адаптировал наши процессы так быстро и прозрачно, как того требовал этот рост. Я признаю свою ответственность. Выход не в громких обещаниях и не в превращении каждого решения в церемонию, а в том, чтобы яснее объяснять, что поддерживается, что носит экспериментальный характер, как принимаются решения и что мы планируем делать дальше.

Эта работа начинается с данной бета-версии. Теперь у нас есть чётко определённые этапы бета-версии, релиз-кандидата и общедоступного выпуска (GA), более ясные обязательства по совместимости, обновлённая политика безопасности и процесс WEP (Wails Enhancement Proposal) для изменений публичного поведения и добавления новых возможностей. По мере развития Wails мы продолжим совершенствовать дорожную карту и пересматривать управление проектом. Наша цель — сделать проект более надёжным и удобным для участия, а не усложнить его развитие.

Мы также перезапускаем [сабреддит Wails](https://www.reddit.com/r/wails/) и будем активно поддерживать его как ещё одну площадку для практических обсуждений, вопросов и обратной связи по мере продвижения v3 к общедоступному выпуску.

## Установите и попробуйте бета-версию

После публикации выпуска установите последнюю версию CLI v3 с помощью следующей команды:

```sh
go install github.com/wailsapp/wails/v3/cmd/wails3@latest
```

Перед созданием проекта запустите пошаговый мастер настройки. Он проверит локальную среду разработки и поможет настроить зависимости, необходимые Wails:

```sh
wails3 setup
```

![Мастер настройки Wails v3 в тёмном режиме](/assets/screenshots/wails3-setup-wizard-dark.png)

### Создайте проект

Когда всё будет настроено, создайте проект с помощью следующей команды:

```sh
wails3 init
```

- Документация: <https://v3.wails.io/>
- Руководство по миграции: <https://v3.wails.io/migration/v2-to-v3/>
- Reddit: <https://www.reddit.com/r/wails/>
- Примечания к выпуску: [ЗАПОЛНИТЕЛЬ ВЕРСИИ](https://github.com/wailsapp/wails/releases)

Если вы обнаружили воспроизводимую ошибку, сообщите о ней, приложив вывод `wails3 doctor` и, по возможности, минимальный пример. Если вы хотите предложить новую возможность или изменение публичного поведения, создайте черновой PR с WEP вместо задачи с запросом функции. Оба способа помогают нам давать чёткие ответы и поддерживать продвижение бета-версии.
