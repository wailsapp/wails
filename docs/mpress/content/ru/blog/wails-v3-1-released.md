Неделя в Wails выдалась насыщенной: сборки без CGO, более простая настройка проектов и меньше сложностей с упаковкой и подписыванием.

Wails v3.1.0 начинает серию наших еженедельных выпусков с новыми возможностями, которые будут регулярно становиться вам доступны. Исправления ошибок по мере готовности продолжат выходить в ночных патч-обновлениях.

## Исправления и оптимизации этой недели

На этой неделе во фреймворке, CLI, инструментах сборки и CI появилось **100 исправлений, 21 улучшений производительности и четыре изменения для усиления безопасности**. Среди наиболее заметных — более надёжное позиционирование окон при использовании мониторов с разным DPI, исправления системного трея и тёмного режима в Linux, более экономная раздача ресурсов и снижение потребления памяти при упаковке MSIX. [Ниже приведены некоторые из этих изменений](#-----1).

## Экспериментальные сборки без CGO

Purego позволяет Go вызывать нативные системные библиотеки без CGo — обычного механизма взаимодействия Go с кодом на C. Мы начали изучать purego сразу после его появления, но поддерживать два бэкенда оказалось непросто. Теперь, когда purego стал зрелее, а генеративный ИИ упростил такую поддержку, мы готовы представить экспериментальные бэкенды для macOS и Linux.

Теперь можно собирать и кросс-компилировать настольные приложения без компилятора C:

```sh
WAILS_PUREGO=1 wails3 build
```

После сборки ресурсов фронтенда можно также выполнить сборку напрямую с помощью Go:

```sh
CGO_ENABLED=0 go build -tags purego,production .
```

Бэкенд macOS использует AppKit и WebKit; в Linux поддерживаются GTK4/WebKitGTK 6.0 и GTK3. Пользователям по-прежнему нужны нативные библиотеки среды выполнения, а для упаковки и подписывания действуют отдельные требования. Пока мы собираем отзывы, CGo остаётся вариантом по умолчанию.

[Подробности реализации и сведения о платформах](https://github.com/wailsapp/wails/pull/6521)

## Зачем нужен Wake?

Wails v2 скрывал слишком многое в процессе сборки. В v3 Taskfile открыли доступ ко всему процессу, однако большинству пользователей нужны лишь некоторые настройки без необходимости сопровождать систему сборки.

Wake переносит распространённые параметры в `wails.yaml`: приложения, вспомогательные инструменты CLI, серверы, целевые платформы и упаковку. Task остаётся нашей основной системой сборки и доступен, когда нужна его гибкость.

Теперь Wake поддерживает автоматическую перезагрузку при изменениях, инкрементальные сборки, кэширование результатов и параллельную упаковку. Уже есть двоичные файлы? `--skip-build` упакует их без установленных Go и инструментов фронтенда.

Включите эту возможность с помощью `WAILS_EXP_USE_WAKE=1`.

### Что можно собрать на моём компьютере?

К компиляции, упаковке и подписыванию предъявляются разные требования. Вот что можно сделать в каждой из систем:

@table{header search sort column-separators align=["left", "centre", "centre", "centre", "left"]}
| Операция | Система Windows | Система macOS | Система Linux | Что потребуется |
| Компиляция настольных приложений с purego | ✓ | ✓ | ✓ | Go и экспериментальный бэкенд purego для целевых платформ macOS/Linux |
| Создание пакетов MSIX | ✓ | ✓ | ✓ | Собранное приложение; Windows SDK не требуется |
| Создание установщиков NSIS | ✓ | ✓ | ✓ | Собранное приложение и `makensis` |
| Создание приложений macOS и образов DMG | ✓ | ✓ | ✓ | Собранное приложение; создание пакета выполняет Go |
| Создание пакетов DEB, RPM, Arch и Void | ✓ | ✓ | ✓ | Собранное приложение |
| Создание AppImage | ✓ | ✓ | ✓ | Среда выполнения AppImage для целевой платформы; дерево среды выполнения графического интерфейса Linux для кросс-платформенной упаковки |
| Подписывание пакетов Windows с помощью экспортированного удостоверения | ✓ | ✓ | ✓ | Экспортированный сертификат RSA в формате PFX и закрытый ключ |
| Подписывание приложений Apple и образов DMG с помощью экспортированного удостоверения | ✓ | ✓ | ✓ | Экспортированное удостоверение RSA PKCS#12; см. примечание о проверке ниже |
| Подписывание пакетов DEB, RPM и Arch | ✓ | ✓ | ✓ | Экспортированный ключ OpenPGP |
| Отправка на нотариальное заверение Apple и прикрепление билетов | ✓ | ✓ | ✓ | API-ключ команды Apple и приложение с подходящей подписью |
| Использование профилей Apple `codesign` или связки ключей | – | ✓ | – | macOS и соответствующее удостоверение для подписывания |

Для сборок с CGo по-прежнему требуется набор инструментов C. Пользовательские хуки, изменяющие образы DMG, требуют macOS и `hdiutil`.

### Подписывание и нотариальное заверение

Wake поддерживает подписывание пакетов Windows, Apple и Linux, включая ситуативные подписи Apple. Для кросс-платформенного подписывания используются экспортированные удостоверения; для удостоверений из хранилища сертификатов и связки ключей по-прежнему требуются нативные инструменты. Учётные данные на уровне пользователя позволяют не хранить закрытые ключи в конфигурации проекта. Подписывание AppImage и Void пока не поддерживается.

Нотариальное заверение Apple выполняется средствами Go с использованием API-ключа команды. Мы протестировали отправку и прикрепление билета из Linux; Gatekeeper принял результат. Приложение было подписано с помощью Apple [`codesign`](https://developer.apple.com/library/archive/documentation/Security/Conceptual/CodeSigningGuide/Procedures/Procedures.html); пока не проверено, принимает ли Apple подписи Developer ID, созданные Wake средствами Go.

### Переход на Wake

Миграция поддерживает все девять встроенных шаблонов. Она необратима: активация `wails.yaml` заменяет маршрутизацию Taskfile. Неподдерживаемые пользовательские команды и переопределения отклоняются для проверки.

[Возможности и требования Wake, а также сведения о миграции](https://github.com/wailsapp/wails/pull/6531)

## Несколько важных улучшений этой недели

- **Окна правильно размещаются на дисплеях с разной плотностью пикселей.** Теперь границы и позиции экранов корректно обрабатываются в конфигурациях macOS и Linux с разными масштабами дисплеев. [#6346](https://github.com/wailsapp/wails/pull/6346)
- **Системный трей и определение темы в Linux работают надёжнее.** Элементы системного трея, созданные после запуска приложения, больше не теряются, всплывающие подсказки заполняются, а определение тёмного режима считывает настройку оформления рабочего стола с момента запуска.
- **Обратные вызовы событий Go сохраняют порядок для каждого слушателя.** Каждый слушатель выполняет обратные вызовы последовательно в порядке генерации событий; разные слушатели могут работать параллельно, а порядок одновременно генерируемых событий не определён. Список обработчиков событий фиксируется под блокировкой, чтобы избежать гонки данных. [#6275](https://github.com/wailsapp/wails/pull/6275), [#6276](https://github.com/wailsapp/wails/pull/6276)
- **Кэширование сборок поддерживает больше реальных проектов.** Пробелы в кавычках или с экранированием больше не приводят к промахам кэша выходных данных Go, а параллельные операции сохранения кэша выполняются последовательно, чтобы предотвратить повреждение файлов. [#6495](https://github.com/wailsapp/wails/pull/6495), [#6488](https://github.com/wailsapp/wails/pull/6488)
- **При раздаче ресурсов выполняется меньше лишней работы.** Для файлов с известными расширениями определение MIME-типа по содержимому пропускается, а при отключённом отладочном журналировании больше не формируются сообщения, которые затем были бы отброшены. Оба изменения сокращают объём работы при обработке запросов. [#6414](https://github.com/wailsapp/wails/pull/6414), [#6420](https://github.com/wailsapp/wails/pull/6420)
- **При упаковке MSIX больше не используются буферы размером с двоичный файл.** Исполняемые файлы передаются в пакет потоково, а не целиком считываются в память. Ранее при типичном копировании 16 МиБ на каждую операцию выделялось около 16.8 МБ. [#6472](https://github.com/wailsapp/wails/pull/6472)
