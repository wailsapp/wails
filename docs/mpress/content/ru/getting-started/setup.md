@note{type="caution" title="Экспериментальная функция"}
Мастер настройки — новая функция, протестированная преимущественно в Linux. Если у вас возникнут проблемы, [сообщите о них](https://github.com/wailsapp/wails/issues/4904) и вместо мастера выполните [установку вручную](/getting-started/installation/#platform-specific-dependencies).

@end

## Быстрый старт

```bash
# 1. Install the Wails CLI
go install github.com/wailsapp/wails/v3/cmd/wails3@v3.0.0

# 2. Run the setup wizard
wails3 setup
```

Мастер открывается в браузере и помогает проверить зависимости, задать параметры проекта по умолчанию и при необходимости настроить кроссплатформенную сборку. В приведённых выше инструкциях используется стандартный процесс настройки; экспериментальный процесс для проектов Wake описан ниже.

После этого можно создать первый проект:

```bash
wails3 init -n myapp -t vanilla
cd myapp && wails3 dev
```

## Возможности мастера

- **Проверка зависимостей** — проверяет Go, npm и инструменты платформы
- **Настройка значений по умолчанию** — сведения об авторе, префикс идентификатора пакета и предпочтительные шаблоны
- **Кроссплатформенные сборки** — необязательная настройка Docker для сборки на любой хост-системе
- **Подписание кода** — необязательная настройка для macOS, Windows и Linux

Конфигурация сохраняется в `$XDG_CONFIG_HOME/wails/defaults.yaml`, а если это невозможно — в `~/.config/wails/defaults.yaml`, и используется командой `wails3 init`. Она не связана с файлом `build/config.yml` проекта.

## Настройка проекта Wake

Запустите настройку из каталога проекта, [включив экспериментальную функцию Wake](/experimental/yaml-builds/#enable-yaml-builds):

```bash
export WAILS_EXP_USE_WAKE=1
wails3 setup
```

В PowerShell:

```powershell
$env:WAILS_EXP_USE_WAKE = '1'
wails3 setup
```

Откроется процесс настройки проекта:

1. **Проект** — укажите метаданные проекта, если собственный манифест отсутствует.
2. **Приложение** — выберите GUI-приложение, CLI-приложение или сервер, серверную часть сборки либо уже собранные исполняемые файлы. Использование только Go — отдельный экспериментальный вариант.
3. **Целевые платформы** — выберите операционные системы и архитектуры. Поддержка iOS и Android по-прежнему экспериментальная; настройте параметры подписывания для них в YAML.
4. **Пакеты** — выберите форматы пакетов и укажите, нужно ли их подписывать.
5. **Инструменты** — проверьте требования для выбранного процесса сборки и упаковки.
6. **Подписание** — если подписание выбрано, настройте его с помощью существующих элементов управления.
7. **Сохранение** — запишите конфигурацию проекта и отобразите команду для запуска.

Требования к инструментам зависят от выбранных параметров. Для компиляции настольного приложения исключительно на Go не нужны Docker и компилятор C. Для кросс-компиляции с CGo требуются совместимый компилятор и библиотеки целевой платформы либо поддерживаемый контейнерный набор инструментов. Для NSIS по-прежнему требуется `makensis`; для сборки GUI-приложений AppImage на хост-системе другой платформы необходимо предоставить дерево среды выполнения Linux. Для экспортированных удостоверений подписания можно использовать средства подписания Wails, реализованные на Go, а удостоверения из системного хранилища ключей или сертификатов по-прежнему требуют инструментов соответствующей платформы. См. [требования к упаковке и подписанию](/experimental/yaml-builds/#package-and-sign-for-distribution).

При использовании уже собранных исполняемых файлов пропускаются компиляция Go, установка и сборка фронтенда, создание привязок и обработка UPX. При этом по-прежнему требуются выбранные инструменты упаковки и подписания, а также корректные входные двоичные файлы. См. [пути к предварительно собранным входным файлам](/experimental/yaml-builds/#use-prebuilt-desktop-executables). Этот выбор применяется к команде, отображаемой после сохранения, и не является постоянным параметром сборки YAML.

При сохранении записывается `wails.yaml`, обновляются тип приложения, включение фронтенда и выбранные параметры бэкенда, а отдельный набор целевых платформ, пакетов и параметров подписывания `profiles.setup` заменяется. Остальные профили, команды фронтенда, вспомогательные исполняемые файлы, хуки и не связанные с этим параметры проекта сохраняются. Параметры бэкенда действуют на весь проект, поэтому выбранный бэкенд также используется другими профилями, которые наследуют эти параметры. Новые метаданные проекта остаются в мастере до сохранения. Мастер сообщает об отсутствующих инструментах, чтобы вы могли установить их перед сборкой; сохранение корректной конфигурации не устанавливает инструменты и не запускает сборку.

Если в подписываемой сборке отсутствуют параметры подписания, используются значения по умолчанию уровня пользователя, включая файлы сертификатов за пределами проекта. Явно заданные параметры проекта имеют приоритет. Мастер настройки не копирует закрытые ключи, пароли или глобальные пути к учётным данным в `wails.yaml`. Пароль для глобально настроенных ключей Windows и Linux передавайте через существующее хранилище учётных данных либо через `WAILS_WINDOWS_CERT_PASSWORD` / `WAILS_PGP_PASSWORD`. Для зашифрованного удостоверения Apple задайте в `darwin.signing.credential` имя переменной среды, содержащей его пароль.

Сохранённый профиль запускается с параметром `wails3 build setup`; при выборе уже собранных файлов добавляется `--skip-build`.

Не отключайте Wake при выполнении отображаемой команды. При активном `wails.yaml` отсутствие флага никогда не приводит к использованию Taskfiles. Мастер настройки не преобразует существующие Taskfiles или устаревшие метаданные: прежде чем настраивать такие проекты с помощью Wake, выполните [проверенную процедуру миграции](/experimental/yaml-builds/#migrate-an-existing-project).

## Подкоманды

```bash
wails3 signing      # Configure code signing
wails3 entitlements # Configure macOS entitlements
```

## Возникли проблемы?

1. Выполните `wails3 doctor` для диагностики проблем
2. Выполните [установку вручную](/getting-started/installation/#platform-specific-dependencies)
3. [Сообщите о проблеме](https://github.com/wailsapp/wails/issues/4904), приложив вывод `wails3 doctor`
