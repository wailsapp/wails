## Общие вопросы

### Что такое Wails?

Wails — это фреймворк для разработки настольных приложений с использованием Go и веб-технологий. Логика приложения пишется на Go, интерфейс создаётся с помощью HTML, CSS и JavaScript (или любого фронтенд-фреймворка), а Wails отображает его во встроенном веб-представлении операционной системы. В результате получается небольшое, быстрое приложение с нативным внешним видом: без браузера в комплекте, с низким потреблением памяти и одним исполняемым файлом, который обычно занимает около 10 МБ.

### Какие платформы поддерживает Wails?

| Платформа | Требования |
| --- | --- |
| Windows | AMD64 и ARM64. Используется среда выполнения [WebView2](https://developer.microsoft.com/microsoft-edge/webview2/). |
| macOS | 10.15+ на компьютерах с процессорами Intel (приложения могут быть ориентированы на 10.13+), 11.0+ на компьютерах с Apple Silicon. Поддерживаются универсальные исполняемые файлы. |
| Linux | AMD64 и ARM64. По умолчанию используется стек GTK4 с WebKitGTK 6.0 (Ubuntu 24.04+, Debian 13+, Fedora 40+ и аналогичные дистрибутивы). Дистрибутивы, в которых доступен только WebKit2GTK 4.1, например Ubuntu 22.04, Debian 12 и RHEL 9, поддерживаются через устаревшую сборку `-tags gtk3` (доступна до v3.1). Дистрибутивы, в которых доступен только WebKit2GTK 4.0, не поддерживаются. См. [руководство по сборке для Linux](/guides/build/linux/). |
| iOS и Android | Экспериментальная поддержка. См. [руководства по мобильной разработке](/guides/mobile/). |

Приложение также можно предоставлять как обычное веб-приложение с помощью [серверной сборки](/guides/server-build/).

В любое время запустите `wails3 doctor`, чтобы проверить систему и получить инструкции по установке для вашей платформы.

### Что нужно для начала работы?

- Go 1.25 или более поздней версии
- Node.js и npm (для сборки фронтенда)
- Инструментарий платформы: WebView2 в Windows (предустановлен в 10/11), Xcode Command Line Tools в macOS, `gcc` и пакеты разработки GTK/WebKit в Linux

`wails3 doctor` проверит всё это и точно укажет, чего не хватает. Полное пошаговое описание см. в разделе [«Установка»](/quick-start/installation/).

### Готов ли Wails v3 к эксплуатации в рабочей среде?

Wails v3 — это бета-версия со стабильным API для настольных приложений. На его основе уже работают приложения в рабочей среде, однако перед развёртыванием следует провести тщательное тестирование, пока мы завершаем окончательную доработку для 3.0. Актуальное состояние см. на [странице статуса проекта](/status/). Wails v2 остаётся текущей стабильной версией и продолжает получать исправления.

## Разработка

### Нужно ли знать Go?

Базовые знания Go будут полезны, но быть экспертом необязательно. Логика приложения реализуется в обычных методах Go, а [учебные руководства](/tutorials/overview/) помогут разобраться со всем остальным. Многие разработчики осваивают Go по мере создания своего первого приложения Wails.

### Можно ли использовать предпочитаемый фронтенд-фреймворк?

Да. Если результатом его сборки являются HTML, CSS и JavaScript, он работает с Wails. В комплект входят шаблоны для React, Vue, Svelte и обычного JavaScript (каждый также доступен в варианте с TypeScript), а любой другой фреймворк можно подключить за несколько минут. См. раздел [«Фронтенд-фреймворки»](/guides/dev/frontend-frameworks/).

### Как вызывать функции Go из JavaScript?

Зарегистрируйте сервис, и Wails создаст для него типизированные привязки:

```go
// Go
type GreetService struct{}

func (g *GreetService) Greet(name string) string {
    return "Hello " + name
}
```

```javascript
// JavaScript
import { GreetService } from "./bindings/changeme";

const message = await GreetService.Greet("World");
```

Привязки автоматически создаются заново во время `wails3 dev` или по запросу с помощью `wails3 generate bindings`. См. раздел [«Сервисы»](/features/bindings/services/).

### Можно ли использовать TypeScript?

Да. Генератор привязок создаёт определения TypeScript для сервисов и их типов, поэтому вызовы Go полностью типизированы.

### Как передавать события между Go и JavaScript?

```go
// Go
app.Event.Emit("time", time.Now().Format(time.RFC1123))
```

```javascript
// JavaScript
import { Events } from "@wailsio/runtime";

Events.On("time", (event) => {
    console.log(event.data);
});
```

Имена событий должны совпадать в точности. См. [справочник по событиям](/guides/events-reference/).

### Как отлаживать приложение?

Запустите `wails3 dev` и щёлкните правой кнопкой мыши в окне, чтобы открыть инструменты разработчика браузера — точно так же, как при веб-разработке. Сервер разработки также поддерживает горячую перезагрузку фронтенда. См. раздел [«Отладка»](/guides/dev/debugging/).

## Сборка и распространение

### Как создать производственную сборку?

```bash
wails3 build
```

Исполняемый файл будет помещён в `bin/`. В производственных сборках уже применяются разумные параметры по умолчанию (теги сборки, `-trimpath`, удаление таблицы символов), поэтому для получения компактного исполняемого файла дополнительные флаги не нужны.

### Поддерживается ли кросс-компиляция?

С ограничениями. Кросс-компиляция чистого Go-кода здесь неприменима, поскольку каждая платформа использует нативные библиотеки веб-представления, однако распространённые сценарии хорошо поддерживаются:

```bash
# Different architecture, same OS
wails3 build GOOS=windows GOARCH=arm64

# macOS universal binary
wails3 task darwin:build:universal
```

Для сборки под Linux в другой операционной системе используется инструментарий на основе Docker. Полную матрицу см. в разделе [«Кроссплатформенные сборки»](/guides/build/cross-platform/).

### Как создать установщик или пакет?

```bash
wails3 package
```

В результате создаётся нативный для платформы формат, а в [руководстве по установщикам](/guides/installers/) рассматриваются NSIS в Windows, пакеты `.app` и образы DMG в macOS, а также пакеты Linux.

### Как подписать приложение цифровой подписью?

Пошаговые инструкции по подписанию для Windows и macOS (включая нотариальное заверение) приведены в [руководстве по подписанию](/guides/build/signing/).

## Возможности

### Можно ли создать несколько окон?

Да, в v3 есть встроенная поддержка нескольких окон:

```go
window1 := app.Window.New()
window2 := app.Window.New()
```

См. раздел [«Несколько окон»](/features/windows/multiple/).

### Поддерживает ли Wails системный трей?

Да, включая меню и обработчики щелчков:

```go
systemTray := app.SystemTray.New()
systemTray.SetIcon(iconBytes)
systemTray.SetMenu(myMenu)
```

См. раздел [«Системный трей»](/features/menus/systray/).

### Можно ли использовать нативные диалоговые окна?

Да. Диалоговые окна выбора файлов, окна сообщений и окна с вопросами используют нативные реализации:

```go
path, err := app.Dialog.OpenFile().
    SetTitle("Select File").
    PromptForSingleSelection()
```

См. раздел [«Диалоговые окна»](/features/dialogs/overview/).

### Поддерживает ли Wails автоматические обновления?

Да. Wails v3 включает встроенный механизм самообновления (`app.Updater`) с подключаемыми поставщиками обновлений для GitHub Releases, keygen.sh и Sparkle AppCast, криптографической проверкой подписи и интерфейсом по умолчанию, тему которого можно настроить или который можно заменить. См. руководство [«Встроенный механизм обновления»](/guides/updater/) и учебное руководство [«Самообновляемое приложение Wails»](/tutorials/04-self-update-a-wails-app/).

## Устранение неполадок

### Что-то не работает. С чего начать?

```bash
wails3 doctor
```

Эта команда проверяет набор инструментов, перечисляет отсутствующие зависимости вместе с командами их установки и выводит сведения о версиях, которые следует включать в каждый отчёт об ошибке.

### Сборка завершается с ошибкой

Обычно помогают следующие действия, выполняемые по порядку:

1. `go mod tidy`
2. `cd frontend && npm install` (чаще всего причиной является отсутствие `node_modules`)
3. Обновите CLI: `go install github.com/wailsapp/wails/v3/cmd/wails3@latest`
4. В Linux проверьте с помощью `wails3 doctor`, отсутствуют ли пакеты GTK/WebKit

### Привязки отсутствуют или устарели

```bash
wails3 generate bindings
```

В режиме разработки привязки создаются заново автоматически. Если вы добавили новую службу или изменили сигнатуры методов вне `wails3 dev`, создайте их заново вручную.

### События не срабатывают

Имена событий в `app.Event.Emit("name", ...)` в Go и `Events.On("name", ...)` в JavaScript должны полностью совпадать. Сначала проверьте опечатки и различия в регистре.

### Я обнаружил ошибку

Пожалуйста, [создайте issue](https://github.com/wailsapp/wails/issues) и приложите вывод `wails3 doctor`. В [руководстве по обратной связи](/feedback/) объясняется, как составить отчёт, по которому легко принять меры.

## Переход с v2

### Стоит ли переходить с v2 на v3?

В v3 появились поддержка нескольких окон, более понятный API на основе служб, встроенный механизм обновления, гораздо более гибкая система сборки и повышенная производительность. Новые проекты следует начинать на v3. Для существующих проектов различия подробно описаны в [руководстве по миграции](/migration/v2-to-v3/).

### Будет ли поддерживаться v2?

Да. Для v2 продолжают выпускаться исправления, пока v3 приближается к стабильному выпуску.

### Можно ли использовать v2 и v3 параллельно?

Да. CLI представлены отдельными исполняемыми файлами (`wails` и `wails3`), а модули имеют разные пути импорта, поэтому проекты на разных основных версиях без проблем сосуществуют на одном компьютере.
