# Domain documentation

This repository uses a single domain context.

Before domain-modeling work, read `CONTEXT.md` when it exists and any relevant
ADRs under `docs/adr/`. Missing files require no setup: create or extend domain
documentation only when the work resolves terminology or an architectural
decision worth preserving.

Use terms as defined in `CONTEXT.md`. Surface conflicts with an existing ADR
explicitly rather than silently replacing its decision.
